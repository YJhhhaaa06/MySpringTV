### R-10 结论（2026-10-11 已拍板 = **C'**）—— 这里只留「为什么」

> 骨架（新域 / 响应形态 / 计数口径 / 约束红线）**已收编进设计篇**；实现细节归 `CURRENT_TASKS.md`。

**★ 先立一个框架：两个议题是「两级问题」** —— 一级是"**互动态在哪取数**"（内联 vs 独立端点），
R-10（内联 `isFavorited`）只是它下面的子项。不先分清这个，"互动域"就会被当成第三个并列选项。

**★ 方案取舍（四条路，以及为何落 C'）**：

| 方案 | 一句话 | 结论 |
|---|---|---|
| **A. 内联平铺**（顶层加 `isFavorited`） | 与既有 `isLiked`/`isFollowed` 同形 | ❌ 唯一**不 breaking**，但 content 继续堆互动字段，且 `content ⇄ favorite` **成环** |
| **B. 独立互动端点**（拆接口） | 三态聚合为一个新端点 | ❌ **请求数更贵**（详情页 2 vs 内联 1）；**解耦的代价就是那 1 个请求** |
| **C. 内联 + `interaction` 子对象**（content 自己组装） | 响应结构对了 | ⚠️ content 仍依赖 like / follow / favorite **三域**（+1 条边、+1 个环） |
| **C'. C 的形态 + `interaction` 由独立互动域组装** | 结构 + 归属都对 | ✅ **采纳** |

**★ C' 的收益在「层次」不在「边数」（别记错）**：content 域依赖 **3 → 1**、**无环**、加投币只改互动域、
未来搬独立端点 ≈ 零成本（Service 已就位）；⚠️ 但**总跨域边数实际增加**（3 条 → 1+3 条）
⇒ 理由应是"**方向变单向 / 分层清晰**"，**不是**"依赖变少"。

**★ 两条不可省的约束**：
1. **C/C' 必须包含"内联 `isFavorited`"** —— 只改响应结构 = 白改（请求数不变，纯白破一次契约）。
2. **投币是解耦的放大器、不是前提**（用户已定"暂不考虑" ⇒ `FURTHER_ISSUES.md` **F-13**）。

**★ 讨论中排除的候选**（逐条留痕，免得将来重提）：

| 候选 | 为什么排除 |
|---|---|
| 顶层平铺加字段（方案 A） | content 承载互动 + 成环；后续每加一维都要改顶层键集 |
| 独立互动端点（方案 B） | 请求数贵 1；且要摘掉详情里已内联的旧字段（多余的一次 breaking） |
| 新增 MySQL「用户×内容关系表」判"是否已收藏" | `findFoldersByUserAndContent` **已走 `idx_user_content` 等值索引**（判存在收益 ≈ 0）；行数量级与 `favorite_item` 相同；**净增第二处事实源**。其"把关系独立出来"的直觉对，但本仓形态指向 **Redis Set**（`LikeCache` 同构） |
| 计数**增量维护**（原二期计划） | 4 个写点 + **并发漂移**（`uk_folder_content` 维度与判定维度不重合） |
| 计数用 `SELECT ... FOR UPDATE` 判定 | 判"**不存在**"时：**RC 下不加锁**（形同虚设）、**RR 下 gap lock 共享** ⇒ 双方都过判定、随后 INSERT 互等 ⇒ **死锁**；且本仓是"唯一键 + 409"的**乐观并发**风格，无取锁顺序规范 |
| 计数**异步延迟合并重算** + 前端单调补丁 | **削弱二期唯一硬 oracle**（不变量退化为"最终一致"）+ 需前端补丁 + 需新基建（重试 / 对账）⇒ 留池 **F-14** |
| `folders`（在哪些夹）也上缓存 | 失效点**五个**、收益只是"省一次**亚毫秒**索引点查" ⇒ 不划算（详见设计篇 §3.6） |

**★ 已核实的事实**（免得再查一遍）：

- 详情**只有 1 个接口** `GET /search/IdSearch`（视频 / 图文按响应 `type` 分流，**不是**两个接口）；
  "按有效 token 决定是否填充"**已是现状**（T10 起由 `InteractionService` 对 `userId == null` 短路，
  `ContentService.getContentDetailVO` 直调互动域）。
- 详情页内容相关请求：T10 前 **3 个**（IdSearch + `/favorite/status` + `/favorite/count`）；
  T10 后 **2 个**（初始收藏态改读详情内联 `interaction.isFavorited`；`/favorite/status` 只在收藏弹窗取 `folders` 时发）。
- feed 的 `isLiked` 是**服务端批量填充**（`FeedService.renderPage:133`），**不是**"内联"。
- 前端**没有任何列表页消费** `ContentVO.isLiked`/`isFollowed`（⇒ `F-15`，**前端功能缺失**，非后端缺陷）。

**★ 结转**：投币 ⇒ **F-13**；异步重算 + 前端补丁 ⇒ **F-14**；前端列表页展示互动态 ⇒ **F-15**。
⏳ **待实测**（本期任务内做）：`GROUP BY content_id IN (...)` 的 `EXPLAIN`（一期基线 2 万行 / 2000 人 ≈ 17ms 作对照）。
