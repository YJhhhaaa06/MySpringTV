### ★ R-13（**已拍板** 2026-10-13）——列表侧互动态形态统一

> **来由**：R-12 候选「性能第二轮」的第一题讨论（2026-10-13）。原始诉求是
> **"互动域允许上游选自己想要填充的维度、减少无用填充"**，讨论中发现**它无法单独成立**（见下）。

**调查事实**（可复算：`grep -rn "batchGetStatus\|batchIsContentLiked" src/main/java`）：

| 读路径 | 今天怎么取 | 每请求批读 | 用得上 |
|---|---|---|---|
| `/start`、`/search` | `ContentStatusFiller` → 互动域 `batchGetStatus` | **3**（赞 / 藏 / 关注） | 2（`ContentVO` 只装得下 `isLiked` + `isFollowed`，**`isFavorited` 查完即弃**） |
| `/feed`、`/profile` | **绕过互动域**，直连 `likeService.batchIsContentLiked` | 1 | 1 |
| `/content` 详情 | 互动域 `getStatus` | 3（单条） | 3 |

**为什么是"一件原子改动"**（形态 / 三态 / 选维度**缺一不可**）：

- `FeedService` 今天之所以**不能**走互动域，其类注释已写明原因——*"会给 feed 条目的 `isFollowed` 填上值 ⇒ 响应形状改变"*。
  根因正是"**互动域只会三维一起答 + VO 是 `boolean`（三维必填）**"。
- ⇒ 只有**维度选择**而没有**可空**，feed 能省查询却**无法表达"本面不查这一维"**，只能继续填 `false`（**换了个地方撒谎**）。
- ⇒ 只有**可空**而没有**形态统一**，列表仍是顶层平铺、与详情两套读法。
- ★ 附带事实：`/feed` 今天的 `isFollowed: false` **本身就是谎言**（作者明明已关注）。按收藏一期的判据
  ——"schema / 契约级的东西必须一次到位，且'默认公开'上线即成对外契约"——**它已经是对外契约的一部分**。

**形态口径**（★ 骨架落 `收藏功能-分期与设计.md` **§3.6**，此处只留结论）：

- 键集**恒三维**、值**三态**（`true` / `false` / `null`），`null` = **本面不查该维**。
- ⚠️ **刻意不加 `@JsonInclude(NON_NULL)`**（不用"缺键"表达）：本仓 `ProfileVO.isFollowed` 就是
  "`Boolean` 三态 + **显式输出 `null`**"的既有惯例，且详情契约测试断言**子对象键集恰好三维**、匿名时 `interaction` **键必须在**。
- **匿名 ⇒ `interaction: null`**（整对象缺席，沿用 R-10，不是 `{}`）。
- ★ 真正的好处不是"更彻底"，而是**终止破契约的次数**：键集收敛为终点形态 ⇒ 将来加维度（如 `coin`）、加面，
  全是"加可空字段 + 改调用点常量"，**不再 breaking**。

| # | 待定 | 原建议 | ✅ **拍板（2026-10-13）** | 理由 |
|---|---|---|---|---|
| ① | `/start` 带哪几维 | 只带 `{关注}` | **只带 `{关注}`** | 对标 B站 首页卡片只显示「已关注」，不显示点赞 ⇒ 赞 / 藏两维本面不查（批读 3→**1**） |
| ② | `/search` 带哪几维 | `{赞}` | ★ **空集（0 维）** | 对标 B站 搜索结果卡片**不显示任何互动态**（批读 3→**0**）。⚠️ 0 维的表示 = **对象在、三维全 `null`** —— **不是** `interaction: null`（那是"匿名"的语义）。★ 这同时**解禁了原红线"不许选 0 维"的*字面***：那条红线的理由（"`interaction: null` 会与匿名不可区分"）在"对象仍在"下**不成立**；**理由本身继续有效** |
| ③ | `authorId <= 0`（作者未知）口径 | 保持 `false` | **保持 `false`** | ⇒ 详情 JSON 零变化；改 `null` 更自洽但要破详情 ⇒ 列为"理论分支、不处置" |
