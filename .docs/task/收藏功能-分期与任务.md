## 一、分期

| 期 | 目标 | 内容 |
|---|---|---|
| **P0** | 最小闭环，跑通三元组 | 收藏夹 CRUD、收藏 / 取消、夹内列表分页、收藏状态与收藏数、前端点亮 |
| **P1** | 私密 + 整理 | 公开 / 私密开关与过滤、简介与封面、移动到其他夹、批量移出 |
| **P2** | 周边对标 | 稍后再看、订阅他人公开夹、失效内容占位、容量上限、连播 |

## 二、开工前必须拍板（F-D 系列）

| 编号 | 待定项 | 影响 |
|---|---|---|
| **F-D1** | 默认收藏夹的**创建时机**：注册即建（并入注册事务）vs 首次收藏时懒建 | 决定是否要动注册流程；懒建耦合小，但"我的收藏夹列表"要能返回空态 |
| **F-D2** | 删除自建夹时**条目怎么处理**：删除条目 vs 迁入默认夹 | B 站口径说法不一；**默认取"删除条目"**，并逐个判剩余以维护计数 |

## 三、与项目现状的落差（技术视角）

| 维度 | 现状 | 收藏带来的新问题 |
|---|---|---|
| 数据模型 | `content_like` 的 `uk_user_content` 是二元组 | 收藏是**三元组** + 多对多，去重计数的边界判定是新增逻辑 |
| 计数 | `content` 有 `comment_count` / `like_count`，**无 `favorite_count`** | 走 **V2** 加列（V1 已冻结） |
| 可见性 | 项目里**没有"资源级私密/公开"**这层概念 | P1 新增一层过滤，涉及 profile、列表、缓存三处 |
| 动态流 | `feed` 是关注流 | 明确"收藏不进 feed"，别与 `ContentPublishedEvent` 混 |
| 前端 | `static/js/main.js` 的 `data-nav="star"` 是 `disabled` | P0 要整页点亮（导航 + 收藏弹窗 + 收藏夹页），同步 `static/js/api.js` |
| 失效 | `content.is_deleted` 已有逻辑删除 | 「已失效」可直接由 `is_deleted=1` 判定（P2 才做占位展示） |

## 四、P0 任务拆分（切片）

| 编号 | 做什么 | 验收（可复算） |
|---|---|---|
| F0-1 | V2 迁移：`favorite_folder` + `favorite_item` + `content.favorite_count` | 迁移落地，起库通过 |
| F0-2 | 域骨架：`favorite` 包（controller / service / dao / cache），定 F-D1 | 包结构与 `like` 域同构；ArchUnit 规则通过 |
| F0-3 | 收藏夹 CRUD：新建 / 改名 / 删除（**默认夹拒绝删除**） | 接口级测试；删默认夹返回明确错误 |
| F0-4 | 收藏 / 取消收藏（指定夹）+ 我的收藏状态 | 同一内容进两夹后，状态仍为"已收藏" |
| F0-5 | 夹内列表分页（收藏时间倒序） | 分页用例：不重不漏、顺序与全量一致 |
| F0-6 | `favorite_count` 增量维护 | **独立 oracle 查列**：进两夹 +1、移出一夹仍 +1、全移出回 0 |
| F0-7 | 前端：点亮 `star` 导航、收藏弹窗、收藏夹页 | 手工冒烟；同步 `static/js/api.js` |
| F0-8 | 契约测试：计数口径、默认夹不可删、取消收藏的边界 | 去掉实现能变红 |

> ⚠️ **F0-6 是 P0 最容易写成"假绿"的一条**：必须查 `content.favorite_count` **列本身**，
> 不能只信接口回显。

## 五、数据模型草图（P0）

```
favorite_folder                     favorite_item
  id              bigint PK           id           bigint PK
  user_id         bigint 归属         folder_id    bigint → 收藏夹
  name            varchar(100)        user_id      bigint 冗余（查去重用）
  is_default      tinyint 默认夹      content_id   bigint
  create_time     datetime            create_time  datetime
  update_time     datetime            UNIQUE uk_folder_content (folder_id, content_id)
                                      KEY idx_user_content (user_id, content_id)
```

**计数维护判据**（口径本身见需求文档 §六，这里只写怎么落地）：

- `favorite_item` 的唯一键是 **(folder_id, content_id)**（保证同一夹内不重复）；
- 计数靠 **(user_id, content_id)** 这条索引判"该用户是否已收藏过"：
  - **加收藏**：插入前查有无行 → **无**则 `favorite_count + 1`
  - **取消收藏**：删除后查有无剩余 → **无**则 `favorite_count - 1`
  - **删夹**（F-D2 取"删除条目"）：批量删后，对每个受影响的 (user_id, content_id) 逐个判剩余

⚠️ 三条路径**必须走同一条判据**，否则计数漂移。

## 六、端点草图（P0，对齐 `/like/*` 命名风格）

```
POST   /favorite/folder/add          新建收藏夹
POST   /favorite/folder/update       改名
POST   /favorite/folder/remove       删除（默认夹拒绝）
GET    /favorite/folder/list         我的收藏夹列表
POST   /favorite/add                 收藏到指定夹
POST   /favorite/remove              从指定夹移出
GET    /favorite/status              我对某内容是否已收藏（含所在夹）
GET    /favorite/count               某内容的收藏数
GET    /favorite/list                夹内内容分页
```
