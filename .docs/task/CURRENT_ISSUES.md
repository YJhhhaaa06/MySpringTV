# 当期问题（Current Issues）

> **定位**：执行过程中**当场发现、且本期或下期要处理**的问题 —— 阻塞、偏差、待裁决、踩到的坑。
> **与 `FURTHER_ISSUES.md` 的分工**：**本期/下期解决** → 本文件；**暂时不会排期解决**（结转 / 留池）→ `FURTHER_ISSUES.md`。
> **边界**：需求与痛点 → `CURRENT_NEEDS.md`；任务执行态 → `CURRENT_TASKS.md`。
>
> ★ **膨胀控制**：处理完即标状态；**期收尾时把正文清出**（归宿 = git commit），本表只留一行摘要。
> 清出前**必须先把编号收进** ★ **活速查**（落点见 `CURRENT_NEEDS.md` §三 末）。
> **编号不回收**：跨期未决的结转时**保留原编号**并在 `FURTHER_ISSUES.md` 中标注来源。

问题 + 现象 + 证据（可复核）+ 影响 + 处置 + 去向。编号 `I-##` 顺延（**不回收**）；从别处结转进来的保留原编号。

**分类取值**：阻塞 / 偏差（与计划不符）/ 缺陷 / 环境 / 决策 / 债务。

### I-30 幂等指纹只覆盖请求体 ⇒ 同 key 换目标会"重放"而不是 422

- **分类**：决策（口径缺口）｜**状态**：**已纳入 `T69`**（2026-10-25 用户裁决：改）
- **现象**：`Idempotency-Key` 相同、请求体相同，但打到**另一条内容**（`POST /api/v1/contents/{id}/coins` 的 `{id}` 变了）
  ⇒ 命中首次快照**重放**（回第一次的 `balance`），**不是 422**；评论端点同理（回第一次的 `commentId`，第二次那条根本没发出去）。
- **证据**：指纹 = `SHA-256(请求体)`，只读 `ContentCachingRequestWrapper#getContentAsByteArray()`；key = `idem:{slug}:{uid}:{clientKey}`，
  slug 是**端点级常量**、不含 `{id}`。`T67` 写用例时实测发现，`CoinIdempotencyTests` 因此约定"换内容必须同时换 key"。
- **影响**：客户端 bug（复用 key 却换目标）会拿到**假成功** —— 用户以为给 B 投了币/发了评论，实际什么都没发生。
  比"重复一次"更隐蔽。正常客户端每次意图生成新 key，概率低。
- **处置建议**：把 `method + 请求路径` 拼进指纹（multipart 也适用——它本来只能靠路径）。如此"换目标 ⇒ 422"，
  代价 = 主代码一次语义变更 + 设计篇 §九/§十三 + 测试篇同改 + 一条新用例。
- **推翻条件（保持现状）**：认定"复用 key 换目标"只是客户端 bug、假成功可由客户端列表刷新自行发现，且不想动已交付语义
  ⇒ 关闭本项，并把该口径固化进设计篇 §九（现已写入）。
