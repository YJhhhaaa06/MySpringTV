## 一、交付物与文件布局

老项目 `src/main/webapp/` 共 20 文件。其中**两个是 Servlet 容器描述符、不是前端资产**，未随迁：

| 老文件 | 为何不搬 | 现由谁承接 |
|--------|---------|-----------|
| `WEB-INF/web.xml` | 声明 5 个 Servlet Filter（AccessLog/Exception/Encoding/Login/Auth） | Spring 过滤器链：`RequestIdFilter`/`AccessLogFilter`/`JwtAuthFilter` + `GlobalExceptionHandler` |
| `META-INF/context.xml` | Tomcat `<PostResources>` 挂载 `/upload` | `WebMvcConfig.addResourceHandlers` 的 `/upload/**`（S7） |

⇒ 实际搬入 **18 个前端文件**：`index.html` + `static/css/common.css` + `static/js/` 16 个 ES module
（`main`/`router`/`api`/`auth`/`utils`/`chunkedList`/`editWork` + `views/` 9 个视图）。

**布局保持相对路径**（`index.html` 里 `href="static/css/common.css"` / `src="static/js/main.js"` 逐字不改）：

```
src/main/resources/static/
├── index.html                 ← 欢迎页（Spring Boot welcome page 命中 static/index.html）
└── static/                    ← 与 index.html 的 `static/...` 相对路径对应
    ├── css/common.css
    └── js/… + js/views/…
```

⇒ 前端 URL：`/`（或 `/index.html`）→ `/static/css/common.css`、`/static/js/main.js`。

## 二、契约差异对照清单

> "旧" = TV（老前端当初对着写的后端）；"新" = 本项目。
> ⚠️ 其中 **K-1/K-2/K-3 是本次核对才登记的跨切面差异**——它们在决策③/⑧ 里定过，
> 但**从未进过《决策留痕表》D 类**，老前端因此会直接失效（不是"文案不同"级别）。

| # | 差异 | 旧（TV） | 新 | 前端影响 | 结论 |
|---|------|---------|----|---------|------|
| **K-1** | **鉴权头**（决策③） | 自定义头 `token: <jwt>` | `Authorization: Bearer <jwt>`（`JwtAuthFilter` 只认它） | 所有需登录端点会 401 | ✅ **已适配**：`api.js` 改写请求头 |
| **K-2** | **HTTP 状态码与业务 code 对齐**（决策⑧） | 协议层恒 **200**，语义码只在 body 信封 | 错误响应 **HTTP status = code**（body 仍带 `{code,msg}`） | 旧 `api.js` 先 `if(!res.ok) throw` ⇒ **丢信封**、401 不跳登录、各视图 `e.code===401/403` 分支全失效 | ✅ **已适配**：`api.js` 改为"**先读 body 再判**" |
| **K-3** | **登录请求字段 + 登录方式** | body `{account, password}`；`account` 可为**手机号或用户ID** | body `{phone, password}`；**仅手机号**（按 id 登录未迁，见《事务边界决策表》U-3/U-4） | 旧 body 的 `account` 不绑定 ⇒ `phone` 缺失 ⇒ 400 | ✅ **已适配**：`login.js` 改字段名；placeholder 去掉"用户ID" |
| D-1 | 重复抢券 `msg` | `"您已抢过该优惠券"` | `"操作冲突"`（code/HTTP 仍 409） | 前端仅 `showToast(e.message)`，**不按文案分支** | ✅ 相容，无需改 |
| D-6 | 未识别 action | 信封体 404 | Spring 无处理器 ⇒ **非信封** 404 | 前端只调已注册路径，**不触发**；`api.js` 对非信封回落通用文案 | ✅ 相容，无需改 |
| D-11 | 上传缺 part / 缺 `categoryId` | NPE 未捕获 → 500 | 400（文案保留） | 前端发布前本地校验；错误统一 `e.message` 展示 | ✅ 相容，无需改 |
| D-12 | admin `contentId`/`mediaId` 缺省或非数字 | 手写文案 | 统一「参数错误」（仍 400） | 前端只用 `e.message`/`e.code` | ✅ 相容，无需改 |
| D-2/D-3/D-5 | 参数类 400 / 文案 | — | 见 D 类 | 仅 `e.code`/`e.message`，无文案依赖 | ✅ 相容 |
| D-7/D-8/D-9 | 缓存/分页/规格内部口径 | — | — | 对外可观察行为不变 | ✅ 相容 |
| D-10 | `GET /user/me` 新增 | 无 | 有 | 前端未调用（用 JWT 解 id） | ✅ 无影响 |

**顺带确认（不构成差异，登记以免后人误判）**：`user/changePassword` 前端发 `{phone, oldPassword, newPassword}`，
新后端 `ChangePasswordRequest` 只收 `oldPassword/newPassword`——Spring Boot 默认忽略未知字段（`FAIL_ON_UNKNOWN_PROPERTIES=false`），
故 `phone` 被静默丢弃、**不报错**；`userId` 由 token 提供，语义等价。

## 三、已适配的前端改动（仅 2 个文件）

| 文件 | 改动 | 对应差异 |
|------|------|---------|
| `static/js/api.js` | ① 请求头 `token` → `Authorization: Bearer`；② 响应处理改为**先解析 body 信封**（`body.code===200` 返 data；否则抛带 `.code/.status` 的 Error，401 仍清登录态跳登录），非信封才按 HTTP 状态回落 | K-1、K-2 |
| `static/js/views/login.js` | 登录体 `{account}` → `{phone: account}`；输入框 placeholder「手机号 或 用户ID」→「手机号」 | K-3 |

其余 16 个文件**逐字照搬**（含 `main.js` hash 路由、`chunkedList.js`、`editWork.js` 与 9 个视图）。
