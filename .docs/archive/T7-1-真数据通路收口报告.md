## 四、双趟方法与等价性论证

```
① mysqldump TVDatabase → TVDatabase.pristine.sql          （只读生产一次）
② 恢复 → TVDatabase_work（不含种子）
③ 基线趟：探针对 TVDatabase_work + temp-script/stone  → baseline.json
④ 写阶段：应用指向 TVDatabase_work + temp-script/stone，施加真实写操作（§五）
⑤ 当前趟：探针对 TVDatabase_work + HTTP 探活           → now.json / lists.json
⑥ 做差 → 三张清单
```

**等价性**（为什么 `now` 用副本而非"活库"也成立）：本仓按"不碰生产"执行，故 `now` 落在工作副本上。
副本由 `--single-transaction` 一致快照恢复，且——**对生产库干跑一遍基线探针，得到与副本完全相同的 8 条发现**
（见 §六）⇒ 副本在基线时点 **等价于生产**。写阶段全部写在该副本上，生产未被任何写路径触达。

## 九、方法学留痕（两条，避免复核者误解）

1. **`now` 趟用"生产 dump 的副本"，不是"活库"**——为满足"不碰生产"，写阶段跑在副本上。等价性论证见 §四；若将来要求严格按工单字面（now=活库），须在生产上重跑双趟。
2. **首次 `now` 趟漏带 `--database TVDatabase_work`，读到了生产库**（探针只读，无副作用；生产计数核对未变），已用正确的库重跑。§一/§六的结论来自**重跑后**的结果。

## 十、复算命令

```bash
# 备份 + 恢复（见 §三；只读生产一次）
mysqldump -uroot -p --single-transaction --triggers --routines --result-file=temp-script/TVDatabase.pristine.sql TVDatabase

# 基线趟（对副本）
python tools/realdata_probe.py --baseline TVDatabase_work --root temp-script/stone --apply

# 当前趟（对副本 + HTTP 探活；/feed 需 token）
python tools/realdata_probe.py --database TVDatabase_work --root temp-script/stone \
       --base-url http://localhost:8080 --token <JWT> --apply

# 只读复算（预演，不落盘）
python tools/realdata_probe.py --baseline TVDatabase --root temp-script/stone
```

退出码：`0` ①清零且第 5 项已执行 / `1` 有代码缺口 / `2` 前置错 / `3` ①清零但第 5 项未执行。
