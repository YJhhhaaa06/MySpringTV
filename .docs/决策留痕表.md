# 决策留痕表（可检索的决策索引）

> 建立时间：2026-10-02（S6 收口批次 C2）
> **用途：本表是"我们当初决定了什么"的<u>唯一检索入口</u>。** 每个决策一行，可按类型/状态筛。
> 逐条**论证过程**不在本表（那会让它重新膨胀）——见"详见"列指向的文档。
> 维护规则：**做决策时先来本表加一行**，再去写代码/写详细论证。
> 关联：《事务边界决策表.md》（事务类明细）《遗留台账.md》（欠着什么）《端点对照表.md》（完整性）

## 〇、为什么要有这张表

《迁移工作流-复盘与修订建议.md》问题 7 的原话：

> 表名叫"**事务边界**决策表"，实际被当作"**所有需要留痕的决策**"在用。
> 结果：真正需要追溯的决策大部分塞进了提交信息——**提交信息可读但不可检索**，
> 而这张可检索的表又装不下它们。

本表就是那个缺的容器。**事务边界只是其中一类（见 §E）**，不是全部。

**与其余文档的分工**（同一事实只写一处）：

| 问题 | 看哪份 |
|------|--------|
| 还剩多少端点没搬？ | 《端点对照表.md》 |
| 现在还欠着什么？ | 《遗留台账.md》 |
| **当初为什么这么定？** | **本表**（再顺链接看明细） |
| 事务这条具体怎么处理的？ | 《事务边界决策表.md》 |
| 怎么做一个切片？ | 《迁移工作流-切片SOP.md》 |

## 附：本表的使用纪律

1. **决策即登记**：改了对外行为、定了范围、选了实现路径 —— 先加一行再动手。
2. **一行一决策**：论证写进被指向的文档，本表只留"结论 + 影响面 + 去哪看"。
3. **状态只能用四种**：`✅ 已完成` / `⚠️ 有意为之（含代价）` / `⏭ 划归后续` / `🔴 待决策`。
4. **不复制明细**：本表复制明细的那天，就是它开始膨胀的那天。
