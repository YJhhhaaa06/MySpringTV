## 一、现状（实测，非推测）

> **⚠️ S6 更正（2026-10-02）**：本节原先描述的"测试依赖本机手工容器、停掉即失败"是
> **切片 0 时期的状态**，早已被 Testcontainers 取代。按 SOP §七.2「正文只留当前有效结论」，
> 过期叙述不再保留在正文（历史论证见 `.docs/archive/`）。以下为**当前**事实。

### 1.1 测试依赖：无需显式声明 `spring-boot-starter-test`

`pom.xml` 并未显式声明 `spring-boot-starter-test`，但测试可编译运行。原因：

```
spring-boot-starter-flyway-test:4.1.1
  └── spring-boot-starter-test:4.1.1          ← 实际来源
        ├── org.junit.jupiter:junit-jupiter:6.0.3
        ├── org.mockito:mockito-core:5.23.0
        ├── org.mockito:mockito-junit-jupiter:5.23.0
        ├── org.assertj:assertj-core:3.27.7
        └── org.springframework.boot:spring-boot-test:4.1.1
```

**Boot 4 的测试 starter 已模块化**，每个功能自带 `-test` 变体：`flyway-test` / `security-test` /
`webmvc-test` / `jdbc-test` / `data-redis-test`…`spring-boot-starter-test` 由它们传递引入。

**结论**：JUnit 6 / Mockito 5.23 / AssertJ 3.27 **无需显式声明**。若将来移除 flyway-test，
需显式补 `spring-boot-starter-test`（或在需要处声明对应 `-test` 变体）。

### 1.2 已建成的地基（S6 实测）

| 能力 | 状态 |
|------|------|
| **Testcontainers** | ✅ **已落地**。容器由 `support/Containers.java` 以**进程级单例**提供（按类生命周期会踩端口漂移的坑，见 SOP 坑 5） |
| 容器隔离断言 | ✅ `Containers.assertConnectedToContainer(url)`，每个全栈测试基类都应含一条（防"静默连到宿主开发库"） |
| `spring-rabbit-test` | ✅ 依赖已声明，供 **feed 批次**（S9）做 MQ 断言用；当前尚未使用 |
| 架构边界测试 | ✅ `ArchitectureTests`（ArchUnit，S6-B3）4 条规则 |
| **回归基线** | ✅ **181 例全绿**（2026-10-02 实测，`mvnw.cmd -B test`） |

**当前测试不再依赖任何本机手工容器** —— 只需 Docker 在跑（Testcontainers 自己起
mysql / redis / rabbitmq）。停掉宿主的 `redis` / `rabbitmq` 容器**不影响**测试结果，
因为测试用的是自己的容器（这正是 T1「环境即代码」的验收点）。

## 二、测试依赖：正确坐标（已逐个 HEAD 验证 200）

### ⚠️ 关键陷阱：Testcontainers 2.0 **改名了模块坐标**

Boot 4.1.1 托管 `testcontainers.version=2.0.5`。**2.0 是破坏性重构**：

| 直觉写法（1.x，**错**） | 2.0 实际坐标（**对**） |
|---|---|
| `org.testcontainers:mysql` | `org.testcontainers:testcontainers-mysql` |
| `org.testcontainers:rabbitmq` | `org.testcontainers:testcontainers-rabbitmq` |
| `org.testcontainers:junit-jupiter`（仍1.21.4） | `org.testcontainers:testcontainers-junit-jupiter` |

**证据**：`org.testcontainers:mysql` 的 metadata **不存在**；2.0.5 的 jar 内**没有** `MySQLContainer`；
`testcontainers-bom:2.0.5` 的模块清单里全是 `testcontainers-*` 前缀。

**另注**：官方 2.0 模块清单中**没有 redis 模块**（Boot 托管的 `testcontainers-redis-module.version=2.2.4`
指的是社区 `com.redis:testcontainers-redis`，**非** `org.testcontainers` 出品）。
Redis 用 `GenericContainer` + `redis` 镜像即可，**不必**引第三方。

### 建议声明（版本全部由 Boot 父 POM 托管，**不写 version**）

| 依赖 | 作用 |
|------|------|
| `org.springframework.boot:spring-boot-testcontainers` | `@ServiceConnection` 支持 |
| `org.testcontainers:testcontainers-junit-jupiter` | `@Testcontainers` / `@Container` |
| `org.testcontainers:testcontainers-mysql` | `MySQLContainer`（提供 `MySQLContainer` / `org.testcontainers.mysql.MySQLContainer`） |
| `org.testcontainers:testcontainers-rabbitmq` | `RabbitMQContainer` |
| `org.springframework.amqp:spring-rabbit-test` | MQ 断言（版本由 spring-amqp BOM 托管） |

> `org.testcontainers:testcontainers`（核心）由上述模块传递引入，无需显式声明。

## 三、分层策略（决策⑦）

| 层 | 范围 | 依赖 | 占比目标 |
|----|------|------|---------|
| **单元** | 分支密集的纯逻辑（校验、换算、状态机） | 无（Mockito 按需） | 少 |
| **集成** | Service + Mapper + 真库（Testcontainers） | MySQL 容器 | 中 |
| **全栈** | `@SpringBootTest(RANDOM_PORT)` + 真 HTTP + 全容器 | MySQL + Redis + RabbitMQ 容器 | 主 |

**核心口径**：
- **集成/全栈测试是新的"端到端"**——不再有 pytest 平行体系（T4 债根因是双体系并行）
- 单测**只**覆盖分支密集逻辑，不做"为覆盖率而测 getter"
- Flyway 在每个测试容器里**自动建 schema**（V1 baseline 由此获得真正的验证环境）

### 3.1 数据的三个层次

| 数据 | 处置 |
|------|------|
| **结构**（DDL） | Flyway V1 自动执行 |
| **代码性质数据**（字典、基线管理员） | 可写成迁移脚本进 git（决策⑥） |
| **测试数据** | **每测试自建**（fixture builder）+ 隔离，废除"全局种子库"（T3 债） |

### 3.2 关键设计约束：`@ServiceConnection` 与"原生 3306"的隔离

**潜在冲突**：`application.yaml` 的开发默认值指向**宿主原生 mysqld:3306**。
若测试直接 `@SpringBootTest`，会连到开发库（读到真实数据、可能写坏）。

**处置**：测试**必须**用容器覆盖数据源：

```java
@SpringBootTest(webEnvironment = RANDOM_PORT)
@Testcontainers
class XxxIntegrationTest {

    @Container
    @ServiceConnection                    // 自动覆盖 spring.datasource.*
    static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.4");

    @Container
    @ServiceConnection
    static RabbitMQContainer<?> rabbit = new RabbitMQContainer("rabbitmq:4.3-management-alpine");

    @Container
    @ServiceConnection(name = "redis")    // GenericContainer + @ServiceConnection
    static GenericContainer<?> redis = new GenericContainer<>("redis:7-alpine").withExposedPorts(6379);
}
```

**防误连的验收断言**（每个全栈测试基类都应含一条）：

```java
// 明确断言"连的是容器，不是宿主库"——否则测试可能悄悄跑在开发库上
assertThat(dataSource.getConnection().getMetaData().getURL())
    .contains(String.valueOf(mysql.getMappedPort(3306)))
    .doesNotContain(":3306/TVDatabase");
```

理由：这是**最容易静默出错**的一处——测试连错库不会有任何报错，只会"意外通过"或"意外失败"。

## 四、防"测试迎合"（决策⑦核心纪律）

**问题**：为了让测试通过而写测试 → 测试变成实现的镜像，失去发现错误的能力。

**三条纪律**：

1. **断言可观察行为**，不断言内部实现
   - ✅ HTTP 状态 + body 信封、DB 终态、幂等性
   - ❌ "调用了 XxxMapper.updateCount 一次"

2. **独立 oracle 复算**（保留 TV pytest 精华）
   - 关键计算（计数、窗口、分页边界）用**独立于被测实现的算法**复算一遍再比对
   - 例：`like_count` 不读缓存也不读被测接口，直接 `SELECT COUNT(*)` 复算

3. **用例做"语义翻译"而非机械复制**
   - 旧测试的**意图**保留（边界/一致性），**形式**随架构重写
   - 迁移参照系里"每个切片必须固化的测试"清单即为翻译后的产物

### 4.1 事务边界测试（本迁移特有）

《事务边界决策表》里每个 ⚠️**有意改进**项，都需要一条**专门证明差异**的测试。
例（U-1）：注册成功 + 自动登录失败 → **断言用户行仍存在且 token == null**。
这类测试是**防回归的关键**——没有它，"顺手把两个事务合成一个"的误改不会被发现。

## 五、阶段验收

### 5.1 每个切片的完成定义（DoD）

一个切片**只有全部满足**才算完成：

| # | 条件 | 验证方式 |
|---|------|---------|
| 1 | 该切片相关事务边界**全部表态**（无 🔴） | 对照《事务边界决策表》§四 |
| 2 | 旧可观察行为已固化为测试 | 测试清单可执行 |
| 3 | 新实现采用 Spring 标准写法，**无旧模式残留** | 见 5.2 反模式清单 |
| 4 | 全栈测试走 Testcontainers，**不依赖本机手工容器** | 停掉本机 redis/rabbitmq 仍通过 |
| 5 | 端点契约与旧版一致（路径/信封/状态码） | 契约测试或手工对照 |
| 6 | `mvnw.cmd verify` 全绿 | CI 级命令 |
| 7 | 文档已更新（决策入 git） | 《事务边界决策表》状态更新 |

### 5.2 反模式清单（切片验收时逐条 grep）

```bash
# 以下任一命中 = 切片未完成
grep -rn "Connection conn" src/main/java/            # 连接穿透
grep -rn "throws SQLException" src/main/java/        # 手工异常
grep -rn "TransactionTemplate" src/main/java/        # 旧事务模板
grep -rn "com.itheima.ioc" src/main/java/            # 旧 IoC 注解
grep -rn "catch (SQLException" src/main/java/        # 手工包装
```

**通过标准**：全部零命中。

### 5.3 首个切片（`user`）的验收清单

**功能闭包**：注册 → 登录 → 持 token 访问受保护接口

| 测试 | 断言要点 |
|------|---------|
| 注册成功 | 返回 `LoginVO` 含 token；`users` 表新增一行；密码为 BCrypt（非明文） |
| 手机号重复 | `DuplicatePhoneException` → 对应信封码；**DB 无新增行** |
| 用户名重复 | `ConflictException` → 对应码；**DB 无新增行** |
| **注册成功+自动登录失败** | **用户行存在** + `token == null`（U-1 语义，**防误改关键**） |
| 登录成功 | 返回 token；token 可解出 userId |
| 密码错误 | `PasswordIncorrectException` → 对应码 |
| 用户不存在 | `UserNotFoundException` → 对应码 |
| 无 token 访问受保护接口 | HTTP 401 + 统一信封（Security `AuthenticationEntryPoint`） |
| 容器隔离断言 | §3.2 的 URL 断言 |
| 反模式 grep | §5.2 零命中 |

## 六、执行命令

```bash
# 依赖解析检查（改 pom 后必跑）
./mvnw.cmd -B dependency:tree

# 编译 + 测试
./mvnw.cmd -B test

# 切片验收（含所有插件绑定与校验）
./mvnw.cmd -B verify
```

**环境前置**：测试**只需 Docker 在跑**（Testcontainers 自带 mysql / redis / rabbitmq），
不再需要手工 `docker start redis rabbitmq`，也不需要本机 mysqld。

**辅助命令**（S6 起的 Python 工具，见 `tools/README.md`）：

```bash
python tools/endpoint_matrix.py     # 复算"还剩多少端点没搬"（校验《端点对照表》）
python tools/doc_stats.py           # 文档体量报告（看有没有又膨胀）
```
