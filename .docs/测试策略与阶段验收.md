### 1.1 测试依赖：无需显式声明 `spring-boot-starter-test`

`pom.xml` 并未显式声明 `spring-boot-starter-test`，但测试可编译运行。原因：

```
spring-boot-starter-flyway-test:4.1.1
  └── spring-boot-starter-test:4.1.1          ← 实际来源
        ├── org.junit.jupiter:junit-jupiter:6.0.3
        ├── org.mockito:mockito-core:5.23.0
        ├── org.mockito:mockito-junit-jupiter:5.23.0
        ├── org.assertj:assertj-core:3.27.7
        └── org.springframework.boot:spring-boot-test:4.1.1
```

**Boot 4 的测试 starter 已模块化**，每个功能自带 `-test` 变体：`flyway-test` / `security-test` /
`webmvc-test` / `jdbc-test` / `data-redis-test`…`spring-boot-starter-test` 由它们传递引入。

**结论**：JUnit 6 / Mockito 5.23 / AssertJ 3.27 **无需显式声明**。若将来移除 flyway-test，
需显式补 `spring-boot-starter-test`（或在需要处声明对应 `-test` 变体）。

## 三、分层策略（决策⑦）

| 层 | 范围 | 依赖 | 占比目标 |
|----|------|------|---------|
| **单元** | 分支密集的纯逻辑（校验、换算、状态机） | 无（Mockito 按需） | 少 |
| **集成** | Service + Mapper + 真库（Testcontainers） | MySQL 容器 | 中 |
| **全栈** | `@SpringBootTest(RANDOM_PORT)` + 真 HTTP + 全容器 | MySQL + Redis + RabbitMQ 容器 | 主 |

**核心口径**：
- **集成/全栈测试是新的"端到端"**——不再有 pytest 平行体系（T4 债根因是双体系并行）
- 单测**只**覆盖分支密集逻辑，不做"为覆盖率而测 getter"
- Flyway 在每个测试容器里**自动建 schema**（V1 baseline 由此获得真正的验证环境）

### 3.1 数据的三个层次

| 数据 | 处置 |
|------|------|
| **结构**（DDL） | Flyway V1 自动执行 |
| **代码性质数据**（字典、基线管理员） | 可写成迁移脚本进 git（决策⑥） |
| **测试数据** | **每测试自建**（fixture builder）+ 隔离，废除"全局种子库"（T3 债） |

### 3.2 关键设计约束：`@ServiceConnection` 与"原生 3306"的隔离

**潜在冲突**：`application.yaml` 的开发默认值指向**宿主原生 mysqld:3306**。
若测试直接 `@SpringBootTest`，会连到开发库（读到真实数据、可能写坏）。

**处置**：测试**必须**用容器覆盖数据源：

```java
@SpringBootTest(webEnvironment = RANDOM_PORT)
@Testcontainers
class XxxIntegrationTest {

    @Container
    @ServiceConnection                    // 自动覆盖 spring.datasource.*
    static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.4");

    @Container
    @ServiceConnection
    static RabbitMQContainer<?> rabbit = new RabbitMQContainer("rabbitmq:4.3-management-alpine");

    @Container
    @ServiceConnection(name = "redis")    // GenericContainer + @ServiceConnection
    static GenericContainer<?> redis = new GenericContainer<>("redis:7-alpine").withExposedPorts(6379);
}
```

**防误连的验收断言**（每个全栈测试基类都应含一条）：

```java
// 明确断言"连的是容器，不是宿主库"——否则测试可能悄悄跑在开发库上
assertThat(dataSource.getConnection().getMetaData().getURL())
    .contains(String.valueOf(mysql.getMappedPort(3306)))
    .doesNotContain(":3306/TVDatabase");
```

理由：这是**最容易静默出错**的一处——测试连错库不会有任何报错，只会"意外通过"或"意外失败"。

## 四、防"测试迎合"（决策⑦核心纪律）

**问题**：为了让测试通过而写测试 → 测试变成实现的镜像，失去发现错误的能力。

**三条纪律**：

1. **断言可观察行为**，不断言内部实现
   - ✅ HTTP 状态 + body 信封、DB 终态、幂等性
   - ❌ "调用了 XxxMapper.updateCount 一次"

2. **独立 oracle 复算**（保留 TV pytest 精华）
   - 关键计算（计数、窗口、分页边界）用**独立于被测实现的算法**复算一遍再比对
   - 例：`like_count` 不读缓存也不读被测接口，直接 `SELECT COUNT(*)` 复算

3. **用例做"语义翻译"而非机械复制**
   - 旧测试的**意图**保留（边界/一致性），**形式**随架构重写
   - 迁移参照系里"每个切片必须固化的测试"清单即为翻译后的产物

### 4.1 事务边界测试（本迁移特有）

《事务边界决策表》里每个 ⚠️**有意改进**项，都需要一条**专门证明差异**的测试。
例（U-1）：注册成功 + 自动登录失败 → **断言用户行仍存在且 token == null**。
这类测试是**防回归的关键**——没有它，"顺手把两个事务合成一个"的误改不会被发现。

### 6.5 顺带答一个常被问的问题：**Spring 生态里测试变简单了吗？**

**是，但不是均匀的，而且代价换了地方。** 6.3 那张表本身就是证据——**40 条**测试
（连接池 + 事务模板）直接消失，因为那些能力由框架提供。

| 能力 | 老项目怎么测 | 新项目怎么测 |
|---|---|---|
| Redis 缓存 | **`MockedStatic` 打桩 `MyRedisPool.getJedis()`**（`CacheAsideTest` 49 例） | **真 Redis 容器** + 直接断言 key 状态 |
| MySQL | `MyConnectionPoolTest` 要**真 MySQL + surefire 单独 fork + 环境变量** | Testcontainers 自动，一个基类 |
| 事务 | 手写模板 + 专项测试 | `@Transactional` + 回滚证明（**断言更强**） |
| 环境编排 | `run_tests.py` + 手工三个容器 | `mvnw verify`（容器自起） |

**最大的一处简化**：不用再造假。`CacheAsideTest` 那 49 例测的是"缓存逻辑在**假 Redis** 下对不对"——
新体系里真 Redis 就在旁边，**这类测试从根上不需要**。

**代价（要认）**：① 必须有 Docker，否则一条都跑不了；② Spring 上下文 + 容器有启动成本
（`clean verify` 2 分 02 秒——**与老 e2e 的 ~2 分钟相当，没有变慢**）；
③ **报错更难读**（踩过的坑 16/17 都是"真因被截断或指错地方"）；
④ 容器与上下文成了**新的测试基建**（坑 5 端口漂移、坑 12 自调用失效）。

### 6.6 ★ 唯一的行为判据（304 例已在执行）

> **能用真组件的就用真的；只在"真组件产生不了该故障"时才用 Mockito。**

样本：`AdminTransactionTests` 的打桩点选在"已有成功写**之后**的最后一步写操作"，
用一次 `doThrow` 证明"多条前置写被回滚"——这种故障**真组件产生不了**，故必须 mock
（且坑 18 证明不能对 MyBatis mapper 用 `doCallRealMethod`）。
反过来，**缓存行为绝不该再 mock Redis**。

### 6.7 ★ 25 条日志 e2e 的处置（第三批 T2 兑现，2026-10-03）

> 这 25 条是 §6.3 里那行"日志基建整块未迁（**唯一账没记全的一项**）"的连带损失。
> T2 按工单的要求**翻译它们的意图**（`test_access_log` 5 / `test_audit_log` 6 /
> `test_milestone_log` 9 / `test_log_outputs` 5），**不照抄实现**——老项目那套是 JUL +
> 手写 `LogUtil`/`LogContext`/`LogFormatter`，新项目换成 logback 配置 + MDC + 自定义转换字。
> 承接方：`observability/` **8 个测试类 33 例** + `common/log/` **2 个纯函数测试类 16 例**，合计 **49 例**，
> 全部带 `@Tag("observability")`（可 `python tools/run_tests.py --group observability` 单跑——
> 该组含**纯函数测试**，它们本来就在默认回归集里，tag 只是让"按任务选跑 T2 交付物"更完整）。

| 老用例（条数） | 翻译成 | 差别 / 有意不照抄的地方 |
|---|---|---|
| `test_access_log`（5） | `observability/AccessLogTests`（6 例） | ① 旧判据是 `code=0`（**HTTP 恒 200 + body code**），新判据是 `status` + `code` **两个**字段（决策⑧"HTTP 状态码正确化"），三态变成 `200/200`·`401/401`·`200/0`；② 旧靠 `LOG_PATH` 注入 + 轮转文件名 `<名>.N` 读法，新用例直接用**该请求的 req** 定位（不依赖行号/文件名）；③ "慢请求 `slow=1`" 的触发改为 `AccessLogFilter.buildLine` 的**纯函数**断言（与旧项目同款：本地请求达不到 1000ms 阈值） |
| `test_audit_log`（6） | `observability/AuditLogTests`（7 例） | ① 旧用"全文件计数 delta"定位，新用 **req 值集合差**（轮转/并发都不影响）；② ★**审计写入层**从 service 方法体内挪到 controller 的服务调用**之后**（提交后），理由见《决策留痕表》G-5；③ TV 第 7 点 `user.changePhone` 无 HTTP 入口，**两边一致地不覆盖**；④ 比旧多一条**机制证明**：打桩让服务事务在"已完成一次写"之后失败 ⇒ 回滚 ⇒ **审计行一条都不产生**（G-5 的存在证明，与里程碑的同族手法） |
| `test_milestone_log`（9） | `observability/MilestoneLogTests`（5）+ `ContentMilestoneTests`（2） | ① 7 个补点全部保留（注册/登录/添加视频/添加动态/删除内容/关注/取关），**文案逐字沿用**（它们就是契约）；② ★内容三点走**独立类**：加了"**事务回滚 ⇒ 一条里程碑都不产生**"的成对用例——那是 `AFTER_COMMIT` 机制的**存在证明**（老项目没有，因为它的日志写在事务方法体里）；③ 关系两点在 S4 已有独立用例，此处只纳入"文件级零重叠"扫描；④ 里程碑与审计的**文件级零重叠**用真实文件断言（内存 sink 挂在 `access`/`audit` logger 上收不到别域日志，那样写会**恒真**） |
| `test_log_outputs`（5） | `observability/LogOutputSplitTests`（3）+ `LogbackConfigTests`（5）+ `SensitiveDataTests`（3） | ① 旧靠"轮转文件名 + 行号增量"，新靠**结构化行不变式 + req 定向**；② "error 只收 SEVERE"→"只收 **ERROR**"（SLF4J 无 SEVERE）；③ 新增**结构性契约**一层（`LogbackConfigTests` 直接断言 `additivity=false` / 阈值 / pattern 三要素），这是旧体系做不到的（JUL 下无等价对象可断言） |
| （T2 新增，非翻译） | `observability/CacheMetricsTests`（2） | 账 **B3** 的兑现：`/actuator/metrics/cache.events` 可见，六事件与 TV `CacheStats` **同名** |

**三处"级别名 + 结论行归属"的口径差**（不是回归，是栈换了）：
JUL `SEVERE`→SLF4J `ERROR`、JUL `WARNING`→SLF4J `WARN`；
老用例要求"可预期拒绝的 WARNING 结论行由**业务类 logger** 记、且**带 `userId=`**"，
新项目集中在 `GlobalExceptionHandler`（决策⑧"错误出口统一"）——**这是有意为之**（《决策留痕表》G-7），
但要如实记下**代价**：新口径的拒绝结论行**不带操作者身份**，且匿名登录失败时 access 行也是 `userId=-`
⇒ "哪个账号在反复失败登录"在日志里**不可回答**（TV 因在业务方法内记，是可回答的）。
若要恢复，落点是 `handleBusiness` 里补一个可得的操作者标识——**这是已知的可观测性降级，不是缺陷**。
（另：新口径的 WARN 结论行**不带堆栈**，与 TV「包装点即源头」一致；
该性质已由 `MilestoneLogTests.登录失败不发里程碑且记WARN` 钉住，不再是巧合。）

## 七、执行命令

```bash
# 依赖解析检查（改 pom 后必跑）
./mvnw.cmd -B dependency:tree

# 编译 + 测试
./mvnw.cmd -B test

# 切片验收（含所有插件绑定与校验）
# ⚠️ 必须带 clean：target/classes 留着上一轮 class 时增量编译会跳过重编，
#    "源码编译不过"会被旧 class 掩盖而测试照样绿（2026-10-03 实测到该路径）
./mvnw.cmd -B clean verify
```

**环境前置**：测试**只需 Docker 在跑**（Testcontainers 自带 mysql / redis / rabbitmq），
不再需要手工 `docker start redis rabbitmq`，也不需要本机 mysqld。

**辅助命令**（S6 起的 Python 工具，见 `tools/README.md`）：

```bash
python tools/endpoint_matrix.py     # 复算"还剩多少端点没搬"（校验《端点对照表》）
python tools/doc_stats.py           # 文档体量报告（看有没有又膨胀）
```
