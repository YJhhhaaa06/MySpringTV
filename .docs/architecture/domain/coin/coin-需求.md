# 投币（硬币）—— 用户可见规则（需求）

> 定位（先读这一句）：本篇只记**用户看得到的行为与规则**，是投币功能"**要做成什么样**"的**唯一事实源**。
> **不写**：表怎么建 / 端点怎么命名 / 缓存怎么失效 → 同目录 [coin](./coin.md)；
> 缓存 / 事务 / 鉴权等**横切机制**不在本篇，去向见文末 [§边界与去向](#边界与去向机制外链)。
>
> 参照系是 **B 站**。★ 本仓有**三处刻意偏离**（§二 / §三）：硬币来源改成**个人主页手动签到**、
> **无等级 / 经验门槛**、**不区分自制与转载** —— 因为本仓**没有定义"在线"**，也没有经验、热度与推荐机制。

---

## 一、这是什么

硬币是站内的"打赏"凭证：观众用自己的硬币给**视频**投票，视频的作者因此收到少量硬币回报。

与点赞、收藏的三处不同，用户能直接感知：

1. 点赞是"一下"、收藏是"收进夹"，**投币是要花掉自己硬币的** —— 它是**有成本的表态**；
2. 点赞能取消，**投币不可取消**；
3. 同一条视频可以被同一个人投**多次**（上限 2 枚），不是"一次表态"。

---

## 二、硬币从哪来（签到）

| 功能 | 用户看到什么 | 本项目 |
|---|---|---|
| 手动签到 | 在**个人主页**上点「签到」 | 纳入（每日一次） |
| 签到给币 | 每次签到 **+1 枚硬币** | 纳入 |
| 连续签到奖励 | 连签第 N 天多给 | ❌ **不做**（每日恒 1 枚） |
| 补签 | 补回漏掉的那天 | ❌ **不做** |
| 新用户初始硬币 | 注册即送 N 枚 | **0 枚**（想有币就得签到） |
| 重复签到 | 当天再点一次 | **幂等** —— 回「今日已签到」，**不再给币、也不报错** |
| 签到算哪一天 | —— | **上海自然日**（与站内时间的既有口径一致） |

> ★ **偏离说明**：B站 的硬币**不是签到来的**（靠每日登录 / 观看 / 分享等任务）。本仓改成"手动签到"
> 是**有意偏离**：本仓**没有定义"在线"**（除登录态外没有活跃度信号），签到是本仓唯一能自证的"每日来过"。

## 三、投币

| 功能 | 用户看到什么 | 本项目 |
|---|---|---|
| 投币对象 | 视频可以投 | 纳入 |
| 帖子能不能投 | 图文动态 | ❌ **不能投**（图文帖不含投币这一维） |
| 一次投几枚 | 弹层里选 **1 枚** 或 **2 枚** | 纳入 |
| 同一视频上限 | **2 枚** | 纳入 |
| 自制 / 转载 | 自制最多 2、转载最多 1 | ❌ **不区分**（本仓没有"自制/转载"）⇒ **统一 2 枚** |
| 分两次投 | 先投 1 枚，再点还能投 1 枚；投满后再点 ⇒ 提示「**对本稿件投币枚数已用完**」 | 纳入（**累加**语义） |
| 取消投币 | —— | ❌ **不能取消**（一经投出不可撤回） |
| 给自己投币 | —— | ❌ **不能**（提示「不能给自己投币」）。★ 除对齐 B站 外还有一条**本仓理由**：自投会形成"**签到 → 自投 → 拿回 1/10**"的刷币闭环 |
| 硬币不足 | 余额不够 | 提示「硬币不足」，**不扣款、不留痕** |
| 内容已失效 | 稿件被删 / 下架 | 提示「内容不存在」，**不能投** |
| UP主收到什么 | —— | 投出 `N` 枚 ⇒ **作者得 `N/10` 枚**（可带 `0.1` 尾数，见 §四） |
| 投币影响推荐 / 动态吗 | —— | ❌ **不影响**（本仓没有推荐机制；投币**不产生动态、不进关注流**） |
| 投币通知作者吗 | —— | ❌ **不做**（本仓没有站内消息 / 通知体系） |

## 四、用户看得到的数字

| 数字 | 用户看到什么 | 本项目 |
|---|---|---|
| **我的硬币余额** | 可带一位小数（如 `1.5`）；投币弹层与签到回执里都看得到 | 纳入 |
| **今天签到了没** | 个人主页的签到按钮**进页就知道**（已签 ⇒ 置灰），不用"点一下才知道" | 纳入 |
| **一条视频被投了几枚** | 详情页与列表卡片上的投币数 | 纳入 |
| **我给这条视频投了几枚** | 打开详情页即知 `0 / 1 / 2`，**不需要二次查询**（数字随详情一起返回） | 纳入 |
| **硬币明细流水**（我投出去的每一枚） | B站 有钱包明细页 | ❌ **本期不做**（留池） |
| **UP主主页「获得硬币」** | B站 个人空间有数据面板 | ❌ **本期不做**（留池） |

> ★ **余额为什么会有小数**：自己签到得的是整枚，但**UP主 收益是 `1/10`** ⇒ 作者余额会出现 `0.1` 这类尾数。
> 展示口径 = **精确到一位小数**（不四舍五入、不丢尾数）；
> 但**能投出的枚数只按整数部分算** —— 余额 `1.5` ⇒ 只能投 1 枚、不能投 2 枚。

## 五、用户看得到的规则（口径汇总）

| 规则 | 口径 |
|---|---|
| 什么能投 | **只有视频**；图文帖 ⇒ 400「该内容不支持投币」 |
| 一次投几枚 | `1` 或 `2`；其它值 ⇒ 400 |
| 单视频上限 | **2 枚**（累加到达）；再投 ⇒ 409「对本稿件投币枚数已用完」 |
| 可否取消 | **不可取消**（系统里就没有"取消投币"这个动作） |
| 余额与收益的关系 | 作者的收益**直接进他的硬币余额**（可继续拿去投币，无需"提现"） |
| 余额精度 | 可见 1 位小数；**投币能力按整数部分**判 |
| 拒因优先级 | 参数非法 → 内容不存在 → 非视频 → 自投 → 已投满 → 余额不足（明细见 [coin](./coin.md) §八） |
| 签到幂等 | 当天重复点 ⇒ 200「今日已签到」，余额不变 |
| 与动态 / 推荐的关系 | **都不产生、都不影响** |

## 六、明确不做

| 项 | 处置 |
|---|---|
| 投币**可取消** | ❌ 不做（B站 亦不可取消） |
| **等级 / 经验**门槛（Lv1 以上才能投） | ❌ 不做（本仓没有等级与经验机制） |
| 每日投币**上限** | ❌ 不做（币的稀缺由"每日 1 枚"的**供给**天然限制，不另设上限） |
| 硬币**充值 / 提现** | ❌ 不做（本仓无支付） |
| 投币后的**站内通知** | ❌ 不做（本仓没有通知体系） |
| 硬币**明细流水页** | ❌ 本期不做（留池） |
| UP主主页**获得硬币**面板 | ❌ 本期不做（留池） |
| **连签奖励 / 补签** | ❌ 不做（本仓只有"每日 1 枚"） |
| 投币**动画 / 音效 / 弹窗动效** | ❌ 不做（前端体验环节另议） |
