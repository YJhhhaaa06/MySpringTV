# 播放记录 —— 用户可见规则（需求）

> 定位（先读这一句）：本篇只记**用户看得到的行为与规则**，是播放记录"**要做成什么样**"的唯一事实源。
> **不写**：表怎么建 / 端点怎么命名 / 缓存怎么失效 / 并发怎么做 → [history](./history.md)；
> 页面与词的准确说法 → [history-术语表](./history-术语表.md)；
> 横切机制 → 文末 [§边界与去向](#边界与去向机制外链)。
>
> 参照系是 **B 站**。★ 本仓有**两处刻意偏离**（§六）：播放量按**人 + 自然日**去重（B站 更宽容）、
> **后到即新**（重看从头会覆盖进度）。★ 2026-10-31（`R-26`）：**"不能删除历史"已不再是偏离** ——
> 删除 / 批量 / 清空已交付（`DELETE /api/v1/history`）。

---

## 一、这是什么

播放记录回答两个问题：**"我看到哪了"** 和 **"这个视频有多少人看过"**。

- 打开视频并上报进度 ⇒ 历史里出现（或更新）一条记录；
- 同一用户第一次播放某视频 ⇒ 该视频播放量 `+1`，之后再看不重复计；
- 下次打开同一视频 ⇒ 能拿到上次的秒数，接着看。

⚠️ 这里有两个容易混的单位：**"一次播放"是计数单位（按人去重）**，**"一次观看会话"是生命周期单位**
（一次打开到关闭）。同一个人看三遍 = 3 个会话、1 次播放。见 [术语表](./history-术语表.md) §二。

## 二、历史记录页（用户看到什么）

| 功能 | 用户看到什么 | 本项目 |
|---|---|---|
| 列表内容 | 我看过的视频，**按最后观看时间倒序** | 纳入 |
| 一条记录 | 封面、标题、作者、**上次看到第几秒**、总时长 | 纳入 |
| 同一视频看多次 | 列表里仍然**只有一条**，时间与进度更新 | 纳入 |
| 多设备看同一视频 | 仍然只有一条；**最后上报的那台设备**覆盖进度 | 纳入（LWW，§六） |
| 只打开、没上报进度 | 也会出现在历史里（进度 0 秒），播放量已计 | 纳入（`/play` 建行） |
| 失效视频 | 显示「**内容已失效**」占位（无封面 / 作者） | 纳入 |
| 分页 | 一页 20 条，最多 100 条 | 纳入 |
| 「记录浏览历史」开关 | B站 在标题行右侧，可暂停记录 | **纳入**（2026-10-31，§2.1，`R-25`） |
| 删除单条 / 批量 / 清空历史 | B站 有 | **纳入**（2026-10-31，`R-26`：多选删除 + 清空，管理态里只能删除） |
| 按日期分组（今天 / 昨天 / 更早） | B站 有 | ❌ **不做**（前端可按时间自行分组） |

**失效占位**：进度仍然保留（接口里还能看到"看到第几秒"），但总时长取不到（`null`）；
前端可以选择不渲染进度条。占位条目**仍计入总数**。

★ **历史记录页只读 `GET /api/v1/history`**（外加 `GET /users/me` 里带回来的开关状态）；
除开关外不发任何写请求 —— 写与续播都发生在**播放页**（§三）。

### 2.1 「记录浏览历史」开关（`R-25`，2026-10-31）

| 规则 | 口径 |
|---|---|
| 位置 | 历史记录页**标题行右侧**；**不吸顶**，随页面滚动移出视野（B站 2560 实测） |
| 默认 | **开**（`users.history_recording = 1`）⇒ 存量用户无感 |
| 关闭 | 弹确认框「确认要停用历史记录？/ 停用之后浏览记录将不再更新」，按钮 取消 / 确认；**点遮罩 = 取消**；确认后开关立即变灰 |
| 打开 | **不**弹确认，立即生效 |
| 生效范围 | **只影响之后开始的观看会话**：不记进度、不记"刚看过"、**不计播放量**（见 §四） |
| 已有记录 | **保留**（关闭开关**不清除**任何记录 —— 要清除请用删除 / 清空，`R-26`）—— 所以文案说的是"不再更新"而不是"清除" |
| 拨动失败 | **不提示、不回弹**（B站 实测口径）：断网时切到关闭，界面照变；服务端没收到 ⇒ **刷新后变回原值**，即"断网期间的关闭不算数" |
| 何时同步 | 每次**整页装载**随 `GET /users/me` 读一次；另一个标签页 / 另一台设备最长到下次装载才生效（判据见 [客户端契约](./history-客户端契约.md) §二.1） |
| 服务端强制吗 | ❌ **不强制**（刻意偏离 B站）—— 直接调 `/report` 仍会记录；理由与推翻条件见 [已知代价](./history-已知代价.md) |

## 三、续播

| 规则 | 口径 |
|---|---|
| 打开播放页后 | 单独查一次「我的进度」（`GET /api/v1/contents/{id}/progress`），没有记录 ⇒ `0` |
| 进度单位 | **秒**（整数） |
| 进度来源 | 播放器上报；**服务端不猜**（不按"打开时长"推算） |
| 已删除的视频 | 仍能查到历史进度（内容是死是活由详情 404 负责） |
| 总时长 | 随内容详情返回（`durationSeconds`）；未知时为 `null` |

## 四、播放量（**按人 + 按自然日**去重）

| 规则 | 口径 |
|---|---|
| 什么算一次播放 | 登录用户对该视频发出**播放事件**（`POST /api/v1/contents/{id}/play`）；按**人**去重，**去重粒度是自然日** |
| "一天"从哪算 | **服务器时间、业务时区 `Asia/Shanghai`** 的日历日（`R-26`：与《接口契约》§2.7 的 +08:00 同一基准）；`0:00` 换日 |
| 同一用户重复播放 | **同一天只算一次**；**第二天再播会再算一次**（旧口径"永远只算一次"已作废） |
| 删了历史再播 | **同一天不再计**（证据在账本里，删历史删不到）；**第二天再播照常计** |
| 跨日会话 | **不补计**：播放事件只在会话开始发一次，23:59 开始的会话算在开始那天 |
| 未登录用户 | **不计**（没有用户可归属） |
| 关闭「记录浏览历史」期间 | **不计**：客户端连播放事件都不发 ⇒ 服务端无从计数（`R-25`；代价见 [已知代价](./history-已知代价.md)） |
| 作者自己看 | **也算一次**（本仓不做"自播排除"；按人按天口径下每人每天最多多 1） |
| 播放量显示在哪 | **详情 + 列表卡片**（GAP-01 起）：详情 `ContentDetailVO.playCount`；网格卡片封面角标 / 动态嵌入块读 `ContentVO.playCount` |
| 图文帖 | 没有播放量（也不能上报） |
| 内容被删除 | 播放量不变（详情已 404，数字不再可见） |
| 播放事件重复发送 | 后端**幂等去重**，不报错、不重复计 |
| 播放量会不会下降 | **不会**（没有"取消播放"） |

> ★ **与 B站 的偏离**：B站 的播放量按"次"累计（有风控），本仓按"**人**"去重
> —— 一个人看一百遍也只算一次。这是本仓为了降低实现难度的**有意选择**。

## 五、时长

| 规则 | 口径 |
|---|---|
| 时长从哪来 | 上传的 mp4 文件头（`moov → mvhd`），**不用 ffmpeg** |
| 什么时候解析 | 发布视频时；作者**换源**（换视频文件）时重新解析 |
| 解析失败 | 时长记为"未知"（`null`），**不阻断发布**；视频仍可播放 |
| 存量视频 | 2026-10-27 已一次性回填（`tools/devclean/backfill_duration.py`，只填 NULL）；盘上文件缺失 / 解析失败仍为 `null`，进度按秒展示、不显示百分比 |
| 换源后 | 时长按新文件刷新；旧进度可能大于新时长，**下次上报时**被修正 |

## 六、明确不做 / 刻意偏离

| 项 | 处置 | 为什么 |
|---|---|---|
| 删除单条 / 批量 / 清空历史 | ✅ **做**（`R-26`，2026-10-31） | 前置条件"计过数人次的独立载体"随 `V10` 的账本 `content_play_dedup` 一起落地 ⇒ 删行不再影响播放量（删历史**不减**播放量，B站 同口径） |
| 播放量去重粒度 | **每人·每内容·每自然日一次**（来源 `R-26`） | 旧口径"永久一次"已作废：它把证据长在历史行上，与"历史可删"互斥。账本**不回填** ⇒ 存量内容与账本行数之间允许有历史余额，见 [已知代价](./history-已知代价.md) |
| 账本清理 | ❌ 不做 | 只有"今天"的行有约束力 ⇒ 清理是纯容量优化；真要做走 `tools/devclean/` 运维脚本，**不引入常驻定时任务** |
| **后到即新（LWW）** | 先到的请求算旧、后到的算新；**不做"进度只能增"** | 代价是**重看从头会把进度改回 0**、客户端重试的旧包后到会倒退 |
| 「已看完」标记 | ❌ 不做 | 前端用 `progress / duration` 自己算（如 ≥95%） |
| 服务端**上报缓冲**（心跳先写 Redis，退出同步落库、空闲轮询兜底） | ✅ **做** | 见 [history-上报缓冲](./history-上报缓冲.md)。用户可见影响只有一条：**崩溃 / 断网的会话最多回退「闲置阈值 + 一次心跳」的进度**；正常退出的会话延迟为 0 |
| 历史容量上限 / 旧行清理 | ❌ 不做 | 一人一内容一行，增长有界（用户 × 看过的内容）；需要时另开清理工具。代价与推翻条件见 [history-已知代价](./history-已知代价.md) |
| 历史列表缓存 | ❌ 不做 | 私有 + 写多读少 + 每次上报都变 |
| 服务端**强制**「记录开关」（B站 实测是强制的） | ❌ **不做**（`R-25`：客户端自愿拦写） | 本仓只有一个客户端；服务端要拦四个口子（`/report` / `/play` / `/flush` / 轮询兜底），其中轮询**没有请求可拦**。代价与推翻条件见 [已知代价](./history-已知代价.md) |
| 前端页面 | ❌ 本期不做 | 后端先落地；`static/` 与 `api.js` 不动（历史记录页的导航项仍是 `disabled`）。★ **状态更新（2026-10-26）**：旧 SPA 已删除；播放页进度已接入（见 [history-客户端契约](./history-客户端契约.md)），**历史列表页已于本窗口交付**（`frontend/src/pages/HistoryPage.vue`） |
| 播放量进列表 | ✅ 做（GAP-01，2026-10-26） | 列表面按面带 `playCount`（网格 / 动态卡片都有展示位）；其余四维仍只在详情。口径见 [缓存与数据一致性 §5.3](../../tech/cache/缓存与数据一致性.md) |

## 七、用户看得到的规则（口径汇总）

| 规则 | 口径 |
|---|---|
| 上报进度的对象 | **只有视频**；图文 ⇒ 400「只能记录视频的播放进度」 |
| 进度非法 | 负数 ⇒ 400 |
| 内容不存在 / 已删 | 404「内容不存在」 |
| 进度超过时长 | 按当前时长**截断**（不报错） |
| 重复上报同一进度 | 幂等，成功；记录仍会排到最前 |
| 播放事件重复 | 幂等，成功；播放量不变 |
| 历史排序 | 最后上报时间倒序；同一秒按内容 id 倒序 |
| 失效条目 | 占位「内容已失效」，保留进度，不保留封面 / 作者 / 时长 |
| 删除一条 | 卡片垃圾桶**直接删**（无确认）；成功即从列表消失（`R-26`） |
| 批量删除 | 管理态勾选后点「删除」**必过确认框**；一次最多 **500** 条（超出 400）；「全选」= **已加载出来的**条目，不是整库 |
| 清空历史 | 工具栏「清空历史」**必过确认框**；删光当前账号的全部历史 |
| 删除后播放量 | **不减**（B站 同口径）；同一天再播**不再计**，换一天再播**再计一次** |
| 删除后重看 | 历史行会**重新出现**（进度 0）；本地续播也被清 ⇒ 从头开始 |
| 进度何时可见（`/position`） | **已落库的那一刻起**（不读缓冲）。本机重开取 `max(服务端, 本地当前进度)` ⇒ **精确到 ≤1s**。**另一台设备**要等原设备 flush（暂停 / 退出 / 切页 ⇒ 立即）—— ★ **原设备一直播不暂停就看不到**（轮询只兜"停止上报"的会话；B站 实测约 30s 可见，本仓这点弱于它） |
| 进度何时出现在列表（`/list`） | **正常退出立即**（flush）；★ **一直在播就一直是旧值**（未落库）；崩溃 / 断网的会话（停止上报）约 **75s** 后被兜底落库 |
| 崩溃 / 断网后重进（同一浏览器） | 客户端本地存**每秒更新**的当前进度（不是"上次上报值"）；重进时取 `max(服务端, 本地)` 定位，**本地更新才补报**（旧设备不能覆盖别处更新的进度）⇒ 崩溃会话也能精确续播。见 [history-客户端契约](./history-客户端契约.md) §六 |
