# 播放记录 —— 用户可见规则（需求）

> 定位（先读这一句）：本篇只记**用户看得到的行为与规则**，是播放记录"**要做成什么样**"的**唯一事实源**。
> **不写**：表怎么建 / 端点怎么命名 / 缓存怎么失效 / 并发怎么做 → 同目录 [history](./history.md)；
> 缓存 / 事务 / 鉴权 / 限流等**横切机制**不在本篇，去向见文末 [§边界与去向](#边界与去向机制外链)。
>
> 参照系是 **B 站**。★ 本仓有**三处刻意偏离**（§六）：播放量按**人去重**、**不能删除历史**、
> **后到即新**（重看从头会覆盖进度）。

---

## 一、这是什么

播放记录回答两个问题：**"我看到哪了"** 和 **"这个视频有多少人看过"**。

- 打开视频并上报进度 ⇒ 历史里出现（或更新）一条记录；
- 同一用户第一次播放某视频 ⇒ 该视频播放量 `+1`，之后再看不重复计；
- 下次打开同一视频 ⇒ 能拿到上次的秒数，接着看。

---

## 二、历史列表（用户看到什么）

| 功能 | 用户看到什么 | 本项目 |
|---|---|---|
| 列表内容 | 我看过的视频，**按最后观看时间倒序** | 纳入 |
| 一条记录 | 封面、标题、作者、**上次看到第几秒**、总时长 | 纳入 |
| 同一视频看多次 | 列表里仍然**只有一条**，时间与进度更新 | 纳入 |
| 多设备看同一视频 | 仍然只有一条；**最后上报的那台设备**覆盖进度 | 纳入（LWW，§六） |
| 只打开、没上报进度 | 也会出现在历史里（进度 0 秒），播放量已计 | 纳入（`/play` 建行） |
| 失效视频 | 显示「**内容已失效**」占位（无封面 / 作者） | 纳入 |
| 分页 | 一页 20 条，最多 100 条 | 纳入 |
| 删除单条 / 清空历史 | B站 有 | ❌ **不做**（§六） |
| 按日期分组（今天 / 昨天 / 更早） | B站 有 | ❌ **不做**（前端可按时间自行分组） |

**失效占位**：进度仍然保留（接口里还能看到"看到第几秒"），但总时长取不到（`null`）；
前端可以选择不渲染进度条。占位条目**仍计入总数**。

## 三、续播

| 规则 | 口径 |
|---|---|
| 打开详情后 | 单独查一次「我的进度」（`GET /history/position`），没有记录 ⇒ `0` |
| 进度单位 | **秒**（整数） |
| 进度来源 | 播放器上报；**服务端不猜**（不按"打开时长"推算） |
| 已删除的视频 | 仍能查到历史进度（内容是死是活由详情 404 负责） |
| 总时长 | 随内容详情返回（`durationSeconds`）；未知时为 `null` |

---

## 四、播放量（**按人去重**）

| 规则 | 口径 |
|---|---|
| 什么算一次播放 | 登录用户对该视频发出**播放事件**（`/history/play`） |
| 同一用户重复播放 | **永远只算一次**（不是每天一次、不是每次一次） |
| 未登录用户 | **不计**（没有用户可归属） |
| 作者自己看 | **也算一次**（本仓不做"自播排除"；一人一次口径下最多多 1） |
| 播放量显示在哪 | **只在详情页**；列表卡片不显示任何计数（本仓 T43 口径） |
| 图文帖 | 没有播放量（也不能上报） |
| 内容被删除 | 播放量不变（详情已 404，数字不再可见） |
| 播放事件重复发送 | 后端**幂等去重**，不报错、不重复计 |
| 播放量会不会下降 | **不会**（没有"取消播放"） |

> ★ **与 B站 的偏离**：B站 的播放量按"次"累计（有风控），本仓按"**人**"去重
> —— 一个人看一百遍也只算一次。这是本仓为了降低实现难度的**有意选择**。

## 五、时长

| 规则 | 口径 |
|---|---|
| 时长从哪来 | 上传的 mp4 文件头（`moov → mvhd`），**不用 ffmpeg** |
| 什么时候解析 | 发布视频时；作者**换源**（换视频文件）时重新解析 |
| 解析失败 | 时长记为"未知"（`null`），**不阻断发布**；视频仍可播放 |
| 存量视频 | 没有时长（`null`），不回填；进度按秒展示、不显示百分比 |
| 换源后 | 时长按新文件刷新；旧进度可能大于新时长，**下次上报时**被修正 |

## 六、明确不做 / 刻意偏离

| 项 | 处置 | 为什么 |
|---|---|---|
| 删除单条 / 清空历史 | ❌ **不做** | 一删就和"播放量只增"打架（B站 删历史不减播放量）；保住 `play_count == COUNT(play_counted=1)` 可复算 |
| **后到即新（LWW）** | 先到的请求算旧、后到的算新；**不做"进度只能增"** | 用户 2026-10-21 拍板；代价是**重看从头会把进度改回 0**、客户端重试的旧包后到会倒退 |
| 「已看完」标记 | ❌ 不做 | 前端用 `progress / duration` 自己算（如 ≥95%） |
| 服务端**上报缓冲**（心跳先进 Redis，退出同步落库、空闲轮询兜底） | ✅ **做**（`R-19`，2026-10-22） | 见 [history](./history.md) §十二。用户可见影响只有一条：**崩溃 / 断网的会话最多回退「闲置阈值 + 一次心跳」的进度**；正常退出的会话延迟为 0 |
| 历史容量上限 | ❌ 不做 | 一人一内容一行，增长有界（用户 × 看过的内容）；需要时另开清理工具 |
| 历史列表缓存 | ❌ 不做 | 私有 + 写多读少 + 每次上报都变 |
| 前端页面 | ❌ 本期不做 | 后端先落地；`static/` 与 `api.js` 不动 |
| 播放量进列表 | ❌ 不做 | 沿 T43「列表零计数」；B站 卡片有，本仓**有意不同** |

## 七、用户看得到的规则（口径汇总）

| 规则 | 口径 |
|---|---|
| 上报进度的对象 | **只有视频**；图文 ⇒ 400「只能记录视频的播放进度」 |
| 进度非法 | 负数 ⇒ 400 |
| 内容不存在 / 已删 | 404「内容不存在」 |
| 进度超过时长 | 按当前时长**截断**（不报错） |
| 重复上报同一进度 | 幂等，成功；记录仍会排到最前 |
| 播放事件重复 | 幂等，成功；播放量不变 |
| 历史排序 | 最后上报时间倒序；同一秒按内容 id 倒序 |
| 失效条目 | 占位「内容已失效」，保留进度，不保留封面 / 作者 / 时长 |
| 进度何时可见（`/position`） | **实时**：读的是缓冲（比库里的新），或已落库的值 |
| 进度何时出现在列表（`/list`） | 正常退出**立即**；崩溃 / 断网的会话**最多滞后一个闲置阈值**（本期 60s） |
| 崩溃 / 断网后重进（同一浏览器） | 客户端本地留"还有未落库的进度"标记，重进时**先读服务端再决定要不要补报**（旧设备不能覆盖别处更新的进度）；见 [history-客户端契约](./history-客户端契约.md) §六 |
