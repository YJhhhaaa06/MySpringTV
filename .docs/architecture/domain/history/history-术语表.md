# 播放记录 —— 术语与页面（域内试点）

> 定位（先读这一句）：本表只解决一件事 —— **同一个东西只有一种叫法**。播放记录这套东西
> 一半在页面上、一半在接口上，最容易说不清的是"图 1 那个页面""标签""几次点查"这类**指代**，
> 一旦指代漂移，讨论就会在"我说的是哪个页面"上绕圈。
>
> **本表只服务 `history` 域**，是本仓**术语表的试点**（推广判据见 §五）。
> 讲机制不看本表：设计 [history](./history.md) · 用户规则 [history-需求](./history-需求.md) ·
> 缓冲 [history-上报缓冲](./history-上报缓冲.md) · 客户端 [history-客户端契约](./history-客户端契约.md)。

## 一、页面 ↔ 端点（本域最常被说错的一张表）

| 页面（**正式名**） | 它在代码里 | 会调用的 history 端点 | 频次 |
|---|---|---|---|
| **播放页** | `frontend/src/pages/VideoPage.vue`（左播放器 + 标题 + 评论；旧 SPA 的 `views/detail.js` 已于 2026-10-26 删除） | `GET /api/v1/contents/{id}/progress` | **每次打开** 1 次 |
| | | `POST /api/v1/contents/{id}/play` | **每次打开** 1 次（开始播放时） |
| | | `PUT /api/v1/contents/{id}/progress` | 每 30–60s + 暂停 + 拖动进度 |
| | | `POST /api/v1/history/flush` | 暂停 / 退出 / 切页 |
| **历史记录页**（= 历史页，`history.html`） | `frontend/src/pages/HistoryPage.vue`（按天分组 + 封面进度条 + 失效占位；2026-10-26 交付） | `GET /api/v1/history` | 每次打开 / 翻页 1 次 |
| **详情（数据面）** | `GET /api/v1/contents/{id}` 的返回体 | **无**（只读 `playCount` / `durationSeconds` 两个字段） | — |

★ **一句话记住**：**写与续播只在播放页**（`POST …/play` · `PUT …/progress` · `POST /history/flush`）；
**历史记录页只读一个 `GET /api/v1/history`**，不发任何写。

⚠️ **"详情页"在本仓不是一个独立页面**：只有一个页面既展示内容详情又放播放器。
说"详情"时指**接口 / 数据面**（`GET /api/v1/contents/{id}`，`playCount` 在详情平铺）；
说"播放页"时指**这个页面与它的 history 行为**。两者不能互换着说 —— 混用会直接产生下面 §三 那句错话。

## 二、一物一名（词 → 它到底是什么）

| 术语 | 一句话定义 | 不要叫 |
|---|---|---|
| **播放页** | 放播放器的那个页面，history 唯一的写入来源 | 视频播放页 · 视频页 · 图 1 |
| **历史记录页** | 看"我看过什么"的列表页 | 历史页 · 历史列表页 · 播放历史页 · 图 2 |
| **详情** | 内容详情**接口 / 数据面**，不是页面 | 详情页（当页面讲时） |
| **标签页** | 浏览器的 tab | 标签 · tab（裸用） |
| **一次观看会话** | 从打开播放页到关闭 / 切走；**缓冲与落库的统计单位**（"每次会话 1 次写库"） | 一次播放（≠，见下） |
| **一次播放** | 用户对某内容的**第一次** `/play`；播放量按**人**去重 | 播放次数 |
| **播放量** | `content.play_count`，按人去重、只增，只在详情平铺 | 播放次数 · 播放数（可，但优先"播放量"） |
| **进度** | "看到第几秒"，秒为单位整数 | 位置 · 播放位置（可，但优先"进度"） |
| **续播位置** | `/position` 回答的**已落库**进度（客户端再与本地 pending 取 `max`） | 上次进度（会与本地每秒值混淆） |
| **上报** | 客户端把进度发给服务端（`/report`，**只进缓冲**） | 心跳（心跳=一次 `/report` 请求，**不等于落库**） |
| **缓冲** | Redis 里待落库的进度（`history:report:{userId}` + `history:dirty`） | 缓存（它不是读缓存，`maxmemory` 淘汰会**丢数据**） |
| **落库 / flush** | 把缓冲写进 `watch_history`；`/flush` = 客户端触发，轮询 = 服务端触发 | 上报（上报≠落库） |
| **当天首播** | 该用户对该内容在**某个自然日**的第一次 `/play`（账本 `content_play_dedup` 插进一行；`R-26`） | 第一次观看（会话意义上每次都是"第一次"）· "首播"（会让人以为一生只有一次） |
| **本地 pending** | 客户端 `localStorage` 的 `history:pending:{contentId}`，**每秒更新** | 本地缓存 · 上次上报值（≠） |
| **内容校验读** | `/report` 每趟都要走一次 `loadContentVOs`（判 404/400 + 取时长做 clamp） | 详情查询（它不返回详情） |
| **失效占位** | 列表里内容取不到时返回的占位行（`invalid=true`，保留 `progress`） | 空行 · 默认值 |

★ **两个最容易被当成同义词的东西**：
**"一次播放"是计数单位（一人·一内容·一自然日一次，`R-26`）**，**"一次观看会话"是生命周期单位（一次打开到关闭）**。
同一个人**同一天**看三遍 = **3 个会话、1 次播放**；**跨天**再看就是新的一次播放。凡写"每次播放 1 次写库"都是把这两个搞混了 —— 正确说法是
**"每次观看会话 1 次写库"**。

★ **"标签"在本仓另有含义**：搜索历史的关键词标签（`views/search.js` 的 `.history-tag`）。
所以 history 文档里说浏览器 tab 时一律写 **标签页**，不写"标签"。

## 三、错 → 对（真实踩过的四句）

| 曾经这么说 | 为什么错 | 应该怎么说 |
|---|---|---|
| "**每详情页** 1 次点查" | `/position` 是**播放页初始化**时调的；历史记录页压根不调它。"详情"又是数据面不是页面 | "**每打开一次播放页** 1 次点查"（与历史记录页无关） |
| "两个**标签**同看一个视频" | "标签"在本仓指搜索关键词标签；且原句后半"最后上报的那个标签"更不知所指 | "同一浏览器的**两个标签页**同看一个视频；进度以**最后上报的那个标签页**为准" |
| "**历史页**只有一行" | "历史"单说会与 `watch_history` 的行、与搜索历史混淆 | "**历史记录页**里只有一行" |
| "**播放次数** +1" | 本仓按**人 + 自然日**去重，加 1 的是"今天有多少人看过" | "**播放量** +1（一人一天一次）" |

★ 正式文档里**不写"图 1 / 图 2"**：图号随截图换版就失效，且读者手上没有那张图。
讨论期用图号可以，**落进文档必须换成页面名**。

## 四、写文档时的三条硬规则

1. **一物一名**：第一次出现给全称（"历史记录页"），之后不再换词；不许同段里换着叫。
2. **指代不跨层**：说页面就只谈页面（谁打开、调哪些端点），说接口就只谈接口（入参 / 出参 / 错误码）；
   不许用"详情页调了 `/position`"这种把两层缝在一起的句子。
3. **数字要带单位与主体**："每打开一次播放页 1 次点查"（主体=播放页，单位=一次打开）；
   "每次观看会话 1 次写库"（主体=会话）。**只有数字的句子**（"1 次点查"）在本域等于没说话。

## 五、这个试点怎么推广（判据，不是计划）

只在**同时满足**下面两条的域再建术语表：

1. 该域**已有 ≥2 次**因为"同一个东西两种叫法"导致的返工 / 澄清（本域 = "详情页 vs 播放页"、
   "标签 vs 标签页"、"播放次数 vs 播放量"、"上报 vs 落库"）；
2. 该域的术语**跨文档在用**（域文档、需求篇、客户端契约各写一遍）。

只满足一条 ⇒ 在对应文档里加一节"口径"即可，**不要**新建术语表（多一个文件就是多一处会漂移的地方）。
本表**只登记已发生的歧义**，不做"概念全景"——没有歧义的词不收。
