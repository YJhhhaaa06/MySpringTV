## ［一致性］并发首藏 ⇒ 收藏数短暂偏小（来源：`F-19`，2026-10-12 拍板）

- **What**：计数器未能保持强一致。在极端的"双人同时首次收藏"并发下，后提交的事务会用旧的统计基数覆盖，导致 `favorite_count` 暂时性偏小。
- **Impact**：影响所有展示收藏数的页面与 API。直观现象：数字会少 1，直到下一次有新操作触发自愈；红线提示：如果未来该字段被用于"抽奖、打赏或结算依据"，此问题必须升级为核心 Bug 修复。
- **When**：仅在"两个不同用户、同时、第一次、收藏同一内容"的瞬间发生，属于低概率的偶发边界态。
- **Why & Mitigation**：放弃锁或复杂异步基建。对冲方案：`favorite_count` 的计算方式为重算，当下一次有人收藏 / 取消收藏时就会自愈。

## ［一致性］容量上限是软上限，真并发可瞬时越界（来源：`F-23`，2026-10-14 拍板 / 2026-10-18 转台账）

- **What**：收藏夹的容量上限不是硬上限。"先数一下条数、再插入"是两步操作、不是一个原子动作——真并发下多个请求可以同时通过检查，把夹撑到超限。
- **Impact**：影响全部四条上限：默认夹 5000、自建夹 500、夹数 20、稍后再看 100。直观现象：越界量 ≤ 并发通过检查的请求数（实测口径：19 个夹 + 8 并发 ⇒ 最多 27）；越界后**自限**——此后所有新增一律 400、数字不会继续涨，但也不会自动回落（只能删夹）；越界的夹照常显示、照常打开（读路径不做任何隐藏）。红线提示：一旦出现**真实流量**，或上限被当作"权益 / 计费"依据（要求硬上限），本条必须先被推翻。
- **When**：仅在真并发打满判定点的瞬间；顺序请求无论怎么试都不会越界。本仓没有真实流量 ⇒ 目前是理论边界，不是现实故障。
- **Why & Mitigation**：放弃行锁与计数列两种硬保证——行锁在本域没有干净的锁对象、且有"锁了但不生效且无报错"的陷阱（完整论证见 `FavoriteLimitProperties` 类注释与 [favorite.md §八](./favorite.md)）；计数列要动 schema 并多维护 5 个写点。对冲方案（未来的填坑路径）：届时走"**计数列 + 原子条件 `UPDATE`**"（判定与扣减在一条 UPDATE 里不可分割，coupon `stock` 形态），**不要**上用户行锁；动手前先按 `CURRENT_NEEDS.md` C-6 补耗时基线。

## ［一致性］数据损坏态可收进、列表占位（承 R-11，已拍板接受的边缘态）

- **What**："列表里显示为失效的内容"和"禁止再收藏的内容"不是同一个集合。存在一种数据损坏态：数据库里没标记删除、但内容装载不出来——此时它仍在收藏夹列表里占位显示，却还能被再次收进夹。
- **Impact**：影响面：只有数据损坏行会触发（正常的删除 / 下架走不到这里）。直观现象：夹里挂着一张"内容已失效"占位卡，且这条内容还能被收藏。目前**没有任何 API** 能把内容弄成这个状态 ⇒ 只能由数据事故造成，正常使用不会遇到。红线提示：若该状态变得可以从 API 到达、或常态化出现，必须重新评估。
- **When**：仅当出现"数据库说没删、装载契约却取不到"的损坏行；常态为零。
- **Why & Mitigation**：放弃为这种边缘态单独写处理分支——失效口径统一折叠（"看不了 ≈ 失效"，R-11），为 API 到不了的状态加逻辑不值得。对冲方案：出现该状态时列表照常占位、条目照常可移出，行为可预期。

## ［安全］公开夹端点向匿名者暴露条目 id / 收藏时间（承 T18，能力固有面）

- **What**："点开他人公开夹"的端点向未登录的任何人暴露两样东西：夹内条目的内部 id 与收藏时间；同时拿任意夹 id 去试探，能分辨"这是个公开夹"（存在性可探测）。
- **Impact**：影响面：所有公开夹（任何人、无需登录）。直观现象：能看到条目的收藏时间、能按 id 引用条目；试探一个 id 能确认"存在且公开"。**不泄露内容本体**——失效内容只给占位卡。红线提示：若私密性 / 合规要求升级（例如不允许任何未登录探测），须重新评估。
- **When**：常态存在——这是"公开夹本来就任何人可看"这一能力的固有面，不是漏洞。
- **Why & Mitigation**：放弃对匿名者隐藏 id / 时间与存在性——要藏就只能砍掉"点开公开夹"功能或加登录墙，与需求矛盾。对冲方案：**私密夹与不存在的夹返回同一个 404、同一文案**，"某人的私密夹有哪些"不可探测（[favorite.md §十](./favorite.md)）。
