# ＜域 / 横切面＞已知代价（Known Costs）

> **复制即用**（复制后删掉本段与文末「模板使用说明」注释）：
> - **域** → 复制为 `.docs/architecture/domain/<域>/<域>-已知代价.md`（命名**必须带域前缀**——`doc_refs.py` 按**基名**解析，
>   多个域都叫 `已知代价.md` 会撞名；与 `<域>-需求.md` 同族）；
> - **横切面** → 复制为 `.docs/architecture/tech/<面>/<面>-已知代价.md`（同上必须带前缀；
>   先例 = `tech/security/安全与鉴权-已知代价.md`，2026-10-18 起 `tech/` 按面分目录）；
> - 全文替换 `＜…＞` 占位符；标签定义、登记纪律**原样保留**（它们是规范本体，不是示例）。
>
> **定位**：本域 / 本机制**已拍板接受**的代价台账 —— 每条回答四件事：牺牲了什么（What）/ 影响多大（Impact）/ 什么时候疼（When）/ 为什么接受（Why & Mitigation）。
> **分工**：机制设计与备选方案论证 → 对应设计文档（域 = `＜域＞.md` / 横切 = 对应 tech 文档）；**未处置**的问题池 → `task/FURTHER_ISSUES.md`。
> **只登记已拍板接受的；还在评审的进 FURTHER_ISSUES，不进这里。**
>
> **登记纪律**（防膨胀）：
> ① 一条代价 = 速查表一行 + 正文一节 ≤30 行，四要素各 ≤3 行；
> ② **不新开编号空间** —— 条目靠锚点定位；已有来源编号的保留原编号作**来源标记**，
> 代码引用链 =「代码里的编号 → `FURTHER_ISSUES.md`「已核销」摘要 → 本台账」，不得断链；
> ③ **行文读者视角**：正文先说人话、再给机制细节 —— 新接手的人**不翻源码**就能读懂四要素；
> 机制细节与完整论证留在设计文档 / 代码注释，本台账不复述、只指路；
> ④ **只追加与修订结论，不删行**（历史在 git）；速查表按拍板时间排序；
> ⑤ 标签优先用下方五枚举，枚举不够时可用自定义标签，**首次使用须在标签定义节补一行含义**（防同义词碎片）；
> ⑥ 体量由 `tools/docs/doc_stats.py` 守门（目标全文 ≤150 行）。
>
> **登记流程**：任务收尾 G14 如实登记代价 → 拍板"不修、转已知代价" → 本台账追加一条
> → 设计文档对应处改**一行指针** → FURTHER_ISSUES 行退场（「已核销」一行摘要，含短版推翻条件）。

## 标签定义（优先枚举；自定义标签首次使用时在此补一行）

| 标签 | 含义 |
|---|---|
| ［一致性］ | 牺牲强一致 / 原子性 ⇒ 出现暂时性错值或边界态 |
| ［性能］ | 牺牲延迟 / 吞吐 / 资源占用 |

| ［运维复杂度］ | 新增需维护的机制 / 扩大排查面 |
