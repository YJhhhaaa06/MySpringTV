# 可观测（日志四输出端 / MDC / 脱敏 / 指标 / 审计）

> 定位（先读这一句）：**可观测面是"结构化单行出口 + 机制而非纪律"的一整套**——
> 四个文件输出端分流、每请求一个 `reqId`、脱敏只做出口一处、缓存打点交 Micrometer、审计只在事实之后留痕。
> 本篇只讲**这五件事的形态与接线边界**；鉴权链本身（`JwtAuthFilter` / `@RequiresLogin` / 401/403 语义）
> 不在本篇，去向见文末 [§九 边界与去向](#九边界与去向机制外链)。

---

## 一、四个输出端

`logback-spring.xml` 把日志拆成**四个文件输出端**（另有控制台共用同一条 pattern）。分流靠
**logger `additivity=false`** 这个机制本身，不靠路径过滤——"审计行泄进 system.log"在结构上不可能发生。

| 输出端 | appender | 文件 | 挂载点 | logger | 阈值 | 内容 |
|---|---|---|---|---|---|---|
| system | `SYSTEM` | `system.log` | `root` | 根 logger | INFO+ | 全量应用日志（含里程碑） |
| error | `ERROR` | `error.log` | `root` | 根 logger | **ERROR+**（`ThresholdFilter`） | 排障速览；ERROR 行**同时**留在 `system.log` |
| access | `ACCESS` | `access.log` | 专属 logger | `access` | INFO（固定，`additivity=false`） | 访问日志，每请求一行 |
| audit | `AUDIT` | `audit.log` | 专属 logger | `audit` | INFO（固定，`additivity=false`） | 审计留痕，成功路径 |

- **控制台**（`CONSOLE`）挂 `root`，与原四个文件端共用同一 `STRUCTURED_PATTERN`，但**不指定 charset**
  （沿用 JVM 平台编码，Windows 为 ANSI 代码页——与测试运行器解码约定一致）；四个文件端一律 **UTF-8 显式钉死**。
- 文件端用 `SizeAndTimeBasedRollingPolicy`：`maxFileSize=10MB`、`maxHistory=7`、
  `totalSizeCap=1GB`，归档为 `.gz`；**当前文件恒为固定名**（`system.log` 等，测试与运维都靠它定位）。
- 单行结构化 pattern（`STRUCTURED_PATTERN`，TV `LogFormatter` 的等价物）：
  ```
  ts=%d{yyyy-MM-dd'T'HH:mm:ss.SSSXXX} level=%level logger=%logger%reqid msg=%maskedMsg%nopex%n
  ```
  即 `ts=<ISO 带 3 位毫秒与时区> level=<级别> logger=<logger 名> [req=<16 位 hex> ]msg=<…>`。

> ⚠️ **阈值写死的如实登记**：`access` / `audit` 两个专属 logger 的级别在 `logback-spring.xml`
> 里**硬编码为 `INFO`**；`application.yaml` 的 `logging.level` **只暴露 `root: INFO`**，
> **没有** `logging.level.access` / `logging.level.audit` 这类按 logger 的覆盖键。
> 口径是"审计是合规留痕、不得被运维调级别静默"——这是**有意**的固定，不提供对外开关。

## 二、请求标识：MDC + `%reqid` + 回写 `X-Request-Id`

**载体是 SLF4J MDC，不是自建 ThreadLocal**，于是"把请求标识写进日志"由**日志配置**承担，业务代码零感知。

| 环节 | 实现 |
|---|---|
| 生成 | `RequestIdFilter.newRequestId()`（**唯一源**）：16 位 hex = 毫秒时间戳低 32 位（8）+ 进程标识（4）+ 进程内自增低 16 位（4） |
| 写入 | `MDC.put("reqId", …)`，MDC 键名 `RequestIdFilter.MDC_KEY` |
| 输出 | 转换字 `%reqid`（`RequestIdConverter`）：**有值才输出** ` req=<值>`，无值**整段不出现** |
| 回写 | 响应头 `X-Request-Id`（`RequestIdFilter.HEADER_REQUEST_ID`）——让前端/调用方与后端日志对齐 |
| 清理 | `finally { MDC.remove("reqId") }`，**只清自己那把键**，不用 `MDC.clear()`（避免抹掉将来 tracing 放的值） |

- **为什么用自定义 `%reqid` 而不是内建 `%X{reqId}`**：`%X` 键缺失时输出空串，每条日志都会留一个悬空的
  `req= ` 字段，污染 grep / awk 抽字段、也让"清空后不含 `req=`"这一判据失效。`%reqid` 是"无值即省略字段"。
- **顺序在最外层**：`RequestIdFilter` 为 `HIGHEST_PRECEDENCE`，比 `AccessLogFilter` 与鉴权链都靠外
  ⇒ `reqId` 在**整条链**（含鉴权拒绝、未处理异常）上都可读，否则"最需要 reqId 的异常日志"反而读不到。
- **不读入站 header（有意）**：**无条件新生成**，不看请求里带的 `X-Request-Id`。理由 = 外部值可信性未定义，
  请求方可伪造 `reqId` 污染排查。若将来开放上游透传，**必须**同时补 `RequestIdConverter` 里的脱敏
  （见 §三：它是 pattern 中唯一不经 `%maskedMsg` 的用户可影响字段）。
- **已知边界**：MDC 是**线程本地**的。项目当前无进程内线程池承载请求处理（MQ 消费线程另成链、不带 `reqId`，属预期）；
  将来引入异步处理必须显式传递 `MDC.getCopyOfContextMap()`，否则异步段日志不带 `reqId`。

## 三、脱敏：出口一处（`%maskedMsg`）

脱敏做成日志 pattern 的**出口转换字**，**不做在每个调用点手写**。
`LogMasker` + `SensitiveDataConverter` 定义 `%maskedMsg`，**所有输出端**（控制台 + 四个文件）共用同一条出口
⇒ "忘记脱敏"不再靠纪律，而是结构上不可能发生。

**它输出什么**（`SensitiveDataConverter.convert`）：

1. 渲染后的消息（`{}` 占位符已填充，与 `%msg` 同源）→ **单行化 + 手机号掩码**；
2. 若有异常：换行后接**同样脱敏过的**异常堆栈（`ThrowableProxyUtil.asString`）。

**消息 + 堆栈一起脱敏**是刻意的：PII 进日志不止"消息"一条路——异常消息会被框架回显进堆栈首行
（如 `DataIntegrityViolationException: Duplicate entry '138…' for key 'users.phone'`、
`MethodArgumentTypeMismatchException` 回显被拒参数）。只脱敏消息等于留半扇门。

**两条规则**（`LogMasker`）：

| 规则 | 形态 | 说明 |
|---|---|---|
| 手机号 → `138****1234` | 正则 `(?<!\d)1[3-9]\d{9}(?!\d)` | 匹配 11 位大陆手机号，保留前 3 后 4（可定位、不可还原） |
| 换行 → `\n` 字面量 | CRLF 先处理 | 守住"一条记录一行"不变式，否则结构化解析被切碎 |

- **`%nopex` 必须保留**（隐性契约）：`PatternLayout` 在 pattern 不含异常转换字时会**自动**在行尾追加一份
  完整堆栈；`%maskedMsg` 已自行渲染堆栈 ⇒ 缺 `%nopex` 会得到**两份堆栈**（第二份还是未脱敏的）。
  `LogbackConfigTests` 直接断言 pattern 含 `%reqid` / `%maskedMsg` / `%nopex` 三要素。
- **手机号匹配的边界（如实登记）**：两侧用**数字边界**（`(?<!\d)` / `(?!\d)`）而非词边界 `\b`——
  数字边界既能命中"夹在其它字符里"的真实泄漏形态（如 `For input string: "138…abc"`），
  又**不会**把 12 位以上自增 id 的前 11 位误掩成手机号。**只认连续 11 位**：带分隔符或国际区号的写法
  （`138-0000-9601`、`+8613800001234`）**不命中**；被截断在 11 位中间的号码也不命中。
  本仓当前无调用点产生这两种形态；若要支持，须在 `LogMasker` 扩展，**不在调用点各写一遍**。
- **只按形态识别 PII 手机号**，不识别身份证 / 银行卡 / 邮箱。密码不需要在此脱敏，因为无任何调用点把密码写进日志。

## 四、指标：Micrometer `cache.events{event=…}`

缓存打点 = 单指标 `cache.events`，维度是 tag `event`（`CacheMetrics.METRIC_NAME` / `TAG_EVENT`）。
**打点只加一、不写摘要日志**（旧自研六计数器 + 摘要日志那套随缓存框架一起被裁）——指标本身即可被抓取、聚合、告警。

**六个事件名（逐字）**：

| `event` tag 值 | 含义 |
|---|---|
| `hit_data` | 数据 key 命中且反序列化成功（脏 JSON 归降级） |
| `hit_empty` | 空标记命中 ⇒ 不回源 DB（防穿透生效） |
| `miss` | 两者皆无 ⇒ 回源 |
| `load` | 回源装载（含批量装载） |
| `degrade` | Redis 不可用 / 值不可信 ⇒ 降级查 DB |
| `write_fail` | 缓存写失败 ⇒ 失效让读自愈 |

- **接线点 = 共享三态引擎 `CacheAside`**：`metrics.record(...)` 全部落在该类的读路径与写路径。
- **不加域维度（有意）**：接入点在共享引擎，它不知道自己正被哪个域使用；硬加一个"猜测的域标签"只会给出错的维度。
- **★ 覆盖边界（如实登记，勿当成"全仓缓存都打点了"）**：六事件**只接在 `CacheAside`**（content 域的共享三态引擎）。
  `like` / `follow` / `comment` / `feed` 四域各自实现了自己的三态机（有意未抽公共框架），
  **未逐个接线**。故 `cache.events` 目前**不覆盖**这四个域的缓存路径。
- **失败不得影响业务**：打点只是 `counter(...).increment()`，本身不抛；调用点不 try/catch——
  Micrometer registry 是进程内对象，不存在"打点失败"的正常路径。

## 五、审计：只在"服务调用返回之后"留痕

审计行只在 `audit` 输出端（`additivity=false` + 专属 appender），**不进 `system.log`、也不进控制台**，
阈值固定 `INFO`（见 §一）。

行形态（时间与 `reqId` 由 pattern 前缀提供，不在本行重复）：

```
ts=… level=INFO logger=audit req=6a1b2c3d0f3e0001 msg=action=admin.content.hide operatorId=13 target=contentId:42 result=success
```

**写入位置 = controller 里"服务调用返回之后"**（`AuditLog.success(action, operatorId, target)`）：

```
controller:
  service.xxx(...)            ← 服务方法标 @Transactional，返回即已提交
  AuditLog.success(...)       ← 事实之后才写审计
```

**为什么不能在 service 方法体内**：service 方法在事务中，方法体内写审计会在**提交之前**留下"改过"的记录——
一旦事务**回滚**就变成**假留痕**。审计是合规物，假留痕比没有更坏。
控制器在事务之外 ⇒ "调用返回即已提交" ⇒ 审计行是"事实之后"。
（`AuditLogTests.服务回滚则不产生审计行` 用"让事务在已有成功写之后失败"来鉴别此点：把审计挪进方法体会立刻变红。）

**三条纪律**（勿"顺手优化"）：

1. **只记成功**：失败路径由既有 WARN/ERROR 承载，审计不重复记。
2. **审计是旁路**：写入失败一律**吞掉降级**，绝不影响业务（捕获 `Exception` 而非 `Throwable`）。
3. **不记敏感值**：`target` 只放对象标识（`contentId:42` / `mediaId:7` / `userId:13`），不放变更后的值。

## 六、日志级别口径

| 场景 | 级别 | 结果 |
|---|---|---|
| 成功里程碑（注册 / 登录 / 内容动作） | INFO，**恰好一条** | 落 `system.log` |
| **预期业务拒绝**（业务异常 / 参数校验失败 / 唯一键冲突） | **WARN**，只记结论、**不带堆栈** | **不进 `error.log`** |
| 未预期异常（数据访问异常 / 兜底） | ERROR（带堆栈） | 落 `error.log`（同 req 可串联） |

- **预期拒绝走 WARN 而非 INFO/ERROR**：INFO 会让"正常成功"与"被拒绝"在级别上不可分；
  ERROR 会把可预期输入错误混进 `error.log`、报成运维事故。WARN 恰好是"业务层判断过、无需人工介入"的位置。
  结论行**不带堆栈**（`%maskedMsg` 把堆栈渲染进同一条记录，故用"无内嵌换行 / 无 `\tat `"判定）。
- **access 行的 `code` = 业务码**，与 HTTP `status` **是两个字段**（非冗余）：

  | 场景 | `status` | `code` | 含义 |
  |---|---|---|---|
  | 正常业务请求 | 200 | 200 | 产生了业务信封 |
  | 未登录访问受保护接口 | 401 | 401 | 鉴权过滤器短路，也记了业务码 |
  | 静态资源 / 被短路响应 | 200（或实际） | **0** | **从未产生业务信封** |

  `code=0` 的判据不是"路径像不像静态资源"，而是"**有没有真的产生业务信封**"。
  正常响应的 code 由 `BusinessCodeAdvice`（`ResponseBodyAdvice`，覆写非 `@ResponseBody` 之外的路）写入请求属性
  `AccessLogFilter.ATTR_BUSINESS_CODE`；鉴权短路的 401/403 因**进不了 DispatcherServlet**，
  由 `JwtAuthFilter.writeError` 在**过滤器内**补记同一属性（见 §边界：鉴权链本身不属本篇）。
- **★ 代价（如实登记）**：业务拒绝的**结论行统一由异常出口（`GlobalExceptionHandler`）记录，
  该行不带操作者身份**（只有方法、URI、业务码、消息，没有 `userId`）。
  ⇒ 排查"谁触发的拒绝"要另找 `access.log`（那里的 `userId=` 才有身份）或 `audit.log`。
  这是"错误出口统一"的代价：换取"包装点即源头、无重复记录"。

## 七、测试侧日志捕获：必须在**打日志的那条线程**里渲染

`support/LogCapture` 把**真实的 logback 输出**搬进断言，用的是从 `root.SYSTEM` 输出端取到的
**运行期真实 `PatternLayout`**。关键约束：

> **渲染必须发生在 `ILoggingEvent` 被 `append()` 的那一刻**（在**请求线程**里），
> 不能在事后把事件收进内存、到**测试线程**再渲染。

原因：pattern 里的 `%reqid` 读的是**线程本地 MDC**。真实文件输出端能写出 `req=` 是因为它就在请求线程里渲染；
若事后在测试线程渲染，`%reqid` 读到的是测试线程那把**空 MDC** ⇒ **所有行都不带 `req=`**。
（`LogCapture.RenderingAppender.append` 里即渲染，正是为守住这一点。）

配套约定：

- **分工**：内存 sink 查"内容"（避开 HTTP 响应先于过滤器 `finally` 落盘的毫秒级竞态），
  **真实文件**查"分流"（"access 行没泄进 system.log"只能由读文件证）。
- **两个 `additivity=false` 的 logger 决定了捕获范围**：挂 `root` 的内存 sink **看不到** `access` / `audit` 的事件
  ——这本身就是"里程碑不进 access/audit 输出端"的机制证明。
- **`awaitAccessLine` 轮询**：访问行写在过滤器链 `finally`，响应可能先被客户端读到 ⇒ 断言日志一律轮询、
  错误信息带上全部行（区分"没等到"与"配置没生效"）。

## 八、新代码检查清单

- [ ] **写日志**：用业务类自己的 logger 记**里程碑**（成功 INFO、恰好一条）；预期拒绝交给统一异常出口记 WARN，**不自己另记**。
- [ ] **不手写脱敏**：手机号 / PII 由 `%maskedMsg` 出口统一处理，调用点**不要**自己 `mask`。
- [ ] **不把敏感值写进日志**：请求体 / query 串 / 密码 / token 一律不落盘；审计 `target` 只放对象标识。
- [ ] **审计写在 controller**、服务调用**返回之后**；**不要**写进 service 方法体（事务内写 = 回滚即假留痕）。只在**成功**路径写。
- [ ] **访问行不新增字段**靠 `AccessLogFilter.buildLine`（纯函数，直测）；`code` 缺省 `0` 只表示"从未产生业务信封"。
- [ ] **新增"可能抛未捕获异常的过滤器"**：回到 `AccessLogFilter` 复核 `finally` 里读到的 `status`（异常逃逸时容器才会置 500）。
- [ ] **改 `logback-spring.xml`**（appender / logger / pattern）后**必跑** `LogbackConfigTests`——它是这条隐性契约的守门人。
- [ ] **加缓存打点**：接 `CacheMetrics`；若域自持三态机，注意**本任务未接线**的覆盖边界（见 §四）。
- [ ] **privacy**：若允许上游透传 `X-Request-Id`，必须同时补 `RequestIdConverter` 的脱敏。
