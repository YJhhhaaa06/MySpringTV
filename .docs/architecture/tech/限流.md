# 限流（RateLimit）

> 定位（先读这一句）：限流是"**按记账主体给请求与后台任务记一笔令牌账**"的横切机制 ——
> 两个记账主体（请求 / 任务）、两个桶（**用户桶** per-key / **服务器桶**全局单桶）、一条**非对称扣减**规则。
> **本篇是限流的活事实源**：结论从代码 / 配置取证，随 `T24`–`T29` 逐段长大。
> ⚠️ 本仓**没有真实流量** ⇒ 所有数值都是"拍"的，靠「来源 + 推翻条件」登记，**不靠数值可信**；
> 数值与锚点的正文写在 `application.yaml` 的 `video.rate-limit` 段注释里（改数只动那里 + 配置类）。
> **设计与论证**（为什么这么定、否决了什么）不属本篇：开工期在 [限流设计稿](../../task/限流-设计稿.md)，
> 收口后随 `T29` 按归档 SOP 冻结。

## 一、算法与账本（T24 已落「桶与脚本」；接线语义待 T25）

两个记账主体：**请求**（过闸）与**任务**（不过闸）；两类桶：**用户桶**（per-key：登录 / 匿名各自一套参数）
与**服务器桶**（全局单桶）。命令层落点 = `common/cache/RateLimitRedisOps`——桶参数 / 成本 / 折扣由调用方传入
（本层不注入配置，测试可用小数值直接驱动）。

- **存储**：每桶一个 key（`CacheKeys.rateLimitUser` / `rateLimitAnon` / `rateLimitServer`），
  值 = 紧凑字符串 `"tokens:lastRefillMs"`；TTL = `ceil(capacity / refillPerSec)`（`BucketSpec#ttlSeconds`），
  **写即刷新**：用户桶每访必刷（放行 / 被拒都写——TTL 自证性质的反推前提）；服务器桶随放行 / 任务扣减
  （被拒时一个字节都不写、也就无从刷新——其淘汰按自证性质无损）。
- ★ **非对称扣减**（一次 Lua 两阶段，`RateLimitRedisOps#tryAcquire`）：用户桶**无条件扣询问费**
  （被拒也扣——防免费探路）；服务器桶**只在放行时扣**（被拒时一个字节都不写回）。
  放行 = `user.tokens ≥ cost × (1 − rejectDiscount)` 且 `server.tokens ≥ cost`；
  放行再扣"尾款"与服务器桶；被拒返回 `Retry-After`（秒，向上取整）= 两桶"补到可过闸"所需时间的**较大者**
  （已够的一侧计 0）——⚠️ 补足目标两桶都是 `cost`（用户桶**不是** `cost × (1 − rejectDiscount)`：
  下次进入闸门前还会再扣一次询问费），这是 `T24` 审查修正钉住的一处口径。
- **惰性补充，无定时任务**：脚本内 `min(cap, tokens + elapsed × rate)`，时钟 = Redis 服务端 `TIME`
  （与 TTL 淘汰同一时钟源）。两条纪律：① 任何一次写"先补后改"、更新 `lastRefillMs`；
  ② 任务侧 `#deductTaskCost`（无条件、可为负、不碰用户桶）同样先补后扣。
- ★ **TTL 自证边界的精确表述**（T24 复核，登记 `I-18`）：对 `tokens ≥ 0` 的桶淘汰无损；
  对 `tokens < 0`（欠账态）的桶，淘汰会**豁免剩余欠账**（首版参数恰整除；语义 = "沉默满桶时间后重新做人"，
  持续活跃的刷子不受影响）。
- **失败边界（本层不 catch）**：Redis 不可达 ⇒ `CacheUnavailableException`（fail-open 归 T25）；
  返回值解析失败 ⇒ `RateLimitScriptException`（**故意不归一**——T28 靠类型把"Redis 挂了（WARN）"与
  "脚本 / 解析异常（ERROR）"在日志上分档）。

## 二、配置与参数（结构已落地，值不在此处）

讲什么：`video.rate-limit` 的键路径与配置字段的对应、绑定期校验的**四条口径**
（为正 / 权重表键形态 / `miss-multiplier ≥ 1` / `reject-discount ∈ [0,1]`）、以及环境变量覆盖面。

★ **一条必须知道的事实**：`cost.base` 的键在 YAML 里**必须**用方括号括起来
（`"[POST /favorite/add]": 3`）—— Spring 绑 `Map` 时会把键里"小写字母数字与 `-` 之外"的字符
**静默删掉**（漏写则 `POST /favorite/add` 变成 `POSTfavoriteadd`，无报错、权重永远命不中）。
实测记录与理由在 `application.yaml` 该段注释 + `RateLimitProperties` 类注释；配置类把键形态钉成
**绑定期校验** ⇒ 漏写方括号是**启动失败**而不是静默放行。

⚠️ 未经环境变量暴露的只有 `cost.base`（键含空格，环境变量名无法表达）：要覆盖它在测试里用
`@TestPropertySource(properties = "video.rate-limit.cost.base.[POST /x]=2")`。

★ **另一条实测事实（它推翻了本仓原有的一条说法）**：把 `server` / `user{authed,anon}` / `cost`
声明为**一个 record 里的嵌套 record 字段**是**能绑**的（Boot 4.1.1 实测：`Binder` 直绑与真实
`@ConfigurationProperties` 两条路径都绑上、层层非 `null`）⇒ `application.yaml` feed 段
"record 只认本前缀下的扁平键、嵌套会被静默忽略并绑成 0"的说法**不成立**。
该偏差登记为 `I-15`（属 feed 域的注释，不在本专项范围内修改）。
