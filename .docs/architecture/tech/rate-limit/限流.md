# 限流（RateLimit）

> 定位（先读这一句）：限流是"**按记账主体给请求与后台任务记一笔令牌账**"的横切机制 ——
> 两个记账主体（请求 / 任务）、两个桶（**用户桶** per-key / **服务器桶**全局单桶）、一条**非对称扣减**规则。
> **本篇是限流的活事实源**：结论从代码 / 配置取证。`T23`–`T29` 已于 **2026-10-17 收口**，

> 数值与锚点的正文写在 `application.yaml` 的 `video.rate-limit` 段注释里（改数只动那里 + 配置类）。

## 一、算法与账本

两个记账主体：**请求**（过闸）与**任务**（不过闸）；两类桶：**用户桶**（per-key：登录 / 匿名各自一套参数）
与**服务器桶**（全局单桶）。命令层落点 = `common/cache/RateLimitRedisOps`——桶参数 / 成本 / 折扣由调用方传入
（本层不注入配置，测试可用小数值直接驱动）。

- **存储**：每桶一个 key（`CacheKeys.rateLimitUser` / `rateLimitAnon` / `rateLimitServer`），
  值 = 紧凑字符串 `"tokens:lastRefillMs"`；TTL = `ceil(capacity / refillPerSec)`（`BucketSpec#ttlSeconds`），
  **写即刷新**：用户桶每访必刷（放行 / 被拒都写——TTL 自证性质的反推前提）；服务器桶随放行 / 任务扣减
  （被拒时一个字节都不写、也就无从刷新——其淘汰按自证性质无损）。
- ★ **非对称扣减**（一次 Lua 两阶段，`RateLimitRedisOps#tryAcquire`）：用户桶**无条件扣询问费**
  （被拒也扣——防免费探路）；服务器桶**只在放行时扣**（被拒时一个字节都不写回）。
  放行 = `user.tokens ≥ cost × (1 − rejectDiscount)` 且 `server.tokens ≥ cost`；
  放行再扣"尾款"与服务器桶；被拒返回 `Retry-After`（秒，向上取整）= 两桶"补到可过闸"所需时间的**较大者**
  （已够的一侧计 0）——⚠️ 补足目标两桶都是 `cost`（用户桶**不是** `cost × (1 − rejectDiscount)`：
  下次进入闸门前还会再扣一次询问费），这是 `T24` 审查修正钉住的一处口径。
- **惰性补充，无定时任务**：脚本内 `min(cap, tokens + elapsed × rate)`，时钟 = Redis 服务端 `TIME`
  （与 TTL 淘汰同一时钟源）。两条纪律：① 任何一次写"先补后改"、更新 `lastRefillMs`；
  ② 任务侧 `#deductTaskCost`（无条件、可为负、不碰用户桶）同样先补后扣。
- ★ **TTL 自证边界的精确表述**（T24 复核，登记 `I-18`）：对 `tokens ≥ 0` 的桶淘汰无损；
  对 `tokens < 0`（欠账态）的桶，淘汰会**豁免剩余欠账**（首版参数恰整除；语义 = "沉默满桶时间后重新做人"，
  持续活跃的刷子不受影响）。
- **失败边界（本层不 catch）**：Redis 不可达 ⇒ `CacheUnavailableException`（fail-open 归 §三 的过滤器）；
  返回值解析失败 ⇒ `RateLimitScriptException`（**故意不归一**——日志侧才能按类型把"Redis 挂了（WARN）"与
  "脚本 / 解析异常（ERROR）"分档）。
- **返回值形态（T28 起四段）**：`allowed:retrySeconds:uPass:sPass`。后两段是**逐桶判定**
  （`Decision#userBucketPassed` / `#serverBucketPassed`），供可观测面按 `scope` 分开计数（§五）；
  ⚠️ 形态不合法（段数不对 / 标志位非 `0|1`）**或语义矛盾**（`allowed ≠ uPass && sPass`）⇒
  `RateLimitScriptException`——**不做宽松容错**，"差一位就静默当成放行"与"矛盾值被静默接受"
  是本机制最危险的两种失败形态（登记 `I-21`）。

## 二、配置与参数（结构在此，值在 `application.yaml`）

讲什么：`video.rate-limit` 的键路径与配置字段的对应、绑定期校验的**四条口径**
（为正 / 权重表键形态 / `miss-multiplier ≥ 1` / `reject-discount ∈ [0,1]`）、以及环境变量覆盖面。

★ **一条必须知道的事实**：`cost.base` 的键在 YAML 里**必须**用方括号括起来
（`"[POST /favorite/add]": 3`）—— Spring 绑 `Map` 时会把键里"小写字母数字与 `-` 之外"的字符
**静默删掉**（漏写则 `POST /favorite/add` 变成 `POSTfavoriteadd`，无报错、权重永远命不中）。
实测记录与理由在 `application.yaml` 该段注释 + `RateLimitProperties` 类注释；配置类把键形态钉成
**绑定期校验** ⇒ 漏写方括号是**启动失败**而不是静默放行。

⚠️ 未经环境变量暴露的只有 `cost.base`（键含空格，环境变量名无法表达）：要覆盖它在测试里用
`@TestPropertySource(properties = "video.rate-limit.cost.base.[POST /x]=2")`。

★ **另一条实测事实（它推翻了本仓原有的一条说法）**：把 `server` / `user{authed,anon}` / `cost`
声明为**一个 record 里的嵌套 record 字段**是**能绑**的（Boot 4.1.1 实测：`Binder` 直绑与真实
`@ConfigurationProperties` 两条路径都绑上、层层非 `null`）⇒ `application.yaml` feed 段
"record 只认本前缀下的扁平键、嵌套会被静默忽略并绑成 0"的说法**不成立**。
该偏差登记为 `I-15`（属 feed 域的注释，不在本专项范围内修改）。

## 三、接线与覆盖范围

**链序（全部显式 `@Order`，同步 [安全与鉴权](../security/安全与鉴权.md) §2.1）**：
`RequestIdFilter`（MIN）→ `AccessLogFilter`（MIN+1）→ Security 链（默认 −100）→
`JwtAuthFilter`（`AUTH_FILTER_ORDER = 0`）→ `RateLimitFilter`（`AUTH_FILTER_ORDER + 10`）→ `DispatcherServlet`。
拍板 A「先鉴权后扣费」：401/403 在鉴权层短路 ⇒ 被拒绝的请求到不了限流器、**不浪费令牌**；
`RateLimitFilter` 的序号取 `AUTH_FILTER_ORDER + 10`——把"限流器在鉴权之内侧"钉进常量本身。
★ 链序的行为级实测证明在测试里：`被拒429的访问行code429`（限流器若不在
`AccessLogFilter` 内侧，429 就没有访问行）＋ `未登录访问受保护接口不耗令牌`（限流器若挪到
鉴权外侧，401 也会扣桶）。

**覆盖范围（`RateLimitFilter`）**：除跳过清单外**全部过闸**——含匿名读接口、未映射路径
（扫描流；本仓当前对其响应 500 = `NoResourceFoundException` 落 catch-all 的既有行为，
与本专项无关）、`/api/admin`（**无白名单**，管理员请求同样过闸）。跳过清单 = 精确
`/`、`/index.html`、`/favicon.ico` ＋ 前缀 `/static/`、`/actuator/`、`/upload/`——
静态资源不是业务成本；⚠️ `/upload/`（`WebMvcConfig` 的静态媒体服务）是设计稿 §七
清单之外**执行期补上**的（同一口径，登记 `I-19`；业务上传是 `POST /api/upload/*`，零交集）。
⚠️ 跳过前缀取**未解码未规范化**的 `getRequestURI()`，规范化绕过由 Spring Security 默认
`StrictHttpFirewall`（排在其前）拒绝 `..`/`//` 兜住——属潜伏边界声明（**若推翻 F-01/F-02 的"不迁 Security"决定**时重估）。

**429 出口**：与 `JwtAuthFilter#writeError` 同款——自写 `ApiResponse`（429「请求过于频繁」）＋
补记 `AccessLogFilter.ATTR_BUSINESS_CODE`（否则访问行 `code=0`，三态塌两态）＋
`Retry-After` 响应头（秒，向上取整；放行路径不写此头）。

**fail-open（两种失败都放行，日志分两档）**：`CacheUnavailableException`（Redis 不可达 /
熔断打开——`guarded` 快速失败抛的也是它）⇒ 放行（WARN）；`RateLimitScriptException`
（限流器**自身缺陷**）⇒ **同样放行**（500 等于让限流器成为整个 API 的单点故障，违背 D-5），
但日志 ERROR——"限流静默消失"的唯一出口。行为契约由
`RateLimitFailOpenTests`（resilience 组）钉住；**日志三档与指标见 §五**。

**测试基线对冲（D-3）**：集成测试的匿名请求 IP 全是 `127.0.0.1` ⇒ 匿名桶在测试环境退化为
全局限流。对策 = `AbstractIntegrationTest` 用 `@TestPropertySource` 内联属性把桶参数整体调大
（10^6）；限流自身的契约测试（`RateLimitFilterContractTests`）用子类 `@TestPropertySource`
小参数覆盖（cap=4 / rate=1 / cost=1 / discount=0.3）并带**守门用例**（覆盖失效 ⇒ 全类假绿）。
★ 实测发现：子类 `@DynamicPropertySource` **不能**覆盖父类同键值（父类源胜出）——
这也是守门用例存在的原因。

## 四、成本信号（① 端点权重 / ② 缓存 miss / ③ 任务成本）

### ① 端点权重表（静态，`RateLimitFilter#costOf`）

- **表** = `application.yaml` 的 `video.rate-limit.cost.base`——**全部非 GET 端点都登记**（38 个）：
  登录 / 注册 5；上传与媒体扫描 / 恢复（同为"重活"）10；其余写路径 3。
  **读一律吃 `default-base = 1`**（不枚举读端点）。
- **查表**：键 = 「方法 空格 路径」**精确匹配**（本仓端点无路径参数；将来出现路径变量再扩，
  推翻条件已登记）；路径与跳过清单**同源**（`#pathOf`，未解码未规范化）。未登记 ⇒ `default-base`
  （★ 不是 0——"漏配 = 不限"正是要防的）。
- **完整性**：`RateLimitWeightTableTests#完整性_全部非GET端点都已登记` 扫描全部 handler 映射——
  新增端点漏配 ⇒ 用例变红（逼一次定价决策）；用例含扫描面 sanity 下界（防 introspection 失效假绿）。

### ② 缓存 miss 系数（运行期信号）

- ★ **两阶段（时序决定的形态）**："miss" 是**本请求运行期事实**（缓存读在请求处理中、门之后）
  ⇒ 门时取不到：**门时按 `base` 扣 → 请求收尾按差额 `base × (multiplier − 1)` 补扣**
  （`RateLimitFilter#settleMissPenalty` ＋ `RateLimitRedisOps#deductDelta`）。仅对 **"门放行过"** 的
  请求（429 短路不补、fail-open 不补）；**用户桶 + 服务器桶同扣**、无折扣、可为负（D-6）。
- **二值不计数**：`CacheMissSignal`（静态 `ThreadLocal` 布尔：`mark` / `consume` / `clear`）——
  任一回源乘一次。不计数：次数 → 系数是无依据的换算函数、且冷启动 / 深翻会 ×(3n) 误伤
  （已否决记录 + 升级路径见设计稿 §12.2）。
- **接线口径**："**凡没走成缓存的读都算**"——miss / 降级 / 脏值 / 部分态兜底 / 缺省全量；
  六类缓存 + 内容索引懒重建共 **41 个回源点**（CacheAside 5、Like 6、Follow 13、Favorite 6、Feed 4、
  Comment 6、内容索引懒重建 1）；**新增回源点必须一起接线**（漏一处 = 该路径在信号②里静默消失，
  属保守方向的漏记）。
- **读写点唯一**：进闸门 `clear()`、收尾 `consume()`（"唯一 set/clear 点"纪律，同 `RequestIdFilter`
  对 MDC）；**线程封闭**（MQ 消费 / 去抖线程天然不带——红线"回传机制不得泄漏到别的线程"）。
- **失败口径**：补扣跑在 `finally`（响应已在途 / 已写出）⇒ **任何失败都不得让请求变 500**：
  Redis 不可达 WARN / 脚本异常 ERROR / 其余兜底 ERROR（对照 `FeedCache.tryAcquireRebuildLock` 的
  `RuntimeException` 兜底手法）；行为由 `resilience` 组的"补扣失败不影响响应"用例钉住。
- **开关**：`miss-multiplier = 1.0` 即关闭（沿用"0/1 = 关闭"惯例；1.0 连一次往返都不花）。
  `application.yaml` **已启用 3.0**（锚点"miss 一次 ≈ 三次命中"；T26 裁决 `I-16`）。

### ③ 任务成本

- **落点与扣减点**：`FeedRebuildService.rebuildInbox` —— **重建锁成功之后、真正重建之前**
  调 `RateLimitRedisOps#deductTaskCost`（无条件、可为负、不碰任何用户桶）。锁跳过（并发去重 /
  Redis 不可用降级）= 没干活 = 不扣，**谁干活谁付费**；重复执行（跨去抖窗口的重复消息）= 重复计费，
  每次都真干了活，属想要的语义（消费容器的本地重试只发生在"载荷非法"出口，**到不了**扣减点——
  `rebuildInbox` 契约"任何失败都不抛出"）。DB 失败不退钱：计费点在重建步骤之前，"试图干活"即扣。
- ★ **立规**：新增昂贵后台任务（如将来的评论热度表重建）一律在**执行处**接同一扣减入口
  `RateLimitRedisOps#deductTaskCost`，不要另起炉灶（`FeedRebuildService` 是范例实现）。
- **独立失败边界（红线）**：扣减失败**不得让任务失败**（fail-open，对齐 §三 过滤器的两败都放行）——
  调用自带 catch（Redis 不可达 WARN；`RuntimeException` 兜底防御性），**不依赖**重建主 try 的兜底
  （主兜底会中止重建步骤，语义就成了"扣减失败让任务失败"）。
- **演进方向（登记，暂不做）**：去抖合并后把任务成本**分摊给触发用户**（用户桶）——
  当前任务成本不属于任何用户，只记服务器桶；分摊需要跨层回传触发者集合，等真实需要再论证。
- **测试**：默认组 `FeedRebuildCostTests`（重建 ⇒ 服务器桶精确 −`task-cost` / 用户桶字节级不变 /
  锁跳过不扣 / DB 失败仍计费）；resilience 组 `FeedRebuildCostFailOpenTests`（扣减失败 ⇒
  重建照常，反向验证 = 删独立 catch 必红）。⚠️ 任务自付费接线后，**凡断言桶绝对值的测试类
  必须 `auto-startup=false`**（异步重建的扣减会污染夹具设值与断言之间的桶状态）——
  T27 起该开关覆盖**全部 6 个**桶断言测试类：4 个小桶限流类 + `RateLimitFailOpenTests`
  + `RateLimitRedisOpsTests`（C4 审查修正补齐，规则无一例外）。

## 五、可观测

**指标**（`common/web/RateLimitMetrics`；名字与维度取值的唯一源 = 该类的常量）：

| 指标 | 维度 | 含义 |
|---|---|---|
| `rate.limit.decisions` | `scope=user|server`、`result=allowed|rejected` | **逐桶**判定计数 |
| `rate.limit.acquire` | 无 | 一次过闸命令（一次 Lua 往返）的耗时 = "限流器自身耗时" |

- ★ **一次请求记两条决策样本**：两桶判定可以不同（用户桶够、服务器桶不够）⇒ 运维要回答的是
  "**该扩服务器还是该管这个用户**"，并成一条就答不了。⚠️ 由此而来的一条读法：
  `sum(result="rejected")` 是**桶级**失败数、**不是**请求数。
- `scope` 的真值来自脚本带出的逐桶判定（返回值 `allowed:retry:uPass:sPass`，登记 `I-21`）——
  不是由调用方猜的（"猜出来的维度比没有维度更坏"，同 `CacheMetrics` 的取向）。
- **fail-open 不记决策指标、也不采样耗时**：判都没判出来，记什么都是假的；
  耗时若把 Jedis 超时样本算进来，会把"Redis 挂了"读成"限流器变慢"。
- 抓取：`/actuator/metrics/rate.limit.decisions?tag=scope:user&tag=result:rejected`（`metrics` 端点已暴露）。
- ⚠️ **刻意不做**：`rate.limit.failopen{reason=…}` 计数——设计稿 §十 没有这一族，fail-open 的出口
  按设计稿只有日志（本仓无监控消费方，日志才是唯一会被看到的出口）。2026-10-17 用户拍板不加。

**日志三档**（`RateLimitFilter`；档位对齐 [可观测](../observability/可观测.md) §六"预期业务拒绝 ⇒ WARN 结论行"）：

| 场景 | 档位 | 持栈 | 行内字段 |
|---|---|---|---|
| 拒绝（429） | WARN | 否 | `path` / `userId`（匿名 `-`）/ `cost` / `blockedBy=user\|server\|both` / `retryAfter` |
| Redis 不可达 / 熔断打开（放行） | WARN | 否 | `path` / `userId` / `原因` |
| **脚本 / 返回值解析异常**（放行） | **ERROR** | 是（这是缺陷，要能定位） | `path` / `userId` / 栈 |

- ★ 前两档同为 WARN，靠**用词**区分（"限流拒绝" vs "限流器不可用"），第三档靠**级别**。
  三档若合并，"限流器自己坏了"会被 fail-open 伪装成"Redis 挂了"⇒ **限流消失而无人知**
  （设计稿 §六 兜底②）。判别力由 `RateLimitFailOpenObservabilityTests`（resilience 组）钉住。
- ★ **不落原始 key**：登录记 `userId`，匿名**不落 IP**——不是"落了再脱敏"，是**根本不传**。
  若将来要记 IP，必须先扩 `LogMasker`（[可观测](../observability/可观测.md) §三 的脱敏面只认手机号），
  **不在调用点各写一遍**。
- ⚠️ **已知代价**：429 是**请求级**日志 ⇒ 刷子场景会按请求放大 `system.log`。
  接受它（拒绝是业务层判断过的结论，静默更坏）；第一条退路 = 按 key 节流，本期不做。
- ⚠️ WARN 行的 `原因=` 是**异常文案**（诊断用）：真实连接失败时可能带 **Redis 端点**（`host:port`）——
  那是基础设施地址、**不是**用户 PII，不在"匿名不落 IP"的口径内；客户端 IP 与 bucket key 仍然
  一个字节都不落。若将来要求"连端点也不落"，只能在 `RedisOps.guarded` 收口改写文案（不在调用点各写一遍）。

**故障注入（`resilience` 组）**：

| 类 | 钉住什么 |
|---|---|
| `RateLimitFailOpenTests` | 两种失败都放行、不 500（T25 的行为契约） |
| `RateLimitFailOpenObservabilityTests` | 两档可区分（WARN 不持栈 / ERROR 带栈）、fail-open 零决策样本 |
| `RateLimitBreakerTests` | 熔断打开 ⇒ 过闸**一次 Redis 都不访问**（快速失败，不是每请求再撞一次超时） |

### 6.3 夹具前提

MockMvc 的匿名请求 IP 全是 `127.0.0.1` ⇒ 匿名桶在该环境下**退化成全局限流**（D-3）。对冲 =
`AbstractIntegrationTest` 用 `@TestPropertySource` **内联属性**把三套桶参数整体调到 10^6；限流自身的契约
测试再用子类 `@TestPropertySource` 覆盖成小参数（cap=4 / rate=1 / cost=1 / discount=0.3），并配**守门用例**
（覆盖失效 ⇒ 全类假绿）。

★ 两条实测（属性通道的优先级不能靠猜）：① 内联属性的优先级规则 = **父类先、子类后、同键子类胜**；
② 子类 `@DynamicPropertySource` **覆盖不了**父类同键值（父类源胜出）——这正是守门用例存在的原因。

### 6.4 已知代价（D-1 ~ D-8）

| # | 一句话 | 边界 / 推翻条件 | 论证 |
|---|---|---|---|
| D-1 | 数值全是拍的（无真实流量） | 有真实行为分布或压测基线 ⇒ 重定价 | [§12.1](../../../archive/rate-limit-2026-10-17/限流-设计稿.md) |
| D-2 | 后台任务忙 ⇒ 前台更容易被限（"服务器确实忙"的诚实信号） | 任务与请求共用服务器桶；推翻 = 分桶记账 | [§12.1](../../../archive/rate-limit-2026-10-17/限流-设计稿.md) |
| D-3 | 测试 / 压测环境匿名桶退化成全局限流（MockMvc IP 全同） | 用测试覆盖阈值对冲（§6.3）；推翻 = 用例能拿到独立 IP | [§12.1](../../../archive/rate-limit-2026-10-17/限流-设计稿.md) |
| D-4 | Redis 从"可降级加速器"变成关键路径依赖 | 对冲 = fail-open + `RedisOps.guarded` 既有熔断；推翻 = 改本地桶 | [§12.1](../../../archive/rate-limit-2026-10-17/限流-设计稿.md) |
| D-5 | fail-open 期间等于没有限流 | 可用性优先（本仓既有口径"缓存不可用不许 500"）；推翻 = 合规要求 fail-closed | [§12.1](../../../archive/rate-limit-2026-10-17/限流-设计稿.md) |
| D-6 | 服务器桶可为负（欠账要靠恢复补回来） | 后台密集期会延长前台拒绝窗口；推翻 = 给欠账封底 | [§12.1](../../../archive/rate-limit-2026-10-17/限流-设计稿.md) |
| D-7 | 反代 / NAT / 校园网下 IP 语义未处理 | 本仓尚无反代；推翻 = 上反代 / 网关 ⇒ 先定信任边界再改取法 | [§12.1](../../../archive/rate-limit-2026-10-17/限流-设计稿.md) |
| D-8 | **未鉴权流量完全绕过限流器**（`JwtAuthFilter` 在 `RateLimitFilter` 之前 ⇒ 401 / 403 一个桶都不扣） | **不改链序**（推翻拍板 A 的代价更大）；推翻 = 上反代 / 网关、出现真实 401 洪水、或做"鉴权前通用桶" | [§12.1](../../../archive/rate-limit-2026-10-17/限流-设计稿.md) |

### 6.5 刻意不做

- `rate.limit.failopen{reason}` 计数：fail-open 的出口只有日志（2026-10-17 拍板）——已在 §五 写过，此处只留指针。
- **不提供全局开关**：关闭限流 = 把桶参数调大（环境变量）后重启；不引入 `enabled` 开关，避免
  "配置里的数值 vs 开关状态"两个事实源互相矛盾。
- **不按 key 节流 429 日志**：第一条退路已登记在 §五 的已知代价里（拒绝是业务结论，静默更坏）。
