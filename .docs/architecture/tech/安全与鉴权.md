# 安全与鉴权

> 定位（先读这一句）：本仓的鉴权由**自研** `JwtAuthFilter` + `@RequiresLogin` + `@CurrentUserId` 承担，
> **Spring Security 尚未接管**（`SecurityPassthroughConfig` 是临时放行态）。
> 本篇只讲**请求鉴权链形态、端点鉴权声明、管理员判定、401/403 语义、JWT 口径、待迁边界**；
> 脱敏口径（token / 手机号不落日志）去 [可观测](./可观测.md)，
> `common` 边界与窄端口去 [模块边界与依赖](./模块边界与依赖.md)
> ——本篇对二者**只写一句话边界 + 链接**，不复制。
> 文末 [§八 边界与去向](#八边界与去向机制外链) 列全部外链。

## 一、现状一句话

**自研三件套**：`common.security.JwtAuthFilter`（过滤器）+ `@RequiresLogin`（端点声明「需登录」）
+ `@CurrentUserId`（把登录用户 id 注入控制器参数）。三者都在 `common`，不依赖任何业务域。

**Spring Security 尚未接管**：项目引入了 `spring-boot-starter-security`（为用其 BCrypt），
但鉴权**不**走它的过滤器链。`common.config.SecurityPassthroughConfig` 提供一条
`anyRequest().permitAll()` 的链，**仅用于替换 Security 的默认保护链**（默认链会把一切拦成 401），
把鉴权交还给 `JwtAuthFilter`。该类注释明确标注：

> ⚠️ 这是临时状态，接入决策③时必须删掉；在那之前本类保证"能跑"但不提供任何 Security 层保护
> ——**不要再往这里加规则**，授权规则的唯一事实源是 `@RequiresLogin`。

```java
// SecurityPassthroughConfig#passthroughFilterChain（现态）
http.csrf(csrf -> csrf.disable())
    .httpBasic(basic -> basic.disable())
    .formLogin(form -> form.disable())
    .authorizeHttpRequests(auth -> auth.anyRequest().permitAll());
```

## 二、请求鉴权链

### 2.1 过滤链顺序（从外到内）

链路顺序由各过滤器类注释与 `@Order` 共同确定：

```
请求
 └─ RequestIdFilter        @Order(HIGHEST_PRECEDENCE)        ← 唯一 set/clear reqId（MDC）
     └─ AccessLogFilter    @Order(HIGHEST_PRECEDENCE + 1)    ← 包住其后全部，含鉴权短路响应
         └─ Security 链（SecurityPassthroughConfig，permitAll）  ← 排在本项目自研过滤器之前
             └─ JwtAuthFilter  OncePerRequestFilter @Component（未标 @Order ⇒ 最低优先级）
                 └─ DispatcherServlet → 控制器 / 参数解析器
```

两条来自类注释的事实锚点：

- `RequestIdFilter` 注释：本类是**唯一**的 set/clear 点，顺序为 `HIGHEST_PRECEDENCE`
  （"比 `AccessLogFilter` 与 Spring Security 链都靠外"）。
- `AccessLogFilter` 注释：紧贴 `RequestIdFilter` 之内（`HIGHEST_PRECEDENCE + 1`），
  "仍包住 Spring Security 链与 `JwtAuthFilter`"——故 401/403 这类**被过滤器短路**的请求同样有访问日志。

> `JwtAuthFilter` **没有** `@Order`，即排在 Security 链之后；`SecurityPassthroughConfig` 注释也点明
> Security 默认链"排在自研过滤器之前"（这正是当初必须放行它的原因）。

### 2.2 `JwtAuthFilter.doFilterInternal` 三段（**顺序不可交换**）

```java
① boolean loginRequired = requiresLogin(request);          // 读 @RequiresLogin
   解析 Authorization: Bearer …
       有 token 且校验通过 → request.setAttribute("userId", userId)
       有 token 但非法/过期 → 仅当 loginRequired 才 401 短路，否则记 debug 按匿名放行
② loginRequired && userId == null            ⇒ 401（UNAUTHORIZED「请先登录」）短路
③ isAdminPath（/api/admin 前缀）
       && (userId == null || !adminChecker.isAdmin(userId))
                                             ⇒ 403（FORBIDDEN「无权访问」）短路
   ↓ 都通过
   chain.doFilter(...)
```

关键点：

- **令牌"存在即校验"**，与端点是否需要登录**无关**：为将来 `@CurrentUserId` 可选注入留口。
- **公开端点收到坏 token ⇒ 按匿名处理**（不写请求属性、不阻断），避免因坏 token 误杀公开接口。
- `requiresLogin(request)` 委托给 `RequestMappingLookup`（见 §2.3）。

### 2.3 `requiresLogin` 的判定（`RequestMappingLookup`）

单点判定「该请求的目标处理器是否打了 `@RequiresLogin`」：

1. 用 `@Qualifier("requestMappingHandlerMapping")` 调 `getHandler(request)`，拿到
   `HandlerExecutionChain`，**解开**后取 `HandlerMethod`（`AbstractHandlerMapping` 的结果会缓存在
   请求属性上，DispatcherServlet 随后的同路径查找是幂等的）。
2. 判定式 = `handler.hasMethodAnnotation(RequiresLogin.class)`
   **||** `handler.getBeanType().isAnnotationPresent(RequiresLogin.class)`。
3. **未映射的路径返回 `false`**——真正的 404 交 DispatcherServlet，本机制不越权处理路由语义。
4. 本 bean **只注入 `JwtAuthFilter`**（不注册为 `Filter` / `WebMvcConfigurer`），
   以避免与 `HandlerMappingIntrospector` 的早期初始化产生循环依赖。

> ⚠️ **一次曾"完全失效"的修复（代码留痕）**：原实现直接对 `getHandler` 的返回值做
> `instanceof HandlerMethod`，而它返回的是 `HandlerExecutionChain` ⇒ 判定**恒 false** ⇒
> `@RequiresLogin` **从未生效**。长期未被发现，是因为所有受保护端点**恰好都用了
> `@CurrentUserId`**（那个解析器取不到 userId 会抛 401），于是"401 看起来是对的"——
> 直到出现首个"标了 `@RequiresLogin` 但不接收 userId"的端点（`/like/content/count`）才暴露：
> 它无 token 时返回了 **200**。回归网 = `SecurityContractTests`（直接断言机制本身）+ HTTP 级
> `LikeFlowTests.未登录全部401`。

### 2.4 类级 vs 方法级：怎么选（取舍）

`@RequiresLogin` 的 `@Target` 是 `{METHOD, TYPE}`：标**类**上 = 该 Controller 全部端点需登录。

| 写法 | 对应 TV `AuthFilter` 语义 | 本仓实证用例 | 为什么这么选 |
|---|---|---|---|
| **类级** | 前缀保护（整族） | `LikeController`（`/like`）、`FollowController`（`/follow`）、`FeedController`（`/feed`）、`AdminContentController` / `AdminCommentController` / `MediaAdminController`（`/api/admin/**`）、upload（`/api/upload/**`） | 把"这一族整体受保护"写在一处，**新增子路径自动覆盖**、比逐方法标更难漏 |
| **方法级** | 精确保护（个别端点） | `UserController`（`changePassword` / `changeUserName` / `me`）、content 写端点、comment 写端点（`/comment/add`、`/comment/delete`） | 这些域名下**同时存在公开端点**；用类级会把将来/现有的公开端点**误拦** |

判据归根：**类级适合"整族无公开端点"的域；含公开端点的域必须用方法级。**
（`SecurityContractTests` 固化了这两个方向——既有"类级覆盖全部端点"的断言，也有
"公开端点不得被判为需登录"的反向断言，防止"整个 `/comment` 被放行"之类的假绿。）

### 2.5 `@CurrentUserId` 的注入来源

- **注册点**：`WebMvcConfig.addArgumentResolvers(...)` 注册 `CurrentUserIdArgumentResolver`。
- **取值来源**：`request.getAttribute("userId")`，即 `JwtAuthFilter.ATTR_USER_ID`（`"userId"`）。
  参数类型须为 `Long` / `long`（`supportsParameter` 只放行长整型）。
- **两种语义**（`@CurrentUserId` 的 `required`）：

| 形态 | 取不到 userId 时 | 用途 |
|---|---|---|
| `@CurrentUserId`（`required = true`，默认） | 抛 `AuthException`（`UNAUTHORIZED` **401**） | "必须登录"端点。**失败要显式**——避免把"未登录"静默变成 `userId = 0` 脏数据 |
| `@CurrentUserId(required = false)` | 注入 `null`（参数须为包装类型 `Long`） | "匿名可见 **+** 已登录则个性化"（`/start`、`/search/*`、`/profile`、`/comment/show`、`/comment/replies`） |

> ★ **纪律**：`required = false` 的参数**不得**同时依赖 `@RequiresLogin`——两者语义相反
> （"可有可无" vs "必须有"）。公开端点断言 `requiresLogin == false` 就是这条纪律的固化。
>
> ⚠️ 注意：401 因此有**两个可能来源**——过滤器第 ② 段（`@RequiresLogin` 无身份）
> 与参数解析器（`required = true` 取不到 userId）。机制级测试之所以必要，正是为了区分"401 是谁给的"。

## 三、管理员判定

**判定分两处，且都不在 `@RequiresLogin` 里**（该注解只表达"需登录"，不表达角色）：

```java
// JwtAuthFilter#isAdminPath：路径前缀（硬编码，沿袭 TV）
path.startsWith("/api/admin");
```

命中 `/api/admin` 前缀后，`JwtAuthFilter` 调**窄端口** `common.security.AdminChecker` 的
`isAdmin(userId)`：

```java
// AdminChecker（接口在 common）
boolean isAdmin(long userId);

// UserService implements AdminChecker（实现在业务域 user）
public boolean isAdmin(long userId) { return userDao.findRoleById(userId) == 1; }   // role == 1
```

**为什么收口在 `common`**：`common` 不得依赖任何业务域。若 `JwtAuthFilter` 直接注入
`user.service.UserService` 就形成"基建 → 业务"倒挂；正解是**依赖倒置**——接口 `AdminChecker`
放 `common`、实现由 `user` 提供，依赖方向变成"业务 → 基建"，与其余模块一致。
端口宽度以**真实使用面**为准：`JwtAuthFilter` 只问"这个 id 是不是管理员"这一个问题，故端口只含一个方法。

> 最小必要不变量：**新增 admin 端点必须落在 `/api/admin` 前缀下**，否则不会被这段角色校验命中。
> 边界与依赖方向的完整论述见 [模块边界与依赖](./模块边界与依赖.md)（本篇只把 `AdminChecker` 当作一例，不复制其规则）。

## 四、401 vs 403 语义

| 状态码 | 业务码 | 触发条件 | 产生点 |
|---|---|---|---|
| **401** | `UNAUTHORIZED`「请先登录」 | 端点需登录（`@RequiresLogin`）却**无有效身份**：无 token / token 非法 / token 过期 | `JwtAuthFilter` 第 ② 段（**或** `@CurrentUserId(required=true)` 参数解析器兜底） |
| **403** | `FORBIDDEN`「无权访问」 | **已解析出身份但非管理员**，或**匿名**访问 `/api/admin` 前缀 | `JwtAuthFilter` 第 ③ 段（`isAdminPath && !AdminChecker.isAdmin`） |
| **403** | `FORBIDDEN` | 已登录但**无权操作该资源**（如删别人的评论） | 业务层抛 `ForbiddenException` → `GlobalExceptionHandler` → 403 |

`JwtAuthFilter` 的 401/403 是**过滤器短路**响应：它在 DispatcherServlet **之前**，
`@RestControllerAdvice` 覆盖不到，故由过滤器**自写** `ApiResponse.error(code, msg)`，
并顺手把业务码写进 `AccessLogFilter.ATTR_BUSINESS_CODE`（否则鉴权拒绝的访问行会记成 `code=0`，
与"静态资源"混为一谈，访问日志的三态就塌成两态）。

### ⚠️ 为什么类级 `@RequiresLogin` 不能省（缺它会从 401 掉成 403）

`JwtAuthFilter` 的三段是**有序**的：

```
① 解析 token
② 需要登录却无身份 ⇒ 401        ← 依据 @RequiresLogin
③ /api/admin 前缀   ⇒ 非管理员 / 匿名 ⇒ 403
```

若 `admin` 控制器**不加** `@RequiresLogin`，**匿名**请求会在第 ② 段被跳过、直接掉进第 ③ 段判成
**403**；而契约要求匿名请求是 **401**（`/api/admin` 在 TV `PROTECTED_PREFIXES` 里，**先**触发登录判定）。
即"不用加也能拦住"是假象——**拦得对，但给错了状态码**。旧契约对匿名 401 / 非管理员 403 有**成对**断言，
故类级注解是**契约要求**，不是保险。

> 两个层面不可互替：`SecurityContractTests` 断言**机制级**（`requiresLogin == true`），
> HTTP 级测试断言**状态码**。缺类级注解时，机制级先红、端到端随后红。

## 五、JWT

| 项 | 现态（从代码取证） |
|---|---|
| 算法 | `Algorithm.HMAC256`（`JwtService`） |
| 载荷 | `sub = userId`（字符串），带 `iat` / `exp`，自动校验 `exp` |
| 签发点 | 登录 / 注册自动登录时 `jwtService.generateToken(userId)`（`UserService`） |
| 传输 | 请求头 `Authorization: Bearer <token>`——前缀 `"Bearer "` **大小写敏感**，token `trim` 后空串按无 token |
| 校验出口 | 过期 → `TokenExpiredException`(401)；签名不符 / 格式非法 / 缺 `sub` → `InvalidTokenException`(401)。二者**对外都是 401**，仅内部类型可区分（便于日志与将来双 Token） |
| 密钥 | `video.jwt.secret`（`JwtProperties`）；默认 `dev-only-change-me-in-production`，可由环境变量 `JWT_SECRET` 覆盖；**绑定期校验非空** |
| 有效期 | `video.jwt.expire-hours`（`Duration`），默认 `2h`（`${JWT_EXPIRE_HOURS:2h}`，TV 原值 2 小时）；**绑定期校验必须为正** |
| 吊销 | **无**——单 Token **无吊销能力**：token 到期前无法即时踢下线（类注释「已知边界」，留后项：Redis token 版本号 / 双 Token） |

两条配置坑（`application.yaml` 注释留痕，`JwtPropertiesBindingTests` 防回归）：

- ⚠️ `Duration` 属性**必须带单位后缀**（`2h`）。写裸数字 `2` 会被当作"2 个单位、无单位"解析为
  **`PT2S`（2 秒）**，表现为"刚登录就 401"，且**不报任何配置错误**。
- ⚠️ 不要写第二个顶层 `video:` 键——YAML 重复键会覆盖前面的，`video.jwt` 被悄悄吃掉，表现为登录直接 500。

## 六、缺口与上线前待办（只列代码 / 类注释里的现状）

| # | 现状 | 取证来源 |
|---|---|---|
| 1 | **Spring Security 尚未接入过滤器链**；`SecurityPassthroughConfig` 为**临时放行态**（`permitAll`），不提供任何 Security 层保护 | `SecurityPassthroughConfig` 类注释「⚠️ 这是临时状态，接入决策③时必须删掉」 |
| 2 | 迁移时 `@RequiresLogin` 应映射为 `authorizeHttpRequests` 的规则来源（语义不变）；该临时类须被真正的授权规则取代 | `RequiresLogin` 类注释 |
| 3 | 接入 Security 后须补齐 **401/403 出口一致性**：目前无 `AuthenticationEntryPoint` / `AccessDeniedHandler` 需要对齐，接入时须回到 `GlobalExceptionHandler` 补齐 | `GlobalExceptionHandler` 类注释 |
| 4 | **单 Token 无吊销**：token 到期前无法即时下线（留后项：Redis token 版本号 / 双 Token） | `JwtService` / `JwtAuthFilter` 类注释 |
| 5 | JWT `secret` 默认值仅"开箱可跑"，**部署前必须换成环境变量** | `application.yaml` 注释 |
| 6 | 管理员判定依赖**硬编码前缀** `/api/admin`（沿袭 TV；规则少且稳定，无清单维护问题）——新增 admin 控制器若不在该前缀下将不触发角色校验 | `JwtAuthFilter#isAdminPath` 注释 |

> ⚠️ 上表只陈述**能从代码验证的现状**，不含任何排期。迁移涉面 = 一条 `SecurityFilterChain`
> 授权规则 + 两个异常出口（entry point / access denied handler），边界即 `${2}`、`${3}` 两条注释所述。

## 七、新代码检查清单

写/改端点前逐条自检：

1. **加一个"需登录"端点** →
   - 该域**整族都需登录**（无公开端点）⇒ 用**类级** `@RequiresLogin`；
   - 该域**同时有公开端点** ⇒ **只在该方法**打 `@RequiresLogin`（勿用类级，否则误拦公开端点）。
2. **方法里需要当前用户 id** → 加 `@CurrentUserId` 参数（`Long` / `long`），
   并确保该端点标了 `@RequiresLogin`；否则解析器会以 401 兜底——那是"忘了标注解"的信号，不是设计。
3. **"匿名可见 + 已登录则个性化"** → 用 `@CurrentUserId(required = false)`（包装类型 `Long`）；
   **不要**同时打 `@RequiresLogin`（语义相反）。
4. **加一个"需管理员"端点** → 路径落在 **`/api/admin`** 前缀下（触发 `AdminChecker` 角色校验），
   并**务必**打**类级** `@RequiresLogin`（缺它时匿名请求会得 **403** 而非契约要求的 **401**）。
5. **加一个公开端点** → 不打任何鉴权注解；若带 token 只做个性化，走第 3 条。
6. **改完必跑** → `SecurityContractTests`（机制级：`requiresLogin` 判定）+ 对应 HTTP 级流程测试
   （状态码契约）。两者不可互相替代。
7. **不要往 `SecurityPassthroughConfig` 加规则**——授权规则的唯一事实源是 `@RequiresLogin`。

## 八、边界与去向（机制外链）

| 不在本篇的内容 | 去向 | 本篇只保留的边界 |
|---|---|---|
| 脱敏（token / 手机号 / 敏感值不落日志）、访问日志三态 | [可观测](./可观测.md) | 只写"鉴权拒绝自记业务码，故访问行可区分"一句 |
| `common` 不得依赖业务域、窄端口范式、ArchUnit 规则 | [模块边界与依赖](./模块边界与依赖.md) | 只把 `AdminChecker` 当作"窄端口"一例 |
| 审计留痕（`AuditLog`） | [可观测](./可观测.md) | 仅提及 admin / user 端点写审计，不展开出口 |
| 端点参数校验口径（手机号正则、分页归一、缺参 400） | 各业务域 / [模块边界与依赖](./模块边界与依赖.md) | 与鉴权无关的一律不写 |
| 业务层 403（`ForbiddenException`，如删他人评论）的**具体业务规则** | 各业务域 | 只写"已登录但无权操作该资源 ⇒ 403"这一句 |
