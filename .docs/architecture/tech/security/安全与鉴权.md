# 安全与鉴权

> 定位（先读这一句）：本仓的鉴权由**自研** `JwtAuthFilter` + 三个授权注解
> （`@Public` / `@RequiresLogin` / `@RequiresAdmin`）+ `@CurrentUserId` 承担，
> **Spring Security 不接管**——这是 2026-10-18 **拍板不迁**的结论（方案原貌 / 否决理由 /
> 推翻条件见 [§六](#六为什么不用-spring-security已拍板不迁)），已接受的代价见
> [安全与鉴权-已知代价](./安全与鉴权-已知代价.md)。
> 本篇只讲**请求鉴权链形态、端点鉴权声明、管理员判定、401/403 语义、JWT 口径**；
> 脱敏口径（token / 手机号不落日志）去 [可观测](../observability/可观测.md)，
> `common` 边界与窄端口去 [模块边界与依赖](../module-boundary/模块边界与依赖.md)
> ——本篇对二者**只写一句话边界 + 链接**，不复制。
> 文末 [§九 边界与去向](#九边界与去向机制外链) 列全部外链。

## 一、现状一句话

**自研三件套 + 一个授权声明面**：`common.security.JwtAuthFilter`（过滤器）、
三个注解（`@Public` 放行口 / `@RequiresLogin` 需登录 / `@RequiresAdmin` 需管理员）、
`@CurrentUserId`（把登录用户 id 注入控制器参数）。全部在 `common`，不依赖任何业务域。

**★ 2026-10-18 两条口径变更**（F-01 调查后判定的"真风险"，均已落地）：

| 变更 | 旧 | 新 | 为什么 |
|---|---|---|---|
| 默认值 | 标了 `@RequiresLogin` 才拦（**fail-open**） | 没标 `@Public` 就拦（**fail-closed**） | 漏标在旧口径下**不会响亮失败**：端点若收 `@CurrentUserId`，参数解析器兜出 401，"看起来是对的"。真正敞开的只有不接收 userId 的端点 |
| 管理员判定 | `path.startsWith("/api/admin")` 前缀 | 处理器上的 `@RequiresAdmin` | 前缀读**未解码** URI，路由走 PathPattern —— 两个判据语义不同；且"新 admin 端点必须落在某前缀下"只能靠人记 |

**Spring Security 未接管**：项目仍引入 `spring-boot-starter-security`（为用其 BCrypt），
但鉴权**不**走它的过滤器链。`common.config.SecurityPassthroughConfig` 提供一条
`anyRequest().permitAll()` 的链，**仅用于替换 Security 的默认保护链**（默认链会把一切拦成 401），
把鉴权交还给 `JwtAuthFilter`。该类的"临时态"标记已作废——它是**永久形态**，
理由与代价见 [§六](#六为什么不用-spring-security已拍板不迁) 与
[已知代价](./安全与鉴权-已知代价.md) 第 2 条。

```java
// SecurityPassthroughConfig#passthroughFilterChain（终态，不是临时态）
http.csrf(csrf -> csrf.disable())
    .httpBasic(basic -> basic.disable())
    .formLogin(form -> form.disable())
    .authorizeHttpRequests(auth -> auth.anyRequest().permitAll());
```

## 二、请求鉴权链

### 2.1 过滤链顺序（从外到内）

链路顺序由各过滤器类注释与 `@Order` 共同确定（限流专项 `T25` 起全部**显式定序**）：

```
请求
 └─ RequestIdFilter        @Order(HIGHEST_PRECEDENCE)        ← 唯一 set/clear reqId（MDC）
     └─ AccessLogFilter    @Order(HIGHEST_PRECEDENCE + 1)    ← 包住其后全部，含鉴权/限流短路响应
         └─ Security 链（SecurityPassthroughConfig，permitAll）  ← 排在本项目自研过滤器之前
             └─ JwtAuthFilter  @Order(0)（限流专项 T25 显式化；此前无 @Order ⇒ 最低优先级）
                 └─ RateLimitFilter  @Order(JwtAuthFilter.AUTH_FILTER_ORDER + 10)
                     ← 限流闸门（限流专项 T25），**鉴权之内侧**——拍板 A「先鉴权后扣费」：
                       401/403 在鉴权层短路 ⇒ 被拒绝的请求到不了限流器、不浪费令牌
                 └─ DispatcherServlet → 控制器 / 参数解析器
```

两条来自类注释的事实锚点：

- `RequestIdFilter` 注释：本类是**唯一**的 set/clear 点，顺序为 `HIGHEST_PRECEDENCE`
  （"比 `AccessLogFilter` 与 Spring Security 链都靠外"）。
- `AccessLogFilter` 注释：紧贴 `RequestIdFilter` 之内（`HIGHEST_PRECEDENCE + 1`），
  "仍包住 Spring Security 链与 `JwtAuthFilter`"——故 401/403 与 429 这类**被过滤器短路**的
  请求同样有访问日志（429 的业务码由 `RateLimitFilter` 补记 `ATTR_BUSINESS_CODE`）。

> 限流器与链序的完整口径（覆盖范围 / 429 出口 / fail-open）在 [限流](../rate-limit/限流.md) §三，
> 本篇只钉"它在鉴权之内侧"这一条结构事实。`RateLimitFilter` 的序号取
> `AUTH_FILTER_ORDER + 10` 而非裸数字——把"限流器在鉴权之后"钉进常量本身。

### 2.2 `JwtAuthFilter.doFilterInternal` 三段（**顺序不可交换**）

```java
① HandlerAuthz authz = mappingLookup.resolve(request);   // 一次解析：{loginRequired, adminRequired}
   解析 Authorization: Bearer …
       有 token 且校验通过 → request.setAttribute("userId", userId)
       有 token 但非法/过期 → 仅当 authz.loginRequired() 才 401 短路，否则记 debug 按匿名放行
② authz.loginRequired() && userId == null          ⇒ 401（UNAUTHORIZED「请先登录」）短路
③ authz.adminRequired() && (userId == null || !adminChecker.isAdmin(userId))
                                                   ⇒ 403（FORBIDDEN「无权访问」）短路
   ↓ 都通过
   chain.doFilter(...)
```

关键点：

- **令牌"存在即校验"**，与端点是否需要登录**无关**：为将来 `@CurrentUserId` 可选注入留口。
- **公开端点收到坏 token ⇒ 按匿名处理**（不写请求属性、不阻断），避免因坏 token 误杀公开接口。
- `resolve(request)` 委托给 `RequestMappingLookup`（见 §2.3）；**每请求只调一次**，
  两个维度一起返回（`HandlerAuthz` 是 record，不可变）。

### 2.3 授权判定的判定式（`RequestMappingLookup`）

单点判定「该请求的目标处理器要求什么」：

1. 用 `@Qualifier("requestMappingHandlerMapping")` 调 `getHandler(request)`，拿到
   `HandlerExecutionChain`，**解开**后取 `HandlerMethod`（`AbstractHandlerMapping` 的结果会缓存在
   请求属性上，DispatcherServlet 随后的同路径查找是幂等的）。
2. 判定式（`AnnotatedElementUtils`，方法级 **或** 类级命中即算）：

   ```java
   adminRequired = @RequiresAdmin                                  // 蕴含 loginRequired
   loginRequired = adminRequired || @RequiresLogin || !@Public      // 默认拒绝；冲突取严
   ```

   ★ 三种"看起来都该放行"的写法其实都要求登录：什么都没标（默认拒绝）、
   `@Public + @RequiresLogin`（矛盾声明取严并 WARN）、`@Public + @RequiresAdmin`（同上）。
3. **只对"属于 `@Controller` 的处理器"做判定**：未映射路径、静态资源（`/upload/**`、`/static/**`、
   `/actuator/**`，由别的 `HandlerMapping` 承接）以及**框架内部 handler** 一律 `NONE`——
   真正的 404 交 DispatcherServlet，本机制不越权处理路由语义。
   ★ 最典型的内部 handler 是 **OPTIONS**：Spring 对"路径能匹配、方法不匹配"的请求返回内部
   `HttpOptionsHandler`（外层是 `HandlerMethod`，但 bean 类型不是任何控制器）⇒ 若按默认拒绝处理，
   匿名 OPTIONS 会从"200 + Allow"变成 401。
   ⚠️ 筛子的判据是「**处理器属于谁**」而**不是**「请求方法是不是 OPTIONS」——控制器里**显式声明**的
   OPTIONS 业务方法照样过授权（否则将来写 `@RequestMapping(method = OPTIONS)` 就会静默绕过鉴权）。
   用例：`SecurityContractTests#OPTIONS不参与授权判定` + `JwtAuthFilterAuthzTests#显式OPTIONS业务方法不被豁免`。
4. 本 bean **只注入 `JwtAuthFilter`**（不注册为 `Filter` / `WebMvcConfigurer`），
   以避免与 `HandlerMappingIntrospector` 的早期初始化产生循环依赖。

> ⚠️ **一次曾"完全失效"的修复（代码留痕）**：原实现直接对 `getHandler` 的返回值做
> `instanceof HandlerMethod`，而它返回的是 `HandlerExecutionChain` ⇒ 判定**恒放行** ⇒
> 授权注解**从未生效**。长期未被发现，是因为所有受保护端点**恰好都用了
> `@CurrentUserId`**（那个解析器取不到 userId 会抛 401），于是"401 看起来是对的"——
> 直到出现首个"需要保护但不接收 userId"的端点（`/like/content/count`，`T58` 后为
> `GET /api/v1/contents/{id}/like-count`）才暴露：
> 它无 token 时返回了 **200**。回归网 = `SecurityContractTests`（直接断言机制本身）+ HTTP 级
> `LikeFlowTests.未登录全部401`。**这也是本轮改"默认拒绝"的直接动因**：同一种假象不能再有第二次。

### 2.4 类级 vs 方法级：怎么选（取舍）

三个注解的 `@Target` 都是 `{METHOD, TYPE}`：标**类**上 = 该 Controller 全部端点适用。

| 写法 | 对应 TV `AuthFilter` 语义 | 本仓实证用例 | 为什么这么选 |
|---|---|---|---|
| **类级 `@RequiresAdmin`** | 前缀保护 + `role==1` | 3 个 admin 控制器（`/api/v1/admin/**`） | "仅管理员"必然包含"需登录"⇒ **不再叠 `@RequiresLogin`** |
| **类级 `@RequiresLogin`** | 前缀保护（整族） | `LikeController`（like 全族 `/api/v1/{contents,comments}/{id}/like[-count]`）、`FollowController`（`/api/v1/follows/**`、`/api/v1/users/{id}/{following,followers}`）、`FeedController`（`/api/v1/feed`）、`UploadController`（`/api/v1/contents/{videos,posts}`、`/api/v1/contents/{id}/media`） | 把"这一族整体受保护"写在一处，**新增子路径自动覆盖** |
| **方法级 `@RequiresLogin`** | 精确保护（个别端点） | `UserController` 的 3 个端点、content 4 个写、comment 2 个写、coupon 2 个、favorite 9 个、watchlater 4 个 | 这些域名下**同时存在公开端点**；用类级会把公开端点**误拦** |
| **方法级 `@Public`** | TV 清单之外的匿名端点 | **12 个**：`POST /api/v1/sessions`、`POST /api/v1/users`、`GET /api/v1/contents/recommended`、`GET /api/v1/users/{id}`、`GET /api/v1/contents/{id}`、`GET /api/v1/contents`（搜索）、`GET /api/v1/contents/{id}/comments`、`GET /api/v1/comments/{id}/replies`、`GET /api/v1/coupons`、`GET /api/v1/users/{id}/favorite-folders`、`GET /api/v1/favorite-folders/{id}/items`、`GET /api/v1/contents/{id}/favorite-count` | **唯一放行口**：默认拒绝下"公开"必须是显式声明，不是"忘了写" |

判据归根：**类级适合"整族无公开端点"的域；含公开端点的域必须逐方法声明。**
（`SecurityContractTests` 固化了两个方向——既有"类级覆盖全部端点"的断言，也有
"公开端点不得被判为需登录"的反向断言，防止"整个 `/comment` 被放行"之类的假绿。）

### 2.5 `@CurrentUserId` 的注入来源

- **注册点**：`WebMvcConfig.addArgumentResolvers(...)` 注册 `CurrentUserIdArgumentResolver`。
- **取值来源**：`request.getAttribute("userId")`，即 `JwtAuthFilter.ATTR_USER_ID`（`"userId"`）。
  参数类型须为 `Long` / `long`（`supportsParameter` 只放行长整型）。
- **两种语义**（`@CurrentUserId` 的 `required`）：

| 形态 | 取不到 userId 时 | 用途 |
|---|---|---|
| `@CurrentUserId`（`required = true`，默认） | 抛 `AuthException`（`UNAUTHORIZED` **401**） | "必须登录"端点。**失败要显式**——避免把"未登录"静默变成 `userId = 0` 脏数据 |
| `@CurrentUserId(required = false)` | 注入 `null`（参数须为包装类型 `Long`） | "匿名可见 **+** 已登录则个性化"（`GET /api/v1/contents/recommended`、`GET /api/v1/contents`（搜索）、`GET /api/v1/users/{id}`、`GET /api/v1/contents/{id}/comments`、`GET /api/v1/comments/{id}/replies`）——这些端点**必须同时标 `@Public`** |

> ★ **纪律**：`required = false` 的参数**必须**配 `@Public`——默认拒绝下漏标会 401，
> 而参数解析器明明能处理匿名。反过来，`@Public` 端点**不得**再标 `@RequiresLogin` / `@RequiresAdmin`
> （语义矛盾；即便写了也按更严的算，且会 WARN）。
>
> ⚠️ 注意：401 因此有**两个可能来源**——过滤器第 ② 段（判定为需登录但无身份）
> 与参数解析器（`required = true` 取不到 userId）。机制级测试之所以必要，正是为了区分"401 是谁给的"。

## 三、管理员判定

**判定只有一处：处理器上的 `@RequiresAdmin`**（`RequestMappingLookup` 读出后由
`JwtAuthFilter` 第 ③ 段执行）：

```java
// JwtAuthFilter # 第 ③ 段
if (authz.adminRequired() && (userId == null || !adminChecker.isAdmin(userId))) → 403
```

`AdminChecker` 仍是**窄端口**（接口在 `common`、实现由 `user` 提供）：

```java
// AdminChecker（接口在 common）
boolean isAdmin(long userId);

// UserService implements AdminChecker（实现在业务域 user）
public boolean isAdmin(long userId) { return userDao.findRoleById(userId) == 1; }   // role == 1
```

**为什么收口在 `common`**：`common` 不得依赖任何业务域。若 `JwtAuthFilter` 直接注入
`user.service.UserService` 就形成"基建 → 业务"倒挂；正解是**依赖倒置**——接口 `AdminChecker`
放 `common`、实现由 `user` 提供，依赖方向变成"业务 → 基建"，与其余模块一致。
端口宽度以**真实使用面**为准：`JwtAuthFilter` 只问"这个 id 是不是管理员"这一个问题，故端口只含一个方法。

**代价与护栏**：权威源从"路径前缀"变成"注解"⇒ 落在 `/api/v1/admin/**` 却漏标 `@RequiresAdmin`
的控制器只要求登录、不要求管理员。该缺口由
`SecurityContractTests#所有admin前缀控制器都必须标RequiresAdmin` 兜住（扫描容器内全部
`@RestController` 的类级**与方法级** `@RequestMapping`（`T58` 后 admin 路由全写在方法上，只扫类级会假绿），
命中前缀却没标注解 ⇒ **红**）。
登记见 [已知代价](./安全与鉴权-已知代价.md) 第 3 条。

> 副作用（有意）：**admin 端点不再必须落在 `/api/admin` 前缀下（`T58` 后为 `/api/v1/admin`）** —— 授权跟着处理器走，
> 放哪个路径都能生效；前缀现在只是"人读得懂的命名约定"。

## 四、401 vs 403 语义

| 状态码 | 业务码 | 触发条件 | 产生点 |
|---|---|---|---|
| **401** | `AUTH_UNAUTHORIZED`「请先登录」 | 判定为需登录（`@RequiresLogin` / `@RequiresAdmin` / **未标 `@Public`**）却**无有效身份**：无 token / token 非法 | `JwtAuthFilter` 第 ② 段（**或** `@CurrentUserId(required=true)` 参数解析器兜底） |
| **401** | `AUTH_TOKEN_EXPIRED`「登录已过期，请重新登录」 | 携带了 token 但已过期（与"没带 / 伪造"分开：前端据此提示"过期"而非"请登录"） | `JwtAuthFilter` 第 ① 段（`JwtService` 抛 `TokenExpiredException`） |
| **401** | `AUTH_BAD_CREDENTIALS`「账号或密码错误」 | **登录失败**：账号不存在**与**密码错误共用一个码、一句文案 | `UserService#doLogin` → `BadCredentialsException` |
| **403** | `AUTH_FORBIDDEN`「无权访问」 | 处理器标 `@RequiresAdmin` 且**已解析出身份但非管理员** | `JwtAuthFilter` 第 ③ 段（`AdminChecker.isAdmin` 为 false） |
| **403** | `AUTH_FORBIDDEN` | 已登录但**无权操作该资源**（如删别人的评论） | 业务层抛 `ForbiddenException` → `GlobalExceptionHandler` → 403 |

> ★ **登录失败不区分「账号不存在」与「密码错误」**（`T55`，用户 2026-10-22 裁决）：分开回答等于提供
> 手机号是否注册过的探测口，一个脚本就能批量筛。同码同文案之外还必须**同耗时** —— 账号不存在时
> 也对一个假哈希跑一次 BCrypt，否则时间差本身就是同一个口子（见 `UserService#doLogin`）。
> 与收藏域「收藏夹不存在 / 不公开 ⇒ 同 404 同文案」是同一条原则。
> ⚠️ 残留探测面（**已知代价**）：注册接口的「手机号已被使用」（`USER_PHONE_TAKEN`）必须如实回答；
> 真正的收口手段是短信验证（本期不做）。口径见 `architecture/tech/api/接口契约.md` §2.2。

`JwtAuthFilter` 的 401/403 是**过滤器短路**响应：它在 DispatcherServlet **之前**，
`@RestControllerAdvice` 覆盖不到，故由过滤器**自写** `ApiResponse.error(code, msg)`，
并顺手把业务码写进 `AccessLogFilter.ATTR_BUSINESS_CODE`（否则鉴权拒绝的访问行会记成 `code=0`，
与"静态资源"混为一谈，访问日志的三态就塌成两态）。

### ⚠️ 为什么"匿名访问 admin 端点得 401"是结构保证，而不是"两个注解都写对"

`@RequiresAdmin` **蕴含**"需要登录"（判定式见 §2.3），于是三段的分工是：

```
① 解析 token
② adminRequired ⇒ loginRequired ⇒ 匿名 ⇒ 401     ← 不再需要额外标 @RequiresLogin
③ adminRequired ⇒ 非管理员 ⇒ 403
```

旧实现的陷阱（已消除）：admin 控制器若漏标 `@RequiresLogin`，**匿名**请求会跳过第 ② 段、
掉进第 ③ 段判成 **403**——"拦得对，但状态码错"。旧 pytest 对匿名 401 / 非管理员 403 有**成对**断言，
故那一步曾是**契约要求**，不是保险。

> 两个层面不可互替：`SecurityContractTests` 断言**机制级**（`resolve()` 的两个布尔量），
> HTTP 级测试（`AdminSecurityTests`）断言**状态码**。缺注解时，机制级先红、端到端随后红。

## 五、JWT

| 项 | 现态（从代码取证） |
|---|---|
| 算法 | `Algorithm.HMAC256`（`JwtService`） |
| 载荷 | `sub = userId`（字符串），带 `iat` / `exp`，自动校验 `exp` |
| 签发点 | 登录 / 注册自动登录时 `jwtService.generateToken(userId)`（`UserService`） |
| 传输 | 请求头 `Authorization: Bearer <token>`——前缀 `"Bearer "` **大小写敏感**，token `trim` 后空串按无 token |
| 校验出口 | 过期 → `TokenExpiredException`(401)；签名不符 / 格式非法 / 缺 `sub` → `InvalidTokenException`(401)。二者**对外都是 401**，仅内部类型可区分（便于日志与将来双 Token） |
| 密钥 | `video.jwt.secret`（`JwtProperties`）；默认 `dev-only-change-me-in-production`，可由环境变量 `JWT_SECRET` 覆盖；**绑定期校验非空** |
| 有效期 | `video.jwt.expire-hours`（`Duration`），默认 `2h`（`${JWT_EXPIRE_HOURS:2h}`，TV 原值 2 小时）；**绑定期校验必须为正** |
| 吊销 | **无**——单 Token **无吊销能力**：token 到期前无法即时踢下线（已登记为[已知代价](./安全与鉴权-已知代价.md) 第 1 条；填坑路径：Redis token 版本号 / 双 Token） |

两条配置坑（`application.yaml` 注释留痕，`JwtPropertiesBindingTests` 防回归）：

- ⚠️ `Duration` 属性**必须带单位后缀**（`2h`）。写裸数字 `2` 会被当作**"2 个毫秒"**
  （`DurationStyle` 无后缀时默认单位是 **MILLIS**）解析为 **`PT0.002S`**，表现为"刚登录就 401"，
  且**不报任何配置错误**。★ 该单位由 `JwtPropertiesBindingTests#裸数字按毫秒解析` 实测钉住
  （2026-10-18 更正：本仓曾长期写作"`PT2S`（2 秒）"，真值是 2 毫秒——结论不变，差三个数量级）。
- ⚠️ 不要写第二个顶层 `video:` 键——YAML 重复键会覆盖前面的，`video.jwt` 被悄悄吃掉，表现为登录直接 500。

## 六、为什么不用 Spring Security（**已拍板不迁**）

> **F-01 / F-02 于 2026-10-18 结案：不迁移**。原先两处"临时态必须删掉"的措辞随之作废。
> 下面按"想过但否决"的三要素留痕：**方案原貌 / 否决理由 / 推翻条件**。

**方案原貌**：用 `SecurityFilterChain` + `authorizeHttpRequests` 接管授权，
`@RequiresLogin` 映射为路径规则（F-02 登记原文如此），删除 `SecurityPassthroughConfig`，
补 `AuthenticationEntryPoint` / `AccessDeniedHandler` 对齐 401/403 出口。

**否决理由**（逐条可复核）：

1. **使用面只有三条**：无状态 Bearer 解析、一个"是否已认证"判定、一个 admin 角色判定。
   会话管理 / CSRF / form login / remember-me / 并发会话控制在纯 token API 里**零场景**。
2. **授权粒度会退化**：本仓是**处理器级**（注解在 handler 上），`authorizeHttpRequests` 是**路径级**
   ⇒ 31 处注解要还原成 ~30 条路径规则，形态与老项目 `PROTECTED_PREFIXES` / `PROTECTED_EXACT`
   **同构**，正是决策③ 要根治的东西（"清单与端点分处两地、评审要人工比对"）。
   用方法安全（`@PreAuthorize("isAuthenticated()")`）能保住注解，但那是**同一个机制改名**，
   还引入 SecurityContext 依赖。
3. **三处刚收口的硬契约要重新对齐**：限流链序（`RATE_LIMIT_ORDER = AUTH_FILTER_ORDER + 10`，
   拍板 A）、访问日志三态（`ATTR_BUSINESS_CODE` 由过滤器补记）、admin 匿名 401 / 非管理员 403 成对。
   而"HTTP 侧对注解机制是假绿"是已知坑 ⇒ 必须先重写 `SecurityContractTests`（200+ 行）才敢动。
4. **角色查询会回归**：现在 `AdminChecker` 只在 `@RequiresAdmin` 端点才查库；
   标准化成 authorities 就是**每请求 +1 SELECT**（除非自定义懒加载 `Authentication`，那更绕）。
5. **一个具体坑**：`GlobalExceptionHandler` 有 `@ExceptionHandler(Exception.class)` 兜底 500 ⇒
   方法安全抛的 `AccessDeniedException` 会被它**吞成 500**（`ExceptionTranslationFilter` 在外侧，轮不到）。
6. **判别力没有增量**：现有机制有"曾经完全失效"的修复史 + **28 例**机制级测试
   （`SecurityContractTests` + `JwtAuthFilterAuthzTests`）+ **19 个测试文件**的 HTTP 级状态码断言
   （另有 6 个文件只是提到 401/403 语义）；迁移不会让它更容易验证，只会让防线先失效一轮。

**它唯一"免费"给到的两样，已单独拿到**：① 默认拒绝（改为"没标 `@Public` 就拦"）；
② 规则与路由同源匹配（`@RequiresAdmin` 跟着处理器走）。

**推翻条件**（出现任一条即应重新评估，届时走方法安全路线，不是路径规则路线）：

1. 引入第二种认证方式（微信 / 短信 / OAuth2，多 provider）；
2. 需要方法级**资源归属**表达式（`@PreAuthorize` 里带 `#contentId`）；
3. 改 cookie 存 token（CSRF 面出现）；
4. 变成**多角色 / 权限点表**（不再是一个 `role == 1`）；
5. 多人接手，自研约定成为上手成本。

## 七、缺口与上线前待办（只列代码 / 类注释里的现状）

| # | 现状 | 取证来源 |
|---|---|---|
| 1 | **Spring Security 不接管任何授权**；`SecurityPassthroughConfig` 为**永久形态**（`permitAll`），并**暗依赖**其 `StrictHttpFirewall`（`//`、`..`、编码斜杠的规范化拦截由它兜） | `SecurityPassthroughConfig` 类注释；[限流](../rate-limit/限流.md) §三"潜伏边界"；[已知代价](./安全与鉴权-已知代价.md) 第 2 条 |
| 2 | 若将来真迁 Security，须补齐 **401/403 出口一致性**（`AuthenticationEntryPoint` / `AccessDeniedHandler`）——当前**无此缺口**，因为短路出口只有 `JwtAuthFilter#writeError` 一处 | `GlobalExceptionHandler` 类注释 |
| 3 | **单 Token 无吊销**：token 到期前无法即时下线 | `JwtService` / `JwtAuthFilter` 类注释 |
| 4 | JWT `secret` 默认值仅"开箱可跑"，**部署前必须换成环境变量** | `application.yaml` 注释 |
| 5 | **角色判定只在 `@RequiresAdmin` 处理器上查库**——新增 admin 端点若忘标注解，不会被前缀兜住（有测试护栏，见 §三） | `RequiresAdmin` 类注释；`SecurityContractTests` |

> ⚠️ 上表只陈述**能从代码验证的现状**，不含任何排期。

## 八、新代码检查清单

写/改端点前逐条自检：

1. **加一个"需登录"端点** →
   - 该域**整族都需登录**（无公开端点）⇒ 用**类级** `@RequiresLogin`；
   - 该域**同时有公开端点** ⇒ **只在该方法**打 `@RequiresLogin`（勿用类级，否则误拦公开端点）。
   > ⚠️ 默认拒绝下 `@RequiresLogin` **不是判定来源**（不标也会拦），它的价值只剩"可读性声明"
   > 与"与 `@Public` 冲突时取严"。所以真正的动作是"**别标 `@Public`**"。
2. **加一个公开端点** → **必须**标 `@Public`（默认拒绝：漏标 = 匿名访问 401）。
   若同时要"已登录则个性化"，配 `@CurrentUserId(required = false)`（包装类型 `Long`）。
   **不要**再叠 `@RequiresLogin`（矛盾声明，会 WARN 且按需登录处理）。
3. **方法里需要当前用户 id** → 加 `@CurrentUserId` 参数（`Long` / `long`）。
   注意：它**不再**是"忘标注解时的兜底 401"来源——默认拒绝已经在过滤器拦下了。
4. **加一个"需管理员"端点** → 在控制器（或方法）上标 **`@RequiresAdmin`**。
   **不需要**再标 `@RequiresLogin`（蕴含）；路径建议仍落在 `/api/v1/admin` 下（只是命名约定），
   并且**必须**标——漏标时它只是个普通登录端点（`SecurityContractTests` 的前缀护栏会红）。
5. **改完必跑** → `SecurityContractTests`（机制级：`resolve()` 两个布尔量）+ 对应 HTTP 级流程测试
   （状态码契约）。两者不可互相替代。
6. **不要往 `SecurityPassthroughConfig` 加规则**——授权规则的唯一事实源是三个注解。
