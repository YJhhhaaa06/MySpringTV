## ［安全］不接管 Spring Security（来源：`F-01`，2026-10-18 拍板）

- **What**：放弃 Spring Security 整套认证 / 授权生态，只保留自研 `JwtAuthFilter` + 三个注解。
  具体拿不到的是：会话管理、CSRF 防护、标准认证事件（登录成功 / 失败可被审计订阅）、
  `hasRole` / SpEL 资源表达式、`AuthenticationEntryPoint` 等标准扩展点。
- **Impact**：影响面：全部 HTTP 端点。直观现象：功能上**用户无感**（401/403 契约一致），
  但后续要做第二认证方式 / 多角色时**没有现成落点**，得先在自研链上加。
  红线提示：一旦出现"第二种登录方式"或"权限点表"，本条目即被推翻（改走方法安全）。
- **When**：常态存在，是本仓"纯 token、无 cookie、单角色"形态的**固有面**；只在扩展认证维度时疼。
- **Why & Mitigation**：放弃 `authorizeHttpRequests`（路径级规则会把处理器级注解退回老项目那两张
  硬编码清单 —— 详见 [安全与鉴权](./安全与鉴权.md) §六 六条否决理由）。
  对冲方案：它唯一"免费"的默认拒绝与规则/路由同源，已单独实现；推翻条件写在设计文档 §六。

## ［安全］［运维复杂度］依赖 Security 却只用其 BCrypt（来源：`F-02`，2026-10-18 拍板）

- **What**：`spring-boot-starter-security` 留在类路径上，于是必须用 `SecurityPassthroughConfig`
  压掉它的默认保护链（`anyRequest().permitAll()`，**永久形态**，不是临时态）—— 若不压，
  Security 的默认链会把**所有**请求（连 `POST /api/v1/sessions`）先拦成 401。
  同时请求合法性（`//`、`..`、编码斜杠等规范化绕过）**由它自带的 `StrictHttpFirewall` 兜底**，
  而这件事在业务代码里搜不到。
- **Impact**：影响面：整条过滤器链 + 依赖清单。直观现象：代码里有一条看起来"多余"的全放行链；
  依赖分析会认为"本项目用了 Spring Security"。
  红线提示：若有人把 starter 收窄成 `spring-security-crypto`（以为"我们没用 Security"），
  防火墙会**静默消失**，限流跳过清单与 `/api/v1/admin/**` 的路由匹配/规范化同时失去这层兜底。
- **When**：常态存在（每次读依赖 / 读链序都会遇到）；第二条只在"精简依赖"那一刻爆。
- **Why & Mitigation**：放弃"收窄依赖"（会连防火墙一起丢）与"完整迁移"（F-01 已否）。
  对冲方案：本台账 + [限流](../rate-limit/限流.md) §三"潜伏边界"两处留痕，把暗依赖写成明文口径。

## ［安全］单 Token 无吊销（来源：`决策③` 留后项，2026-10-18 登记）

- **What**：JWT 自包含、无服务端状态 ⇒ 签发后**到期前无法作废**。封号、改密、怀疑泄露都踢不掉。
- **Impact**：影响面：`PUT /api/v1/users/me/password` 之后旧 token 仍然可用（窗口 = 剩余有效期，默认 2h）。
  直观现象：用户改完密码，别的设备上的会话**不会**掉线。
  红线提示：若出现"封禁必须立即生效"的运营要求，本条目须先推翻。
- **When**：仅在"需要即时失效"的场景疼（封号 / 泄露）；常态下无感。概率：低（本仓无真实流量）。
- **Why & Mitigation**：放弃双 Token / Redis 版本号（为 2h 窗口引入一次每请求 Redis 读或一次落库，
  与"每请求少一次往返"的口径相反）。对冲方案：有效期保持 2h；真要填坑走
  "token 内加版本号 + 每请求比一次 Redis"，届时按 [韧性](../resilience/韧性.md) 的降级口径设计。

## ［运维复杂度］角色权威源从路径前缀改为处理器注解（来源：`F-01` 修复项，2026-10-18 拍板）

- **What**：`@RequiresAdmin` 取代 `path.startsWith("/api/admin")`。好处是规则与路由同一份事实；
  代价是**前缀不再自动兜底**：新 admin 控制器漏标注解时，它只是个"要登录"的端点。
- **Impact**：影响面：未来所有 `/api/v1/admin/**` 控制器。直观现象：漏标时非管理员也能调管理接口。
  红线提示：`SecurityContractTests#所有admin前缀控制器都必须标RequiresAdmin` 变红 ⇒ 立即可见，
  **该用例被删/被跳过**本身就是红线。
- **When**：护栏的**精确扫描面** = 「`@RestController` bean + **类级或方法级** `@RequestMapping` 的 value/path
  以 `/api/v1/admin` 开头 + 要求 `@RequiresAdmin` 标在**类**上」（`T58` 后 admin 控制器去掉类级
  `@RequestMapping`、路由全路径写在方法上 ⇒ 护栏同批改为**类级 + 方法级都收**，否则变空转的假绿）。
  ⚠️ 反例：类级 `@RequestMapping("/api")` + 方法级 `@GetMapping("/v1/admin/x")`（实际 URL 仍在
  `/api/v1/admin/x`）——`T58` 后方法级映射也在扫描面内，该漏扫形态**已消除**；仍漏不掉的只剩
  "注解标在父类/接口上被代理吞掉"这类结构性写法，只能靠评审。
- **Why & Mitigation**：放弃前缀判据（它读**未解码** URI 而路由走 PathPattern，两个判据语义不同，
  且"必须落在某前缀下"只能靠人记）。对冲方案：容器级扫描用例把"约定"变成**会失败的测试**。

## ［运维复杂度］默认拒绝：公开端点必须显式 `@Public`（来源：`F-01` 修复项，2026-10-18 拍板）

- **What**：授权默认值从"声明才拦"改为"声明才放"。代价是新增**公开**端点必须显式标注解，
  否则匿名访问得到 401。
- **Impact**：影响面：全部端点。直观现象：漏标时首页 / 详情 / 搜索类接口对匿名用户 401 ——
  **功能坏掉，但不会静默泄露**（这正是要的方向）。
  红线提示：若某端点"应该公开却要登录"，**补 `@Public`**（`@RequiresLogin` / `@RequiresAdmin`
  都不是绕道口——它们只表达"要登录 / 要管理员"，不能放行匿名）。
- **When**：只在"新增公开端点"时发生；该端点若已有 HTTP 级匿名用例，会当场变红
  （没有匿名用例的新端点则不会）。
- **Why & Mitigation**：放弃 fail-open（漏标会静默开放，且 `@CurrentUserId` 的兜底 401 会把它伪装成
  "鉴权正常"——S3 那轮 `RequestMappingLookup` 完全失效就是这样被掩盖了很久）。对冲方案：`SecurityContractTests` 钉住
  "未标注解 ⇒ 需登录"与"标 `@Public` ⇒ 匿名"两个方向。
