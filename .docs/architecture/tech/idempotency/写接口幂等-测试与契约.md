# 写接口幂等 —— 测试与对外契约

> 定位：本篇回答两件事 —— **"怎么证明它真的生效"** 与 **"对外承诺了什么"**。
> 设计与边界在 [写接口幂等](写接口幂等.md)；测试纪律的**唯一事实源**是仓库根 `AGENTS.md`「测试纪律」节，本篇只写幂等专项的落地口径。

---

## 一、注册表完整性（防"漏登记"）

注册表在 `common/idempotency/IdempotencyScope`，键 = `"<方法> <路由模式>"`。
四条断言，**全部扫真实 handler**（`RequestMappingHandlerMapping#getHandlerMethods`），不读配置文件：

| # | 断言 | 治什么 |
|---|---|---|
| 1 | 扫描面 `seen >= N`（当前非 GET 端点总数） | introspection 失效导致"全绿但什么都没查" |
| 2 | `missing` = handler 有、表里无 ⇒ 空 | 新增端点漏登记 ⇒ **静默不幂等** |
| 3 | `methodUnlimited` = 方法级 `@RequestMapping` 未限定 HTTP 方法 ⇒ 空 | 扫描盲区；逼调用方改用 `@GetMapping` / `@PostMapping` |
| 4 | **`stale` = 表里有、handler 无 ⇒ 空** | 删端点忘删登记；**全站改路径后旧键残留** |

第 4 条是既有权重表没有的，本专项要补上。有了它，"批量改路由"这类改动之后，
表与代码**双向**对不上会立刻变红，而不是留下一条永远不命中的死键。

**跳过规则**（与限流权重表一致）：

- `GET` / `HEAD` / `OPTIONS` / `TRACE` 不登记。
- `pattern` 以 `/error` 开头的不登记（Spring 默认错误分发，不是业务端点）。
- 表里 `NATURAL` 条目**只服务本测试**：运行期"未命中 `KEYED`"即放行，不需要查 `NATURAL`。
  它存在的意义是"我们确实看过这个端点，并判断它天然幂等"——**这行登记本身就是 review 的锚点**。

## 二、用例矩阵

四条端点各跑同一套 6 条。**缺一条不算交付**。

| # | 场景 | 断言（可观察行为） |
|---|---|---|
| 1 | 同 key 重发 | 第二次 2xx；body 与首次**逐字节相同**；响应头 `Idempotent-Replayed: true` |
| 2 | 同 key 重发 | **独立 oracle** 复算的副作用计数只 +1（直查 DB，不信接口回显） |
| 3 | 并发两请求同 key | 业务只执行一次；另一个拿到重放或 409，**不得**两个都执行 |
| 4 | 同 key 不同 body | 422 `IDEMPOTENCY_KEY_CONFLICT`，且**零副作用** |
| 5 | 首次失败（非 2xx）后同 key 重发 | 能正常执行（没有被 `FAILED` 卡住），并最终 2xx |
| 6 | 缺 key / 非法 key | 缺 key：放行且**不建 `idem:*` 键**；非法 key：400 且零副作用 |

**端点专属**：

| 端点 | 追加断言 |
|---|---|
| `coin` | ★ **两个不同 key 各投 1 枚 ⇒ 累计 2 枚**（证明没有退化成"按内容去重"，见下） |
| `video` / `post` | 第二次请求**没有新文件落盘**（比对上传目录文件数，而不是断言"没调用上传方法"） |
| `comment` | ⚠️ 响应体目前是 `{}` ⇒ "重放 body 与首次相同"是**真空转**（怎么写都相同）。**不写这条**（假绿）；响应层补齐（需求侧）后再补一条"两次的 `data` 含同一个新标识" |

⚠️ **投币那条是反向判别力所在**：投币是**累加语义**（两台设备各投 1 枚是合法的两次独立意图）。
客户端每次点击生成新 key，服务端只按 key 去重。若实现图省事把 key 里的 `clientKey` 换成
`contentId`，"两个不同 key 累计 2 枚"这条会立刻变红 —— 这是全专项最重要的一条断言。

## 三、反向验证（证明测试有判别力）

按 `AGENTS.md`：**先 commit 基线**，再注入，跑，再 `git checkout --` 还原。
每条注入都要指明**哪条用例必红**；红不了说明测试是假绿，重写。

| 注入 | 预期必红 |
|---|---|
| 去掉 `COMPLETE` 的 `owner` 条件 | 用例 3（并发同 key） |
| 把 `RELEASE` 改成"无条件写 FAILED" | 用例 1 的"断连后重发命中 DONE"分支 |
| 把"写快照"挪到 `copyBodyToResponse()` 之后 | 同上（断连场景） |
| 去掉指纹比对 | 用例 4 |
| 缺 key 时也写占位 | 用例 6（断言 `idem:*` 不存在） |
| 把 `ACQUIRE` 的 `FAILED ⇒ 可覆盖` 去掉 | 用例 5 |
| 注册表删掉一条 `KEYED` | §一 断言 2（`missing`） |
| 注册表留一条已删端点的键 | §一 断言 4（`stale`） |

**断连场景怎么测**：用单测直接构造 `HttpServletResponse`，让 `getOutputStream()` 抛 `IOException`，
断言 store 终态是 `DONE`（**断言终态，不断言调用顺序**——顺序是内部实现）。

## 四、对外契约

### 4.1 请求头与响应头

| 方向 | 名称 | 说明 |
|---|---|---|
| 请求 | `Idempotency-Key` | 可选。`[A-Za-z0-9._-]{1,64}` |
| 响应 | `Idempotent-Replayed: true` | 仅重放命中时出现；正常首次响应**不带**这个头 |

⚠️ 不要复用 `X-Request-Id`（服务端生成的 trace id，客户端不可用）。

### 4.2 错误码（3 个，均为新增）

| 码 | 状态 | 触发 | 客户端该怎么办 |
|---|---|---|---|
| `IDEMPOTENCY_KEY_INVALID` | 400 | key 超长 / 字符集非法 | 修 bug；**不要重试** |
| `IDEMPOTENCY_IN_PROGRESS` | 409 | 同 key 的上一次仍在处理，且短轮询耗尽；带 `Retry-After: 1` | **可重试**（同一 key） |
| `IDEMPOTENCY_KEY_CONFLICT` | 422 | 同 key 不同载荷 | 修 bug；**换个 key 重发或不要重试** |

`422` 是本仓第一个 `UNPROCESSABLE_ENTITY`，已确认允许扩展状态码集合，须在
[接口契约](../api/接口契约.md)登记。

### 4.3 前端重制时必须实现的行为（本期不改前端）

本期只交付服务端能力与这份契约，**不动 `static/**`**。前端重制时按下表实现，
**每一条缺失都会让机制白做**（写进 [写接口幂等](写接口幂等.md) §十四 的推翻条件）：

| 必须 | 原因 |
|---|---|
| 每次用户**意图**生成一个新 key（发一条评论 / 投一次币各一个） | 用"内容 id / 用户 id"当 key 会毁掉累加语义 |
| 重试**沿用**同一个 key，且**不换载荷** | 换载荷 ⇒ 422，等于把 bug 暴露给用户 |
| 重试触发条件包含**网络异常与超时**，不只 5xx | 最常见的成因是"响应丢了"，那时看到的是超时 |
| 重试窗口 **≤ 3 min** | 超过 `DONE` TTL 就没有保护了 |
| 把 `409 IDEMPOTENCY_IN_PROGRESS` 当**可重试**（按 `Retry-After`） | 否则"上一次还在跑"会被当成失败 |
| 把 `Idempotent-Replayed: true` 当正常成功处理 | 重放不是错误 |

### 4.4 欠账

`openapi.yaml` 本期**不声明** `Idempotency-Key`（需改 `OperationCustomizer` 给 4 个操作加 header 参数），
前端重制时一并补 —— 已登记为已知代价。

## 五、落地顺序

**不要一次上四条**：回归面太大，且上传会与既有的孤儿文件清理缠在一起。

| 步 | 端点 | 为什么这个顺序 | 完成判据 |
|---|---|---|---|
| 1 | `comment` | 单事务、JSON、响应体极小 ⇒ 最小闭环，先把 filter / 状态机 / 快照跑通 | 6 条用例 + 反向验证 1、2、3 |
| 2 | `coin` | 语义最特殊，靠"两个不同 key 累计 2 枚"防退化 | 再加上 §二 投币专属断言 |
| 3 | `video` / `post` | multipart：`PENDING` TTL 加长、无指纹、"早于解析"要有证明 | 再加上"无新文件落盘" |

`comment` 这一步只做**效果层**（不重复写 + 快照重放）。若响应体在此之前补上了新对象标识
（需求侧，另册登记），**契约变更要与机制同一步落**，避免"机制先上、重放却回 `{}`"的中间态。
