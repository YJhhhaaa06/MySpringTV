### 2.1 分辨率为什么不是 2560×1600（★ 更关键是 150% 缩放）

用户屏幕是 **2560×1600**；这些图是**浏览器内容区**，不是整屏：

- `2560×1398` = 带标签栏 / 地址栏的窗口（浏览器 chrome 约 202px）；
- `2560×1528` = 最大化后（chrome 约 72px）；
- `638×184` = 局部裁剪（卡片 hover）。

**命名里的尺寸 = 文件真实像素**（用 PIL 读 `Image.size` 得到）。不要拿 2560×1600 去推页面像素。

★ **这批 2560 图是 150% 缩放，不是 2560 CSS 视口**：B 站顶栏 64 CSS → **96 物理 px**
（`13-57/13-58` 两张实测），首页内容 2118 物理 → **1412 CSS**、卡片 400 → **266.7 CSS**、
搜索卡片 355 → **236.7 CSS**。⇒ **CSS 视口 = 1707×932**（2560/1.5、1398/1.5）。
**所有物理 px ÷1.5 才是 CSS**；把 400px 卡片直接抄进 `tokens.css` 会宽 1.5 倍。
（上一版 §2.2 的 1637 / 2000 / 2100 都是物理 px —— 1637 播放器 = 1091 CSS，不是 CSS 宽。）

### 4.1 拍 B 站（匿名）

⚠️ **必须在 `danger-full-access` 下跑**（Chrome 在沙箱里起不来）。

```powershell
$out = ".screenshots\bilibili-<日期>"
$chrome = "C:\Program Files\Google\Chrome\Application\chrome.exe"
& $chrome --headless=new --disable-gpu --hide-scrollbars --no-first-run `
  --user-data-dir="$out\_profile" --window-size=1600,1000 --virtual-time-budget=10000 `
  --screenshot="$out\home-1600.png" "https://www.bilibili.com/"
```

### 4.2 拍本仓（`dist` 上 Spring 或 Vite dev 都可以）

```powershell
$chrome = "C:\Program Files\Google\Chrome\Application\chrome.exe"
$out = (Resolve-Path ".screenshots\frontend-<日期>").Path
$prof = Join-Path $env:TEMP ("chrome-shot-" + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Force -Path $prof | Out-Null
& $chrome --headless=new --no-sandbox --disable-gpu --disable-dev-shm-usage --hide-scrollbars `
  --user-data-dir="$prof" --window-size=1600,1000 --virtual-time-budget=15000 `
  --screenshot="$out\home-1600.png" "http://localhost:8080/"
```

**需要登录态的页面**（收藏 / 稍后再看 / 历史 / 自己的空间）必须走 CDP：先开 `--remote-debugging-port=9222`，

一次性脚本在 `.tmp/`（不入库）；本轮脚本：`watchlater-e2e.mjs`（含登录态与写路径）、
`visual-calibration.mjs`（1600 与 1707×1.5 两套截图 + 实测列宽）。

## 五、截图坑（实测，按时间顺序）

1. **别把 Chrome 调用封成 PowerShell 函数 + `*>` 静默重定向** —— 会**静默失败**（无产物、退出码仍为 0）；
   用直接 `& $chrome …`，并检查 PNG 大小（真页面 ≥ 500 KB，404 / 验证码页只有几十 KB）。
2. **BV / UID 从搜索结果页 `--dump-dom` 里取**（`/video/(BV[0-9A-Za-z]{10})`、`space\.bilibili\.com/(\d+)`）；
   从首页正则取会捞到广告壳的假号 ⇒ 拍出 404。
3. 登录浮层是**未登录态常态**，对照时看浮层底下的真实布局。
4. ★ `--screenshot` 必须给**绝对路径**。相对路径会报 `Failed to write file …: 0x3`，**退出码仍是 0**。
5. ★ `--user-data-dir` 不能复用旧 profile（复用会 `exit 21` 且**无任何输出**）。每次在 `%TEMP%` 下新建。
6. ★ `--screenshot` + `--virtual-time-budget` 会在懒加载图片解码前收工 ⇒ 卡片封面截成**灰块**
   （不是 404，用 CDP 查 `img.complete/naturalWidth` 全是 true）。可信的产物图要走 CDP：
   等 `img.complete` 全真再 `Page.captureScreenshot`；或临时把 `loading="lazy"` 去掉再拍。
7. ★ **登录态截图拿不到匿名对照**：B 站历史页匿名只有登录墙、收藏页匿名会被落到空间主页；
   DSH 的 headless Chrome 是**独立 profile（没有用户的 cookies）**，所以需要用户手动补图（2026-10-26 即如此）。
8. ★ **2560 图不一定是 2560 CSS**：先量 B 站顶栏（64 CSS）确定缩放；这批是 **150%**（CSS 视口 1707×932，
   物理 ÷1.5）。把 400 物理 px 卡片直接抄进 CSS 会宽 1.5 倍。用 `--force-device-scale-factor=1.5
   --window-size=1707,932` 复拍，才能与用户图同尺度并排。
9. ★ **同一批图可能混了不同缩放 / 滚动位置**：`15-01-*` 动态详情图看起来与首页那批的缩放不同，
   本窗口只归档、不拿它量播放页；量哪一页之前先确认那一张的 `innerWidth`/DPR。
10. ★ **CDP 的 `Emulation.setDeviceMetricsOverride` 要重设后再 `Page.navigate`**：改设备参数不会自动重排
   已加载页面的媒体查询；本窗口的 `visual-calibration.mjs` 每次换视口后都重新导航。
11. ★ **`waitImages()` 必须自带超时**（2026-10-27 踩到）：等 `img.complete` 的 Promise 若有一张图
    既不 load 也不 error（或懒加载一直没触发），脚本会**永久挂住且没有任何输出**——
    加 `Promise.race([..., setTimeout(5000)])` 再截图；E2E 本身也要给每次 CDP 调用加超时。
