## 一、应用形态：MPA 外壳 + 应用内 SPA

**B 站网页版实测口径（2026-10-25）**：跨应用是**整页跳转**（首页 DOM 有 149 处 `target="_blank"`：
视频卡片指向 `www.bilibili.com/video/BV…`、UP 主指向 `space.bilibili.com/<uid>`，不同子域 = 不同文档）；
应用内是**客户端路由**（播放页分 P、空间页 tab、搜索页 tab/排序，URL 变化而不整页重载）。
我们照抄这个**混合**结构，而不是二选一。

| 入口 | 应用内路由（vue-router，history） | 主要接口 | 状态 |
|---|---|---|---|
| `index.html` | `/`、`/placeholder/:feature` | `GET /contents/recommended` | 已建 |
| `search.html` | `/search?keyword=&page=` | `GET /contents?keyword=` | 已建 |
| `video.html` | `/video/:id` | `GET /contents/{id}` + 互动 + 评论 + 进度 + `GET /users/{id}` | 已建（互动/评论/进度齐全） |
| `space.html` | `/space/:id`（tab / 翻页 / 夹用 query） | `GET /users/{id}` + 公开收藏夹 + 夹内条目 | 已建 |
| `favorites.html` | `/favorites`（`?folder=` / `?tab=later` / `?page=`） | `GET /favorite-folders` + `GET /favorites` + `GET /watch-later` + 两条 `DELETE` | 已建（2026-10-26） |
| `history.html` | `/history?page=` | `GET /history`（**只读**） | 已建（2026-10-26） |
| `upload.html` | `/upload` | `POST /contents/videos`、`POST /contents/posts` | 待建 |

- **跨应用**一律 `<a href="/video/92" target="_blank" rel="noopener">`：新标签、可中键、可复制链接。
- **应用内**每个入口一个 router 实例（`createWebHistory`）；切 tab 只改 URL、不重载。
- **页面之间不共享内存态**：`AppHeader` 等组件在每页各自 import（Vite 抽公共 chunk）；登录态从
  `localStorage` 读 token（后端是 `Authorization: Bearer`，不是 Cookie），每个应用自己
  `GET /users/me` 重建 —— **代价** = 每进一次应用多一次公共请求，换来与参考实现同构。
- ⚠️ **history 模式两侧都要 fallback**：dev/preview 由 `vite.config.ts` 的中间件把
  `/search` → `search.html`、`/video/<digits>` → `video.html`、`/space/<digits>` → `space.html`、
  `/placeholder/*` → `index.html`；生产由 Spring 的 `WebMvcConfig#addViewControllers` 做**同一张映射表**
  （**已落地 2026-10-26**，两者必须同步改）。用 **forward 不是 redirect**：地址栏 URL 不变，
  应用内 router 才能按真实路径匹配。
  ★ 转发用 `ViewController`（`viewControllerHandlerMapping`，处理器不是 `HandlerMethod`）
  而不是 `@Controller` ⇒ **不进端点登记簿、不进 spec、不需要 `@Public`**。
  资源根是构建产物的 `/assets/**`（不是旧 SPA 的 `/static/**`），它和 HTML 外壳都在
  `RateLimitFilter` 的跳过清单里（否则首屏会 **429 掉 CSS**），但页面里的 `/api/v1/**` 照常过闸。

## 二、类型三层（铁律）

```
openapi.yaml ──gen:api──▶ src/types/api.d.ts   生成、只读、入库（diff = 契约变更记录）
                          src/types/ui.ts       手写：页面期望形状，**允许含后端暂无的字段**
                          src/api/adapters/     纯函数 api → ui，缺口在此显式 fallback
```

- **组件只吃 `types/ui.ts`**，不许直接吃生成类型。例外：纯透传页（表单 / 详情只读页）。
- 缺口（后端暂缺的字段 / 端点）**只允许在 adapter 里 fallback**：不许在组件里散判断，更不许编数字。
- ⚠️ **生成类型会撒谎**：spec 把可空字段声明成"可缺省"，实际匿名响应会给显式 `null`
  ⇒ `coverUrl` / `durationSeconds` / `interaction` 一律按 `null` 兜底；**不要手改生成文件**顶掉这个差异。

## 四、页面 × 端点矩阵

| 面 | 端点 | 分页 / 形态 | 备注 |
|---|---|---|---|
| 顶栏登录 | `POST /sessions` → `GET /users/me` | — | token 存 `localStorage`；401 清 token 退化匿名 |
| 首页 | `GET /contents/recommended` | 固定 12 条、**无分页** | 不做无限滚动；「换一换」= 重新拉取（顺序每次不同） |
| 搜索 | `GET /contents?keyword=&page=&pageSize=` | **Page**（page / pageSize / total / totalPages） | `keyword` 空白会被后端 400 拒绝 |
| 播放页 | `GET /contents/{id}` | — | 详情侧**有**五个计数（与列表侧相反） |
| 播放页·互动 | `PUT|DELETE /contents/{id}/like`、`POST …/coins`、`POST|DELETE /favorites`、`PUT|DELETE /follows/{id}` | — | 投币是 `KEYED`（带幂等键）；收藏夹列表走 `GET /favorite-folders` |
| 播放页·评论 | `GET /contents/{id}/comments`（Page）+ `GET /comments/{id}/replies`（Cursor）+ `POST|DELETE /comments` + `PUT|DELETE /comments/{id}/like` | **两种分页并存** | 主楼 `total` = 主楼条数；楼中楼 `total` = `reply_count` |
| 播放页·进度 | `POST …/play`、`PUT|GET …/progress`、`POST /history/flush` | — | **客户端行为以 [history-客户端契约](../domain/history/history-客户端契约.md) 为准**，不在本篇 |
| 播放页·侧栏 | `GET /users/{id}` | 作品列表内嵌 Page | 失败不阻塞页面（侧栏降级为空） |
| 播放页·相关 | `GET /contents/recommended` | 固定 12 条 | 取前 6 条、剔除当前内容 |
| 空间页 | `GET /users/{id}?page=&pageSize=` | 一个端点装"资料 + 作品一页" | 翻页也走它 |
| 空间页·收藏 | `GET /users/{id}/favorite-folders` + `GET /favorite-folders/{id}/items` | 夹列表无分页；条目 **Page** | 只返回**公开**夹 |
| 收藏页 | `GET /favorite-folders` + `GET /favorites?folderId=` + `GET /watch-later` | **Page** | 我的夹（含私密）；条目缺 authorId / 时长（GAP-16） |
| 收藏页·写 | `DELETE /favorites?folderId=&contentIds=`、`DELETE /watch-later?contentIds=` | — | 乐观移除 + 成功后静默重读；失效条目也删得掉（按 contentId 定位） |
| 历史页 | `GET /history` | **Page** | 版式 = **左侧时间轴 + 4 列卡片网格**（封面「已看/总长」角标）；只读；无删除/清空（GAP-19）、无筛选/搜索（GAP-20）、无记录开关（GAP-21） |

- 另一类分页是 **Cursor**（楼中楼 `GET /comments/{id}/replies`）；两种分页在组件层**显式分开**，不强行统一。
- **互动态维度**按"哪个面读哪几维"：详情三维 · `/feed` 与 `/users/{id}` `{赞}` · recommended `{关注}` ·
  搜索 0 维；`null` 表示**本面不查**（≠ `false`）。口径见 [favorite](../domain/favorite/favorite.md) §六。

## 五、登录态

- token 只存 `localStorage`（`token.ts` 是唯一落点），请求层统一加 `Authorization: Bearer`。
- **不装 Pinia**：顶栏只需要"有没有登录 + 昵称首字"，模块级 `reactive` 足够；等跨页共享真出现再谈。
- 每个应用挂载后 `restoreSession()`：无 token → 匿名；有 token → `GET /users/me`；
  401 / 403 → 清 token 退化匿名（不把用户卡在"看起来登录了但什么都点不了"）。
  ★ 并发调用复用**同一个请求**（入口与页面都会调它，不合并等于每个页面白花一枚限流令牌）。
- ★ **登录是"动作级"闸门，不是页面级跳转**：需要身份的动作先 `await requireLogin()`
  （`auth/loginPrompt.ts`），弹浮层并阻塞到用户给出结果；**登录成功后这一次点击的意图继续执行**
  —— B 站也是这么做的，回调式写法会把一条流程劈成两段，中间态正是 bug 温床。
- ★ **整页都属于"我"的页面走「页面级身份态」**（收藏 / 历史，2026-10-26）：匿名请求必然 401、
  没有"匿名可见的一部分" ⇒ 先 `await restoreSession()`，匿名渲染「登录后查看」+ 登录按钮；
  按钮本身仍是**动作级** `requireLogin()`，登录成功后 watcher 自动装载。
  分界：页面**有**匿名可见内容（播放页 / 空间页）⇒ 动作级；整页无匿名可见内容 ⇒ 页面级。
- 未登录**不隐藏页面**，只在需要身份的动作上触发登录（收藏 / 历史是例外：整页内容就是身份本身）。

## 六、降级约定（缺口时怎么表达）

| 缺口 | 表达方式 | 禁止 |
|---|---|---|
| 列表 VO 无任何计数 | 卡片**不渲染**播放量角标 | 编数字 / 为每张卡片回源详情 |
| 无弹幕域 | 卡片不显示弹幕数；播放页放一条"永远占位"说明 | 放假弹幕 / 假计数 |
| 无运营 banner 端点 | 用推荐流前 3 条**有封面的**做轮播，并**从网格剔除**；不足就不渲染 | 编活动图 / 同一内容轮播与网格重复 |
| 无头像字段 | 昵称首字 + 渐变底 | 引用不存在的头像 URL |
| 评论无 `createTime` | **不显示时间**（`timeText` 恒空串） | 写"刚刚"顶上（是编数字的变体） |
| 评论无排序参数 | **不渲染排序条**；发布后跳末页并高亮新评论 | 前端假排序 |
| 历史无删除 / 清空端点（GAP-19） | **不渲染**删除与清空按钮；失效行保留观看时间 | 摆一个点不动的删除图标 |
| 历史无筛选 / 搜索参数（GAP-20） | **不渲染** tabs、搜索框与「更多筛选」（只按时间倒序） | 前端假筛选 / 假搜索 |
| 无「记录浏览历史」开关（GAP-21） | **不渲染**开关（历史始终记录） | 摆一个点不动的开关，暗示能暂停记录 |
| 内容缺总时长（`durationSeconds=null`） | 历史只显示「看到 mm:ss」，**不画进度条**（比例算不出来就不猜） | 用 0% 或 100% 假装有进度 |
| 空间无 banner / 签名 / 资料字段 | 低饱和渐变 banner；资料卡只放真计数 | 编签名 / 编地区 |
| 空间无「动态 / 合集 / 最近点赞」端点 | **不渲染这些 tab** | 摆点不动的 tab |
| 「代表作」无字段（B 站是 UP 自选） | 第一页把**最新 3 条**放大卡，标题写「最新投稿」 | 把"最新"叫成"代表作" |
| 收藏条目缺 `authorId` / 时长 / 发布时间 | 作者渲染成纯文本、不显示时长与日期；`invalid` 打「已失效」灰角标 | 拿收藏时间冒充发布日期 / 拼死链 |
| 匿名不能上报播放 | **整段不接**进度上报（端点全要登录） | 打一串 401 |
| 搜索无 `type` / 排序参数 | 只留「综合」tab；**不渲染排序条** | 前端假装筛选 / 排序 |
| 无分类端点 | 18 分区前端常量，点击进占位路由 | 假装有分区页 |
| 封面缺失 / 404 | 灰底占位块（`@error` 兜底） | 破图 |
| 时长缺失 | 不渲染时长角标 | 编时长 |

**占位分两态**（注册表在 `constants/features.ts`）：

- `never`：本仓设计上不做（弹幕 / 番剧 / 直播 / 会员购 / 游戏中心 / 分区页…）⇒ 永远占位、**不进「等后端」清单**；
- `pending`：后端接口已有、只差页面（收藏 / 历史 / 动态 / 投稿 / 后台）⇒ 后续窗口交付。
- ★ 页面一旦交付就**从注册表删掉**（`space` 于 2026-10-25 删除），否则它会永远显示"后续窗口"——
  注册表是"还没做的清单"，不是"历史清单"。

## 八、请求层与写接口约定

**唯一入口**：`src/api/http.ts`（四个动词 `getJson/postJson/putJson/deleteJson`）。它只做四件事：
信封解包（`{code,msg,data}` → `data` / `ApiError`）、`Authorization: Bearer`、`204` 视为成功、
把 `Retry-After` 变成 `ApiError.retryAfterSeconds`。**返回类型由 spec 的 `paths` 推导**，不手写 DTO。

| 约定 | 做法 | 反例（别这么写） |
|---|---|---|
| 写动词 | 一律走 `http.ts`；请求体/响应类型来自生成层 | 页面里自己 `fetch` + 自己判信封 |
| **幂等键** | 只有 `KEYED` 端点需要（评论 / 投币 / 两条投稿）。键在**用户按下按钮**时取，同一草稿的重试**复用**，草稿一改就作废 | 每次请求新生成（重试 = 两条评论）；让请求层自动加（掩盖"这个端点要不要幂等"） |
| **写后对齐** | 乐观更新 → 失败回滚 → 成功后用**服务端权威值**再对齐（详情 / 资料重读） | 只乐观不回滚；或回滚后不回读（并行请求会把旧值写回去） |
| **登录闸门** | 动作级 `await requireLogin()`；登录成功后这一次点击继续执行 | 页面级跳登录页 / 弹窗关掉就丢操作 |
| **不重试的** | `400/401/403/404` 是确定失败：停手并说清楚（进度上报据此 stop） | 循环重试把 429 也刷出来 |
| **可重试的** | `429` 吃 `Retry-After` 说人话（"N 秒后再试"）；`5xx` 给页面级「重试」按钮 | 静默重试 / 只给"回首页" |
| **本地存储** | 只有两处：`myspringtv.token`（`auth/token.ts`，唯一落点）与 `history:pending:{id}`（崩溃补偿） | 把页面状态塞 localStorage 冒充缓存 |

- **计数一律搬数字、不预先格式化**（`types/ui.ts` 的 `Count`）：万/亿是展示口径，且互动态要乐观加减。
- **三态**：`interaction` 整块为 `null` = 匿名（本面不查）；字段为 `null` = 这一维没查。
  `null ≠ false`，归一成 `false` 会让"我不知道"画成"我知道"。
- 展示格式化器集中在 `api/adapters/format.ts`（纯函数，可单测）；组件可以直接 import 它。

### 状态放哪（本窗口实测过的三种）

| 规模 | 放哪 | 例 |
|---|---|---|
| 一个页面内的行为机 | `composables/use*.ts`（`ref`/`reactive` 都在里面，页面只做布局） | `useVideoInteractions`、`usePlaybackProgress` |
| 跨组件、跨页共享的登录态 | 模块级 `reactive`（`auth/session.ts`） | 顶栏头像 / 硬币余额 |
| 与 DOM 无关的规则（可单测） | `src/player/`、`src/api/adapters/` 纯函数 | 进度节奏 / 退避 / 续播基线 |

**不装 Pinia** 的理由仍然成立：需要跨页共享的只有登录态，一个模块级对象足够；等"收藏页与播放页要共享同一份收藏夹列表"真正出现时再谈。

## 九、边界与去向（机制外链）

| 不在本篇 | 去向 |
