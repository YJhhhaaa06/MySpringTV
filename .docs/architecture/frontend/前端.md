## 一、应用形态：MPA 外壳 + 应用内 SPA

**B 站网页版实测口径（2026-10-25）**：跨应用是**整页跳转**（首页 DOM 有 149 处 `target="_blank"`：
视频卡片指向 `www.bilibili.com/video/BV…`、UP 主指向 `space.bilibili.com/<uid>`，不同子域 = 不同文档）；
应用内是**客户端路由**（播放页分 P、空间页 tab、搜索页 tab/排序，URL 变化而不整页重载）。
我们照抄这个**混合**结构，而不是二选一。

- **跨应用**一律 `<a href="/video/92" target="_blank" rel="noopener">`：新标签、可中键、可复制链接。
  **唯一例外**：播放页「相关推荐」同标签 SPA（不新开标签，见 §四 / `task/CURRENT_FRONTEND.md`「客户端行为口径」）。
- **应用内**每个入口一个 router 实例（`createWebHistory`）；切 tab 只改 URL、不重载。
- **页面之间不共享内存态**：`AppHeader` 等组件在每页各自 import（Vite 抽公共 chunk）；登录态从
  `localStorage` 读 token（后端是 `Authorization: Bearer`，不是 Cookie），每个应用自己
  `GET /users/me` 重建 —— **代价** = 每进一次应用多一次公共请求，换来与参考实现同构。
- ⚠️ **history 模式两侧都要 fallback**：dev/preview 由 `vite.config.ts` 的中间件把
  `/search` → `search.html`、`/video/<digits>` → `video.html`、**`/opus/<digits>` → `opus.html`**、
  `/space/<digits>` → `space.html`、`/favorites` → `favorites.html`、`/watchlater` → `favorites.html`（同一入口、独立路由）、
  `/history` → `history.html`、`/dynamic` → `dynamic.html`、**`/creator` → `creator.html`**（含 `/creator/manage`、`/creator/edit/<digits>`，2026-10-29）、`/placeholder/*` → `index.html`；生产由 Spring 的
  `WebMvcConfig#addViewControllers` 做**同一张映射表**（**已落地 2026-10-26；`/dynamic` 与 `/opus` 2026-10-27 补齐**、
  **`/creator` 2026-10-28、创作中心两个子路由 2026-10-29 补齐**，两者必须同步改）。
  用 **forward 不是 redirect**：地址栏 URL 不变，应用内 router 才能按真实路径匹配。
  ★ 转发用 `ViewController`（`viewControllerHandlerMapping`，处理器不是 `HandlerMethod`）
  而不是 `@Controller` ⇒ **不进端点登记簿、不进 spec、不需要 `@Public`**。
  资源根是构建产物的 `/assets/**`（不是旧 SPA 的 `/static/**`），它和 HTML 外壳都在
  `RateLimitFilter` 的跳过清单里（否则首屏会 **429 掉 CSS**），但页面里的 `/api/v1/**` 照常过闸。

## 二、类型三层（铁律）

```
openapi.yaml ──gen:api──▶ src/types/api.d.ts   生成、只读、入库（diff = 契约变更记录）
                          src/types/ui.ts       手写：页面期望形状，**允许含后端暂无的字段**
                          src/api/adapters/     纯函数 api → ui，缺口在此显式 fallback
```

- **组件只吃 `types/ui.ts`**，不许直接吃生成类型。例外：纯透传页（表单 / 详情只读页）。
- 缺口（后端暂缺的字段 / 端点）**只允许在 adapter 里 fallback**：不许在组件里散判断，更不许编数字。
- ⚠️ **生成类型会撒谎**：spec 把可空字段声明成"可缺省"，实际匿名响应会给显式 `null`
  ⇒ `coverUrl` / `durationSeconds` / `interaction` 一律按 `null` 兜底；**不要手改生成文件**顶掉这个差异。

### 封面裁剪与预览（2026-10-29，投稿 / 编辑共用）

- **为什么必须有**：本仓封面展示位**全是 16:9 + `object-fit: cover`**（首页 / 搜索 / 历史 / 动态卡片、
  播放页海报区），后端**不校验比例** ⇒ 不裁就上传，等于把"切哪一刀"交给展示端，作者在上传时看不见。
- **裁什么**：固定 **16:9**（不是可选项列表）。16:10 的侧栏相关推荐由预览里那一格显式呈现
  （会在 16:9 的封面上**再切掉左右各约 5%**）——把"唯一一个不等比的位置"摆在作者眼前，而不是藏起来。
- **产物**：`1280×720` JPEG（质量 0.92、先铺白底，PNG 透明区不落黑块）；文件名 `photo.png → photo-cover.jpg`
  （`coverFileName` 对已裁过的名字幂等）。名字与 `lastModified` 参与 `fileKey` / `draftSignature`
  ⇒ 换封面必然换幂等键指纹，不会复用旧 URL 或旧键。
- **几何是纯函数**（`api/coverCrop.ts`）：状态 = `zoom`（1..4）+ **归一化中心**（`0..1`），与舞台尺寸无关
  ⇒ 拖窗口 / 改宽度不会把构图挪走。`dragBy` 的位移换算、`zoomAround` 的"锚点下像素不动"、
  `cropRect` 的"恒 16:9 且不越界"都由 `coverCrop.test.ts` 按等式复算（组件里没有第二套数学）。
- **交互口径**：**选封面 = 立刻进裁剪**；取消 = 这次没选（不产生半成品）。「重新裁剪」永远从**来源原图**开始
  （从已裁产物再裁会越裁越小）；编辑页的来源是**线上封面**（同源 `fetch` → blob，canvas 不被 taint）。
- **已知代价**：编辑页重裁会先 `POST /uploads/cover` 拿新 URL ⇒ 不保存就让旧文件成孤儿
  （与"换源"同一笔账，后端离线脚本回收）；裁剪是不可逆的重编码（原图不作为媒体清单的一部分保留）。

## 五、登录态

- token 只存 `localStorage`（`token.ts` 是唯一落点），请求层统一加 `Authorization: Bearer`。
- **不装 Pinia**：顶栏只需要"有没有登录 + 昵称首字"，模块级 `reactive` 足够；等跨页共享真出现再谈。
- 每个应用挂载后 `restoreSession()`：无 token → 匿名；有 token → `GET /users/me`；
  401 / 403 → 清 token 退化匿名（不把用户卡在"看起来登录了但什么都点不了"）。
  ★ 并发调用复用**同一个请求**（入口与页面都会调它，不合并等于每个页面白花一枚限流令牌）。
- ★ **签到状态不落 localStorage**（2026-10-29）：`CurrentUserVM.signedToday` 直接来自 `/users/me`
  （后端 `last_sign_date == SiteTime.today()`，上海自然日）。
  考虑过"浏览器存上次签到时间 + 前端比日期"——**否决**，判据：它是**"某账号在某自然日"的状态，不是"这个浏览器"的**。
  落本地会出现三种立刻可复现的错：换号后按钮仍灰（所以还得登出清缓存）、跨设备撒谎（手机签过、桌面亮着）、
  本机时钟可改且日期换算要在浏览器里重写一遍（日历口径后端已收敛在 `SiteTime`）。
  ⇒ 签到成功后的状态迁移在 `auth/session.ts#markSignedIn`（任何一次 200 回执都算"今天已签"，`credited` 只决定文案），
  组件层只读它；**换号不需要清任何缓存**。
- ★ **登录是"动作级"闸门，不是页面级跳转**：需要身份的动作先 `await requireLogin()`
  （`auth/loginPrompt.ts`），弹浮层并阻塞到用户给出结果；**登录成功后这一次点击的意图继续执行**
  —— B 站也是这么做的，回调式写法会把一条流程劈成两段，中间态正是 bug 温床。
- ★ **整页都属于"我"的页面走「页面级身份态」**（收藏 / 历史 / 稍后再看，2026-10-26；**动态页 2026-10-27**）：
  匿名请求必然 401、没有"匿名可见的一部分" ⇒ 先 `await restoreSession()`，匿名渲染「登录后查看」+ 登录按钮；
  按钮本身仍是**动作级** `requireLogin()`，登录成功后 watcher 自动装载。
  分界：页面**有**匿名可见内容（播放页 / 空间页）⇒ 动作级；整页无匿名可见内容 ⇒ 页面级。
- ★ **空间页的「关注 / 粉丝」是两个页面级身份态子面**（不是整页）：空间头 / 主页 / 收藏匿名可见，
  但两个关系列表都要登录（B 站同样：`api.bilibili.com/x/relation/followings` 匿名返回 `-101`）
  ⇒ 面板内部渲染「登录后查看」，**不把 401 画成空列表**；登录成功后面板自己的 session watcher 装载
  （深链直接落在 `?tab=following` 也不会停在空白）。
- **图文详情页是"匿名可见 + 动作级闸门"**（与播放页同类）：正文 / 图片 / 评论匿名可看；点赞 / 收藏 / 评论
  走 `requireLogin()`（登录成功后这一次点击继续执行）。它**不是**页面级身份态（没有"整页都属于我"）。
- ★ **创作中心投稿页是页面级身份态**（2026-10-28）：两条投稿端点都要登录，整页没有匿名可见内容
  ⇒ 先 `restoreSession()`，匿名渲染「登录后投稿」，按钮走 `requireLogin()`；表单用 `v-show` 保持挂载
  ⇒ 登录成功后**草稿不丢**（v-if 会把已填内容一起卸载）。
- 未登录**不隐藏页面**，只在需要身份的动作上触发登录（收藏 / 历史 / 动态是例外：整页内容就是身份本身）。

## 六、降级约定（缺口时怎么表达）

| 缺口 | 表达方式 | 禁止 |
|---|---|---|
| 列表**没有**某一维计数 / 图文播放量 | `null` ⇒ **不渲染**该角标；视频卡显示 `playCount`（GAP-01）；图文 `play_count` 结构性恒 0 ⇒ **不渲染**（GAP-05） | 编数字 / 为每张卡片回源详情 / 把图文的 0 画成「浏览 0」 |
| 无弹幕域 | 卡片不显示弹幕数；播放页放一条"永远占位"说明 | 放假弹幕 / 假计数 |
| 无运营 banner 端点 | 用推荐流前 3 条**有封面的**做轮播，并**从网格剔除**；不足就不渲染 | 编活动图 / 同一内容轮播与网格重复 |
| 无头像字段 | 昵称首字 + 渐变底 | 引用不存在的头像 URL |
| 评论时间（GAP-12 已补回） | 按 **web 端评论区口径**：同一自然日 `刚刚` / `N分钟前` / `N小时前`，跨自然日 `YYYY-MM-DD HH:MM`（恒带年）；日界与呈现均按**用户本地时区**（不按 Asia/Shanghai 硬算）；"现在"取**服务器时钟**（HTTP `Date` + `performance.now()` 单调锚点，见 `serverClock.ts`），不取浏览器时钟；`createTime` 缺失（存量缓存 / 脏数据）⇒ **不渲染节点** | 用 24 小时口径冒充 web 端 / 写"刚刚"兜空值 / 用浏览器时钟算相对时间 |
| 评论无排序参数 | **不渲染排序条**；发布后跳末页并高亮新评论 | 前端假排序 |
| 历史无删除 / 清空端点（GAP-19） | **不渲染**删除与清空按钮；失效行保留观看时间 | 摆一个点不动的删除图标 |
| 历史无筛选 / 搜索参数（GAP-20） | **不渲染** tabs、搜索框与「更多筛选」（只按时间倒序） | 前端假筛选 / 假搜索 |
| 无「记录浏览历史」开关（GAP-21） | **不渲染**开关（历史始终记录） | 摆一个点不动的开关，暗示能暂停记录 |
| 内容缺总时长（`durationSeconds=null`） | 历史只显示「看到 mm:ss」，**不画进度条**（比例算不出来就不猜） | 用 0% 或 100% 假装有进度 |
| 空间无 banner / 签名 / 资料字段 | 低饱和渐变 banner；资料卡只放真计数 | 编签名 / 编地区 |
| 空间无「动态 / 合集 / 最近点赞」端点 | **不渲染这些 tab** | 摆点不动的 tab |
| 动态流无 `type` 筛选（GAP-23） | **不渲染**「全部 / 视频投稿 / 列」tabs（只按时间倒序） | 前端假筛选（只筛当前页 = 分页口径坏掉） |
| 动态流无发布框 / 无转发域 / 无热搜 | 不渲染发布框、转发按钮、热搜与社区中心；右栏用**我关注的人**（真接口）填位 | 摆一个点了没反应的发布框 / 编热搜榜 |
| 关注/粉丝 `FollowUserVO` 无头像 / 签名 / 分组（GAP-25） | 首字头像 + 名字 + 关注按钮；不渲染签名 / 分组 / 排序 / 搜索 / 批量操作 | 写「这个人很神秘」冒充签名 / 编等级 |
| 图文详情无投币（GAP-26） | **不渲染**硬币按钮（点赞 / 收藏 / 分享 / 评论保留） | 摆一个必然 400 的硬币按钮 |
| 图文详情无「赞与转发」（GAP-27） | **不渲染**该 tab；只留「评论 N」 | 摆一个点不动的 tab |
| 列表图文无封面 / 有图无封面（GAP-28） | **文字卡面**（真 `description`；空简介 / 后端占位 `-` → 中性「图文动态」）；不逐卡回源 | 用 TV 图标 / 编文字 / 为卡面回源详情取首图 |
| 收藏夹图文没有 `type`（GAP-16） | 卡片先落 `/video/{id}`，详情取到 `isPost` 后 `replace('/opus/{id}')` | 每卡回源 / 把图文画成视频卡 |
| 首页推荐含图文（GAP-29） | 保留图文（与移动端一致）；卡面按 type 走 `/opus` | 为像 web 首页在前端假过滤（只筛当前 12 条） |
| 「代表作」无字段（B 站是 UP 自选） | 第一页把**最新 3 条**放大卡，标题写「最新投稿」 | 把"最新"叫成"代表作" |
| 收藏条目缺 `authorId` / 时长 / 发布时间 | 作者渲染成纯文本、不显示时长与日期；`invalid` 打「已失效」灰角标 | 拿收藏时间冒充发布日期 / 拼死链 |
| **稍后再看"是否已在池中"不可知** | 卡片 / 播放页初始**一律显示「加入」**；同一 URL 内点过才显示「取消」；刷新 / 换页即忘 | 每张卡片回源状态 / 把"不知道"画成"未加入"并禁用 |
| 匿名不能上报播放 | **整段不接**进度上报（端点全要登录） | 打一串 401 |
| 搜索类型 / 排序（GAP-10 已销账） | tab 与排序条都是真接口；**图文 tab 不渲染「最多播放」**（`play_count` 恒 0） | 把图文 `PLAY` 当有效排序 / 前端假筛选 |
| 无分类端点 | 18 分区前端常量，点击进占位路由 | 假装有分区页 |
| 投稿页无标签 / 创作声明 / 活动 / 定时发布 / 合集 / 商业推广 / 存草稿（**本仓无域**） | **不渲染**这些字段与按钮；顶部只留「视频投稿 / 图文投稿」两个 tab | 摆一个点不动的控件 / 编标签 / 摆 4 个无域投稿 tab |
| 投稿分区只有 **0~9 十项**（不是首页 18 频道） | `constants/categories.ts` 固定 10 项，与 `CHANNELS` 分开 | 拿 18 频道当 `categoryId`（后端只收单个数字字符） |
| 投稿无草稿 / 审核态（`content` 没有状态列） | 成功后只显示「已发布」；不渲染筛选 tabs | 编「审核中 / 未通过」 |
| 封面缺失 / 404 | 灰底占位块（`@error` 兜底） | 破图 |
| 封面比例不是 16:9（后端**不校验**比例） | 投稿 / 编辑页**强制裁剪**（16:9 舞台 + 三处真实展示位预览）；裁完才进草稿 | 直接上传原图、靠 `object-fit` 黑盒切；或前端"帮"用户裁成某个非 16:9 比例 |
| 时长缺失 | 不渲染时长角标 | 编时长 |

> ⚠️ **服务器时钟的前提**：`Date` 响应头必须可读。当前是同源部署（Spring 直出 static / Vite proxy），
> 跨源部署需服务端 `Access-Control-Expose-Headers: Date`；读不到时 `syncServerClock` 静默跳过 ⇒
> 退化成"全部按浏览器时钟"（正是要避免的症状，且不报错）。

★ **稍后再看的"是否已在池中"：不查、不猜、只记本页**
后端**刻意没有**状态查询端点（`favorite.md` §六 红线：不新增 status 端点、不塞进 `interaction`）。
所以前端用 **URL 作用域的内存记忆**（`common/watchLaterSession.ts`）：加入成功时把 `(contentId, pathname+search)`
记进模块级 `reactive(Map)`；`isAdded` 只在**同一 URL** 为真；刷新 / 换路由即忘。
这**不是**降级凑合，而是复刻 B 站 2026-10-26 实测行为 —— 同一页认识刚加入的视频、不刷新可取消；
换了页面就不认识，自然也无法在卡片上取消。**禁止**为了"显示已在池中"去逐卡回源
`GET /watch-later`（一个列表页 N 次请求）或编一个本地假状态。

**占位分两态**（注册表在 `constants/features.ts`）：

- `never`：本仓设计上不做（弹幕 / 番剧 / 直播 / 会员购 / 游戏中心 / 分区页…）⇒ 永远占位、**不进「等后端」清单**；
- `pending`：后端接口已有、只差页面（收藏 / 历史 / 动态 / 投稿 / 后台）⇒ 后续窗口交付。
- ★ 页面一旦交付就**从注册表删掉**（`space` 于 2026-10-25 删除），否则它会永远显示"后续窗口"——
  注册表是"还没做的清单"，不是"历史清单"。

## 八、请求层与写接口约定

**唯一入口**：`src/api/http.ts`（四个动词 `getJson/postJson/putJson/deleteJson`）。它只做四件事：
信封解包（`{code,msg,data}` → `data` / `ApiError`）、`Authorization: Bearer`、`204` 视为成功、
把 `Retry-After` 变成 `ApiError.retryAfterSeconds`。**返回类型由 spec 的 `paths` 推导**，不手写 DTO。

| 约定 | 做法 | 反例（别这么写） |
|---|---|---|
| 写动词 | 一律走 `http.ts`；请求体/响应类型来自生成层 | 页面里自己 `fetch` + 自己判信封 |
| **幂等键** | 只有 `KEYED` 端点需要（评论 / 投币 / **投稿 `POST /contents`**）。键在**用户按下按钮**时取，同一草稿的重试**复用**，草稿一改就作废 | 每次请求新生成（重试 = 两条评论）；让请求层自动加（掩盖"这个端点要不要幂等"） |
| **写后对齐** | 乐观更新 → 失败回滚 → 成功后用**服务端权威值**再对齐（详情 / 资料重读） | 只乐观不回滚；或回滚后不回读（并行请求会把旧值写回去） |
| **登录闸门** | 动作级 `await requireLogin()`；登录成功后这一次点击继续执行 | 页面级跳登录页 / 弹窗关掉就丢操作 |
| **不重试的** | `400/401/403/404` 是确定失败：停手并说清楚（进度上报据此 stop） | 循环重试把 429 也刷出来 |
| **可重试的** | `429` 吃 `Retry-After` 说人话（"N 秒后再试"）；`5xx` 给页面级「重试」按钮 | 静默重试 / 只给"回首页" |
| **本地存储** | 只有两处：`myspringtv.token`（`auth/token.ts`，唯一落点）与 `history:pending:{id}`（崩溃补偿） | 把页面状态塞 localStorage 冒充缓存 |
| **上传与提交分离**（2026-10-29） | 文件走 `postForm` 打到 `POST /uploads/{type}`（XHR、**10 分钟**超时、`upload.onprogress`、不手设 `Content-Type`），拿到 URL 再 `postJson` 提交清单；信封 / Bearer / `Retry-After` 与四动词**共用 `parseEnvelope`** | 页面自己 `fetch` + 自己判信封 / 手拼 boundary / 把 1 万字简介拼进 URL |
| **重试不重传**（2026-10-29） | `AssetUploadPool` 在**一次提交意图内**记住"文件 → URL"，重试复用同一 URL | 重试时重新上传：幂等指纹含 body，URL 一变就 409 `IDEMPOTENCY_KEY_CONFLICT`（"重试"变成新失败） |
| **编辑保存**（2026-10-29） | 恒提交**整份** `media` 清单（顺序即 sort）+ `title`；脏判定驱动按钮（没有改动就不发 `PUT`） | 只发改动的字段：`media` 缺省 = 不动媒体（换序/删图静默失效）、`title` 缺省 = 400「标题不能为空」 |

- **会乐观加减的计数搬数字**（`types/ui.ts` 的 `Count`）；**只读展示**（播放量）由 `format.ts` 预格式化，
  组件不重复实现万/亿。两者都用 `null` 表示"本面没给"，不假装 0。
- **列表卡的写后对齐**：动态卡点赞先乐观加减，成功后回读 `GET /contents/{id}/like-count`
  （一个裸数字）覆盖成权威值 —— 比"重拉整页 12 张卡 + 三个计数"便宜，且不需要把整页状态重置。
- **三态**：`interaction` 整块为 `null` = 匿名（本面不查）；字段为 `null` = 这一维没查。
- ★ **编辑面三条已知代价**（2026-10-29，都是**接受**而非待办）：
  1. **未保存的新上传会留孤儿文件**：换源/加图先 `POST /uploads/{type}`，用户放弃编辑则文件无主
     （后端由离线脚本按"磁盘有、库无引用"回收；**不进请求事务**）。换成"保存时才上传"会让保存
     变成一个不可中断的长事务式操作（视频可能传 50MB），代价更大。
  2. **稿件列表 = 公开主页的作品页**：没有创作者专用端点，所以**没有**草稿 / 审核态 / 删除入口，
     且翻页会顺带重读一次资料（与空间页同口径）。补真端点属于后端契约批次（GAP 台账另开）。
  3. **编辑没有并发冲突保护**：两个标签页同时编辑同一条稿 → 后保存的整份覆盖先保存的（LWW）。
     加 `version`/`update_time` 前置条件要改 `PUT` 契约 + 加一列，收益（单人创作者极少并发）＜成本，
     **刻意不做**；真要做得先有"谁改了什么"的审计需求。
- **长按换序为什么不是拖拽**：触屏上拖拽必须 `touch-action:none`，会把"想滚动页面"变成"把图拖走"；
  而交换是**离散操作**（选中 → 点目标），中间态只有一个"选中了哪一张"，还能落成纯函数 `swapImages` 被单测覆盖。
  长按阈值 420ms、移动超 10px 取消计时（= 用户其实在滚页面）；鼠标/键盘用户直接点击即选中，Esc 取消。
  `null ≠ false`，归一成 `false` 会让"我不知道"画成"我知道"。
- 展示格式化器集中在 `api/adapters/format.ts`（纯函数，可单测）；组件可以直接 import 它。

### 状态放哪（本窗口实测过的三种）

| 规模 | 放哪 | 例 |
|---|---|---|
| 一个页面内的行为机 | `composables/use*.ts`（`ref`/`reactive` 都在里面，页面只做布局） | `useVideoInteractions`、`usePlaybackProgress`、`useWatchLaterAction` |
| 跨组件、跨页共享的登录态 | 模块级 `reactive`（`auth/session.ts`） | 顶栏头像 / 硬币余额 |
| 同一文档内、跨组件的**临时记忆** | 模块级 `reactive(Map)`，**URL 当作用域**；不落存储 | `common/watchLaterSession.ts`（稍后再看"刚加入"） |
| 与 DOM 无关的规则（可单测） | `src/player/`、`src/api/adapters/` 纯函数 | 进度节奏 / 退避 / 续播基线 |

**不装 Pinia** 的理由仍然成立：需要跨页共享的只有登录态，一个模块级对象足够；等"收藏页与播放页要共享同一份收藏夹列表"真正出现时再谈。
