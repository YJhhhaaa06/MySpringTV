feat(slice-S5b): 迁移 comment 读路径 + CommentCache + /comment/show /comment/replies

S5 的第二段：comment 读路径。这段是 S2 显式划出去的（CM-3 记了理由与补回位置），
本提交兑现，并把 S2/S3 裁剪掉的两处"提交后失效"补回。

## 交付端点
- `GET /comment/show`（缺省全量数组 / 传分页参数则信封；**实现在 ContentService**）
- `GET /comment/replies`（按主楼展开，分页信封）

## 主要新增
- `comment/cache/CommentCache`（744 行 TV → 精简版）：**T10-A 两键组**
  （roots LIST + replies HASH + count String + 空标记）、**窗口装载**（水位不足才按 keyset 追加）、
  楼中楼按主楼懒载 + **前 K=2 预览**（缓存与响应同源）、失效重映射（整组 / 定向 HDEL）。
- `comment/cache/CommentRedisOps`：LIST/HASH 命令层（协议层已上移 RedisOps）。
- `comment/dao/CommentDao` +7 读方法、CommentMapper 的 `commentCacheMap` + 8 条语句。
- `comment/model/{cache/CommentCacheDTO, vo/CommentVO}`。
- `comment/event/{CommentCacheChangedEvent, CommentCacheChangedListener}`（AFTER_COMMIT）。
- `CommentController` 两个 GET（分页归一走 common/PageParams）。

## ★ 补回 S2/S3 的裁剪（这是本提交的纪律落点）
- **S2/CM-3**：`CommentService.addComment` / `doDeleteComment` 的事务后 3 行失效，
  改为在事务内**发事件**、由监听器在 AFTER_COMMIT 执行（并保留 TV 的 T34/U-22 结论：
  必须在提交后，否则并发读者按旧计数回填）。
  TV 为删除路径构造的 `DeletedComment` 载体**不需要**了（局部变量已够）。
  TV 在 addComment 里那次"仅用于判 newComment != null"的回查**仍不恢复**（CM-1 已预告该结论）。
- **S3/L-6**：`LikeChangedListener` 的两处 TODO 补上——内容点赞失效内容 key、
  评论点赞定向失效该主楼的 replies field。少了它们，"点赞后数字不变"会一直持续到 TTL 到期。

## 有意改进（与 TV 不同，逐条留痕）
1. ★ **窗口装载的 DB 失败不再降级成"没有评论"**：TV 在 `ensureRootsWindow` 里 catch 掉
   DatabaseException 后**继续读缓存**（其注释写"本次降级走 DB"但代码并没有走），冷缓存下会
   返回"无评论"。本实现让它上抛（500）——主楼列表就是本次请求的答案，不能伪装成空。
   同类的 `loadRootsFromDb` / `loadRootTotal` 也一并纠正（TV 分别吞成 null / 0）。
2. **一处刻意的例外（不是疏忽）**：**楼中楼（children 预览）的 DB 失败仍降级为空数组**。
   理由是可表示性：children 是预览子集，缺席可如实表达（`children: []` + 顶层 `replyCount` 仍在），
   用户点开走 `/comment/replies`（那里 DB 失败照常 500）。主楼列表降级成空则是**声称"没有评论"**。
3. **降级路径的分页窗口不再被 200 截断**：TV 的降级单趟 `LIMIT min(200, watermark)`，
   `pageSize=500` 时只会返回 200 条。本实现按需要装完窗口。

## 踩到的坑（写进夹具注释防复发）
夹具里直改 JDBC 的 `content.comment_enabled` **绕过缓存失效**（内容 key 里缓存了该开关），
于是"关闭→直改开启→仍读到关闭"。断言"开关生效"必须走真实端点。
第一个版本就是这么假红过一次。
