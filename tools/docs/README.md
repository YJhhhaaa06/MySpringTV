# tools/docs/ —— 文档门禁（三个只读脚本）

> 只服务**文档引用一致性**：`.docs` 的交叉引用、`src/` 注释里的文档引用、`.docs` 的体量。
> 与测试 / 备份 / 数据清理无关 —— 那些在 `tools/` 根级与 `tools/devclean/`。
>
> ★ **纪律本体不在这里**：可复算清单 = `.docs/INDEX.md` §四；引用与挪家纪律 = 同文件 §五.5；
> 改完文档要跑哪几道门禁 = 仓库根 `AGENTS.md`。本文件只讲**怎么用、查得出什么、查不出什么**。

---

## 一、三个脚本

| 脚本 | 管什么 | 扫描面 | 退出码 |
|------|--------|--------|--------|
| `doc_stats.py` | **度量**体量（按文件 / H2 章节归因），让膨胀可归因 | `.docs/**/*.md` | `0` 正常 / `2` 目录不存在 |
| `doc_links.py` | **校验** `.docs` 正文的交叉引用是否指得到 | `.docs/**/*.md`，**跳过 `archive/`** | `0` 无悬空 / `1` 有悬空（`--strict` 时"尚未创建"也算失败） |
| `doc_refs.py` | **校验** `src/` 注释里的文档引用、别名、`task/` 登记台引用 | `src/`，**跳过 `db/migration/**`** | `0` 无违规 / `1` 有违规 |

三者都是**只读**：判断留给人和文档，脚本只负责"让判断可复算、让回归会失败"。

共同实现约定（封在 `common.py`，新脚本照此引用）：

- **仓库根向上找 `pom.xml`** ⇒ 在任意 cwd 下跑都正确，脚本挪目录也不用改代码；
- `setup_stdio()` 强制 stdout/stderr 走 UTF-8（`tools/README.md` §3.1）；
- 公共层**只放基建**，检查逻辑各留各的 —— 三者口径差异大，抽到一起只会把口径变成推断出来的东西。

---

## 二、用法

```bash
python tools/docs/doc_stats.py                 # 体量总览 + 最大的 5 份章节拆解
python tools/docs/doc_stats.py --top 6 --min-kb 8
python tools/docs/doc_refs.py                  # 违规清单（退出码 0/1，可直接进门禁）
python tools/docs/doc_refs.py --verbose        # 附行号
python tools/docs/doc_links.py                 # 悬空引用（去重后）
python tools/docs/doc_links.py --verbose       # 附行号
python tools/docs/doc_links.py --strict        # ⏳"尚未创建"也算失败（收口时用）
```

也可以 `python -m tools.docs.doc_links`（仓库根下），两种调用等价。

## 三、查得出什么 / 查不出什么

| 脚本 | 测得到 | ★ 测不到（**已知假阴性，别 over-claim**） |
|------|--------|------------------------------------------|
| `doc_links` | ① `《xxx.md》` ② `.docs/` `report/` `archive/` 形态路径 ③ 章节裸引用（`§二·X`，同段有 `archive/` 路径即视为可指到） ④ markdown 链接 `[文字](x.md)` ⑤ 仓库路径（`tools/` `src/` `.mvn/` 下的 `.py/.java/.xml/.yaml/.cmd/.sh`，**不要求反引号包裹**） | **不扫 `src/`**（那是 `doc_refs` 的活）；**不认裸文件名**（`\`决策留痕表.md\`` 没有路径前缀 ⇒ 不在面内）；**编号引用**（`T#` / `R-##` / `F-##`）不在面内，靠 `INDEX §四` 那条手工 grep；`archive/` 整目录跳过（那里是当时正确的历史） |
| `doc_refs` | ① `.md` 引用可解析（带路径按路径，只有基名按基名全树查） ② 解析到 `task/` 登记台 ⇒ 违规（`FURTHER_ISSUES.md` 结转池例外） ③ 别名黑名单（`需求篇` / `设计稿` / `设计篇` / `分期篇` / `三期设计` / `骨架 §`） ④ 裸文件名只解析到 `archive/` 副本 ⇒ 违规 | **第二锚点是否真的存在、是否指对**（`类#方法` 无法机械判定）；**"活文档是否开工就建了"**（那是 T1 纪律）；**名单外的别名** |
| `doc_stats` | 文件体量 / H2 章节体量 / 正文与归档分列 | **不判定**"该不该拆" —— 阈值只是提示，判定要读内容 |

三条使用要点：

1. **"全绿"只等于"上面那几类形态都查过了"**，不等于"引用没问题"。收口时用 `--strict`，
   并记得手工跑一次编号引用的 grep（`INDEX §四`）。
2. **解析面 = `.docs` 全树按"路径后缀"匹配**：`《决策留痕表.md》` 能指到归档里的那一份。
   它只回答"这个文件名在 `.docs` 里存在吗"，**不保证指对了那一份** —— 同名文件请写全路径。
3. **两级分工**：`doc_links` 管文档侧，`doc_refs` 管代码侧。改完引用两道都要跑，缺一道就有盲区。

## 四、`doc_stats` 的读法（只度量、不判定）

- **正文 vs 归档**：`.docs/archive/` 是有意保留的历史，体量大**不是**问题；要盯的是**正文**那一行。
- **单文件 > 40 KB** ⇒ 考虑拆分或归档；**单章节 > 300 行** ⇒ 它其实是另一份文档
  （阈值与 `architecture/ARCHITECTURE.md` §四「写作规范」一致，改一处必须同步另一处）。
- 归因粒度是 **H2**（不够再看它下面的 H3）："某份文档膨胀"这句话不可行动，"哪一节该动"才可行动。

## 五、加检查 / 改检查的纪律

1. **先做反向验证再交付**：造一个违规样本（如临时写一条 `《根本不存在.md》`），确认门禁**真的变红**，
   再删掉样本。加了一条永远不红的规则比不加更坏 —— 它让人以为查过了。
2. **通过语只许如实列覆盖面**：写"①②③ 已覆盖、④① 仍不可测"，**不许**写成"四条不变式成立"
   （`doc_refs.py` 的收尾输出就是模板）。
3. **用索引表达，不要枚举目录**：门禁要判断"某个文件在哪"，就建一次 `.docs` 全树索引按后缀匹配；
   不要写"搜索目录清单" —— 新建归档目录时漏加一行，就会把"搬家"误报成"悬空"。
4. **改检测面 = 换一条门禁**：加形态 / 删形态都要同时更新上表与文件头 docstring（两边说法必须一致），
   否则下一个人会照着过期的"测得到"放心。
